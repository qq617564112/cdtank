# 首只付费宠物购买来源

首只采用正式支持的宠物2“大麦”，原pet表金钱价3500、代币价350，基础MaxHP700、Critical20、Lucky8。原购买入口只验证金钱；首片可接MONEY购买、独立base拥有记录、Home选择与正常战斗生命。原服务器购入建档未恢复，完整初值应明确采用重建策略。

## 原购买入口与定义

当前原表来源是 `pet.dat`，没有独立petshop表。一次静态入口核对定位 `0x493d4f–0x493e7b`：阶段要求2、拥有宠物数少于10，取资料selector7金钱余额，真实413c83获取PetTable，按请求定义ID查表，余额与记录+54比较。成功构造492b56请求并把定义ID写入packet+c后发送；没有币种参数、购买方式分支或扣款/拥有记录写入。它与战车按tankshop购买方式选择币种的分支不同。

大麦的PetMoney3500对应该金钱比较；PetCoin350是原表价，不等于上述入口允许代币购买。首只只开放MONEY符合所见入口；目录范围、实例分配、扣款与成功建档属于重建服务端权威。

## 完整拥有宠物记录

唯一reader为 `recovery/evidence/roles/role-owned-base.ts`，原41e5f1读取顺序如下。所有数值在Map中保持DWORD数值，16位线路字段零扩展，不能把宽度当成新字段语义。

| 顺序/组 | 原字段 | 线路宽度与来源 |
| --- | --- | --- |
| 前缀 | +4、+0 | 各uint32；+0为拥有实例键，+4业务未确定 |
| 定义与数值 | +8、+84、+34、+38、+8c、+80、+88、+7c、+3c、+40、+2c、+30、+94、+28、+90 | 各uint16；+8为PetTable定义ID |
| 名称 | +c字符串 | uint32字节数及原名称字节；购入名称“大麦”由原表提供，赋值是重建建档政策 |
| 技能 | +44/+5c、+48/+60、+4c/+64、+50/+68、+54/+6c、+58/+70 | 每对为技能ID/等级，各uint32；逐对读取 |
| 尾部 | +74、+78 | 各uint32；业务初值未确定 |

原41e90e客户端构造将上述全部数值清0，初始化+c字符串；已有owned-base/pair证据执行真实构造与reader。这个清0合同是消息接收前的空对象初始化，不证明购入服务器记录默认值。现有生产OwnedRoleBaseRecord只有契约，无原购买建档工厂；不得用取证reader作为生产工厂。

## 数值与初值分类

| 内容 | 原直接配置/消费者 | 首片建档边界 |
| --- | --- | --- |
| 实例/定义 | +0实例、+8定义2；已证索引与PetTable查找 | 实例由重建事务分配，不等于2 |
| 生命 | +2c直接复制到OdlPlayer MaxHP；大麦表MaxHP700 | 赋+2c=700可作明确重建未成长购买规则 |
| HP附加/成长 | +30被线路保存，但正式433466基础初始化只读取+2c，不累加+30；表MinHPUp/MaxHPUp均0 | +30业务名称与server赋值未证，不把它直接加到700；字段清0仅重建初值政策 |
| Critical/Lucky | 正式重算读取+34/+3c；原表20/8 | 明确重建赋20/8，不能把基础表当购入producer |
| 其他数值/成长 | +38/+40/+28/+7c..+94均有原宽度，购入producer未恢复；表Critical/Lucky成长上下限均0 | 不命名未知偏移、不从任意fixture补值；保留完整字段并明确重建初值 |
| 四精通 | 原表STank/MTank/LTank/STugMastery=2/3/4/2；正式重算取PetTable对应值 | 不从拥有记录另一组偏移替代原定义精通 |
| 六技能 | 表Skill0..5=10211/10221/10231/10241/10251/10261；SkillLv0..5=5/1/5/5/1/0 | 配置存在，复制至拥有技能/等级是重建建档政策；0级保持0，不自动升为1 |

正式属性接线当前要求base有+2c/+34/+3c，定义查找还需要+8、实例索引需要+0；同角色equipment必须有+34/+3c/+40/+4c/+50/+58/+5c/+60，以及完整tank/pet/skill/item来源。完整433466先把base+2c作为生命基础，再应用实际选择到的技能和限制，因此700是未叠加基础，不应绕过重算直接写战斗HP。

宠物选择写profile+a4（selector28），按账户base实例查询；正式World复制选中拥有来源，再经 `battle/attributes.ts` 与完整重算生效。生命在开局/复活按maxHp恢复。需同时有合法已选战车；购入宠物不自动赠送战车。

拥有宠物六技能不能被误当生产boundGear已绑定：`skill-sources.ts`读取独立boundGear的技能ID/等级，当前账户宠物不是已证实的这个独立绑定对象。本片保存原表技能政策可以与当前正式运行一致，但不能宣称六技能已自动产生战斗被动效果。

## 可接线合同与缺口

可接首只明确重建购买：商品pet2/MONEY3500，事务插入 `role_records.kind=base` 的完整31数值字段、原名称与receipt；不写Item3库存，不自动选中。玩家随后经Home SelectRole选该实例，既有拥有/资料/属性路径可承担入场与生命保存验证。余额不足、重复请求和重启引用现有购买事务惯例。

阻塞原版初值完成的唯一关键来源是原服务器购买建档producer：HP附加/成长字段含义、未知字段成功值以及技能/等级复制尚未证明。首片若允许明确重建“未成长购入”政策，可以正式接线；若要求全初值与原server完全一致，则该来源仍阻塞。原客户端空构造清0与实际表配置分别保持其范围，不形成伪造的原模板。

静态结果保存于 `recovery/output/pet-purchase-source-sol.json`，包含原pet2完整行、完整reader偏移集合和当前生命重算字段要求。本轮不运行native、不展开其余宠物，也不重验已有角色证据。
