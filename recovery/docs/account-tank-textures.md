# 账户战车迷彩确认与持久扣费（M6-03）

`AccountStore.configureTankTextures` 将账户拥有的战车实例、原 `tanktexture` 价格和成功确认接入单次 SQLite 事务。改动保存拥有记录 `+0x28/+0x2c/+0x30`，并保存资料 `+0x74` 代币与 `+0x70` 金钱两个 unsigned32；其他字段、名称、资料字符串、其他拥有记录和其他账户保持原值。

## 重建账户规则

实例和请求 U/M/XY 必须是0至 `0xffffffff` 的整数。实例必须属于当前账户的 equipment 记录，拥有记录必须已有三槽及 `+0x24` 战车定义，账户必须已有完整资料。每个变化的非零请求 ID 必须存在于原表目录、对应拥有战车定义及请求部位，且稀有度为1或2。未变化槽保留原拥有值，不要求当前目录中存在或可购买；原拥有默认迷彩可与其他槽的新选择一起保存。保存路径只更新已有记录，不创建拥有记录或初始余额。

资格检查、读取当前选择与余额、费用计算和两次保存均在 `BEGIN IMMEDIATE` 内完成。请求费用使用共享 `evaluateRoleTankTextureRequest`：只有变化的非零槽计费，稀有度1收原购买金钱价，稀有度2收原购买代币价，DWORD累加和余额比较保持 unsigned 语义。代币不足或金钱不足分别拒绝，数据库保留原值；不返回成功确认。

三槽相等或请求三槽全0返回结果0、原选择及原余额，不扣费。其他通过请求返回结果3，用 `applyRoleTankTextureConfirmation` 更新三个拥有字段及两个余额，再保存并提交；提交完成后才返回确认。非空请求中的0原样进入确认并清空该槽，没有默认迷彩回填。任何保存失败回滚两个更新。

原完整请求门禁和原成功确认见 [role-texture-transfer-sol.md](/workspace/cdtank/recovery/docs/role-texture-transfer-sol.md)。原客户端对照证明请求费用、消息字段与确认写入；账户归属、战车定义/部位资格和数据库事务是重建服务器规则。

## 验证

```sh
npx tsx tests/account-tank-textures.cts
```

PASS：711条原表价格作为服务器输入，战车2的 `21011/21012/20013` 共扣110代币，原 `20011/20012` 零价更换不扣余额；未变化及全0不写入，非空请求的0清槽。验证未变化的稀有度0/目录缺失槽保留及无操作返回、整数 ID、unsigned 高位余额、归属、定义、部位、稀有度0/无效稀有度、缺少资料/拥有字段、余额不足、资料仅8字节变化、名称/字符串/其他记录/账户保留及重启保存。数据库触发器使第二次资料更新失败，验证第一次拥有记录更新也回滚。结果见 `recovery/output/account-tank-textures.json`。

该检查发现费用币种或金额、授权、保存范围、重启恢复和两次写入原子性错误；发生错误时应停止接入更换确认并修正事务。原表没有稀有度1记录，金钱不足分支使用明确的测试夹具；付费及零价验证使用原表记录。

## 限定范围

该事务不证明原服务器购买授权与保存实现，也未恢复完整改装、耐久消耗或维修业务。M6-03保持进行中。
