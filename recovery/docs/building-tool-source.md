# I502 建筑工具：原客户端有限取证

本轮只追踪原 `CDTank.exe` 的 `SYcCastle`（碉堡/城堡）对象、其 HP 字段和普通对象加载入口；不能从客户端推导服务器技能公式或服务器资格。

## 已确认

* `SYcCastle` 类名位于 `0x5c7324`，vtable 为 `0x5c72b0`。对象构造器 `0x45dbaa` 分配 `0x1e0` 字节并进入 `0x45ced3`；普通资源/场景加载入口 `0x45dd08` 通过 `0x44ecbb` 创建对象，再调用 `0x45db74` 初始化其记录。该链是城堡实体创建链，不是 `SYcScnObjBreach`。
* 城堡的运行时数值在对象 `+0xdc`（当前值）和 `+0xe0`（上限/基准）处理。虚槽 `+0x14`（`0x45d16f`）执行 `current -= delta`，将结果限制在 0 与 `+0xe0` 之间；随后按 HP 区间切换 `+0x110..+0x130` 的模型/效果资源。`0x45dcd9`（更新入口）调用该虚槽，故这是客户端显示/动画状态链。
* `SYcCastle` 的序列化读取在 `0x45bcc4`：先读通用 placement，再从输入读出 `+0xe0` 与 `+0xe4`；`0x45bec0` 将记录中的 `+0xe0/+0xe4` 复制到运行对象 `+0xdc/+0xe0/+0xe4`。这些字段是原始城堡对象数据来源，尚未证明是服务器技能恢复值。
* 资源加载会按对象 `+0xd8` 绑定场景节点；对象销毁/重置经过 `0x45bdcb`。客户端通知计数链在 `0x4247aa`：类型 2 直接跳过 `0x44e081`，其他类型递增角色 `+0x314`；这不是 HP 写入入口，也不能将 mode5 Breach 目标当作城堡。
* 原表 `m005` 的 `BunkerHP` 是模式配置列；现有客户端证据未建立该列到 `SYcCastle +0xdc/+0xe0` 的网络/服务器映射。mode2 当前中立占领圈快照的 `hp=0` 不能作为城堡实体或可恢复目标。

## 当前缺失的接线

尚未找到 `skill502`/`FuncType18` 到 `SYcCastle` 对象查询、目标资格判定或服务器 HP 写入的入口，也未找到客户端普通输入如何提交该目标的协议消息。因此不能为 I502 选择 Item 说明 `1000` 或 Skill 参数 `5000`，不能注入目标 HP/位置，也不能把任意当前 mode5 Breach 实例冒充碉堡。

可交付给后续实现的最小合同是：目标必须来自原 `SYcCastle` 身份及其 `+0xdc/+0xe0/+0xe4` 数据；服务器需另行证明 mode/队伍资格、恢复量和 CAS/消费入口。当前证据仅支持客户端显示链，不能证明服务器公式。

取证依据：`CDTank/CDTank.exe` 原始 PE；静态反汇编地址见上文。未修改运行代码、任务清单或进度文件。
