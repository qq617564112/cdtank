# I502 建筑工具：原客户端来源

原 `CDTank.exe` 的 `SYcCastle`（碉堡/城堡）对象、其 HP/归属字段和普通对象加载入口。

## 已确认的静态事实

* `SYcCastle` 类名位于 `0x5c7324`，vtable 为 `0x5c72b0`。对象构造器 `0x45dbaa` 分配 `0x1e0` 字节并进入 `0x45ced3`；普通资源/场景加载入口 `0x45dd08` 通过 `0x44ecbb` 创建对象，再调用 `0x45db74` 初始化其记录。该链是城堡实体创建链，不是 `SYcScnObjBreach`。
* 城堡的运行时数值在对象 `+0xdc`（当前值）和 `+0xe0`（上限/基准）处理。虚槽 `+0x14`（`0x45d16f`）执行 `current -= delta`，将结果限制在 0 与 `+0xe0` 之间；随后按 HP 区间切换 `+0x110..+0x130` 的模型/效果资源。`0x45dcd9`（更新入口）调用该虚槽，故这是客户端显示/动画状态链。
* `SYcCastle` 的序列化读取在 `0x45bcc4`：先读通用 placement，再从输入读出 `+0xe0` 与 `+0xe4`；`0x45bec0` 将记录中的 `+0xe0/+0xe4` 复制到运行对象 `+0xdc/+0xe0/+0xe4`。
* 资源加载会按对象 `+0xd8` 绑定场景节点；对象销毁/重置经过 `0x45bdcb`。客户端通知计数链在 `0x4247aa`：类型 2 直接跳过 `0x44e081`，其他类型递增角色 `+0x314`；这不是 HP 写入入口，也不能将 mode5 Breach 目标当作城堡。
* 原表 `m005` 的 `BunkerHP` 是模式配置列。mode2 当前中立占领圈快照的 `hp=0` 不能作为城堡实体或可恢复目标。
* 原表数据：目录物件 502“建筑工具”说明“回复碉堡生命值1000点。”、`battleUseMax2`、技能列表 `[502,0,0]`、ItemMoney/ItemCoin 均为 0、GGet 为 0。技能 502 说明“回复碉堡生命值5000点。”、Target1、TriggerType1、Range0、首函数 FuncType18（t0/x2/y5000/z0）、首效果 Effect12/SE13/Tag0/Method3、其余引用为 0。源 CAS 每城堡 `+e0` 为 2000，`+e4` 为 1 或 2。

## 静态字段与 CAS

`getSceneCastles` 公开源 CAS 的 HP（尾偏移 4）与归属（尾偏移 8）。0001/0002/0003/0005/0006/0008/0010/0011/0012/0013/0023 中每个场景各两座 Castle，源 `+e0` 均为 2000，`+e4` 为 1/2。`+e4` 与取值 1/2 是事实；把 1 映射到 team0、2 映射到 team1 是采用的重建策略。

取证依据：`CDTank/CDTank.exe` 原始 PE；静态反汇编地址见上文。除上述采用策略外未修改运行代码、任务清单或进度文件。
