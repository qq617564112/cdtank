# 战斗装备、退出处罚与乱斗计数

结算事务实际写入道具库存与坦克拥有记录，显式退出使用服务端报价和积分扣减，乱斗显示本人猫／狗击毁计数之和。原客户端显示接口、处罚门槛和倍率沿用已取得来源；装备概率、处罚计数的当前生产规则与乱斗计数拆分采用下列项目规则。

## 装备奖励

账户在非 FORFEIT 对局结束时仍有真人参与者在场、真实 PLAYING 时长至少 60 秒且冻结 combatScore 大于 0，才有装备抽签资格。胜、负、平局使用相同概率，每账户每局只抽一次：

| 类别 | 概率 | 数量与选择 |
| --- | --- | --- |
| 道具 | 25% | 均匀选一件，拥有数量 1 |
| 坦克 | 5% | 从尚未拥有的可用型号中均匀选一辆；空池不发 |

两类独立抽签，可同时获得，无保底。道具池为 1、2、3、4、5、6、7、8、12、13、2002、2003、2004、3001、3002、3003、3004、3005、3008、3009、9、10、11、501、502、3006、3007，名称与图标读取原定义。新增七件取得规则见battle-item-acquisition-runtime.md。坦克池复用 tankShopCatalog 的金钱购买型号与原基础属性、纹理、部件容量；购买可用范围只是当前奖励池政策，不是原战斗发放依据。

finishRoom 冻结 completedRound、实际时长及结果；普通中途离场者保留历史和既有成长结算，但没有装备资格。一账户多连接先逐参与者判定，至少一名真人参与者独立满足完赛、时长和得分资格时，账户只生成一份抽签。抽签在冻结待提交数据时生成，数据库失败重试使用同一抽签。

AccountReward 在 AccountHistory 的现有 BEGIN IMMEDIATE 中同时写入成长、金钱、装备与 account_reward_ledger。道具写入 inventory，坦克写入 role_records/equipment；实例号从两个拥有表的共同 ID 空间分配。发放不扣商城余额、不记购买支出、不自动装备或绑定快捷槽。重复结算使用保存的回执，不再发放。

ResultAward.grantedItems/grantedTanks 只含实际写入成功的记录。原弹窗按新称号、道具、坦克的顺序显示，客户端不抽签或发放。原记录队列、名称、图标、gamestring140、动画与声音来源见 battle-summary-equipment-source.md、battle-ui-remaining-source.md。

首次提交及重试成功后，从数据库读取实际新增道具，同步到该账户全部在房角色的库存，并沿现 inventoryChanged 通知客户端重新查询。只添加尚不存在的实例，保留已有物品的本局数量和快捷槽；继续留房、再战或重连保留角色均可读取到账记录。坦克拥有列表沿 OwnedRoles 直接读取持久记录。

## 退出处罚

sceneBreakCount 按本人实际引发的场景物件归零、破坏目标归零或 Crush 首次隐藏累计。已破坏对象不会重复计数；目标实际重生后再次被毁可再次计数。Castle 与玩法目标共用实体，转交场景破坏链只累加一次。坦克击毁、空射、免疫命中和普通移动不增加此计数。首局和再战清零，死亡复活保留本局累计。

仅真实 PLAYING 开始后、显式 Leave 确认触发账户处罚。计数大于 7 时，名义罚分为计数乘 100；实际可扣积分为名义罚分与当前 rankPoints 的较小值。扣后积分最低为 0，等级按原积分阈值重算，创意点、技能点、金钱与原 profile 字节保持原业务。

点击退出先用 Leave.quoteOnly 读取权威报价，此请求不离房、不扣分。计数不超过 7 使用 gamestring829；超过 7 使用 gamestring593：

> 现在退出会扣除%d积分作为处罚，仍然要退出吗？

%d 为当前实际可扣积分。确认携带已显示的 confirmedPenaltyPoints，服务端重新核对本局、成员、阶段、计数与账户余额；金额变化时保留成员与账户，刷新报价，玩家须再次确认。扣减与独立处罚回执在一次数据库事务中保存，按账户、运行期房间标识、局号、参与者身份避免重复扣减。断线保留／到期清理、踢人和普通房间生命周期不调用处罚事务。

原 selector0x15、role+0x314、门槛 7、倍率 100 与确认回调来源见 battle-ui-exit-progress-source.md、battle-ui-remaining-source.md。本项目以成功场景破坏事件生产 sceneBreakCount；它不是原 role+0x314 完整业务名的证明。

## 乱斗计数

按用户“DogsInfo 参照 CatsInfo”的要求，两个字段共用 finalizePlayerDeath 的真实击毁生产链：

| 字段 | 当前生产规则 |
| --- | --- |
| catsInfo | 本人击毁 team0 猫方坦克的累计次数 |
| dogsInfo | 本人击毁 team1 狗方坦克的累计次数 |

只有已记入本人 kills 的同一次真实死亡才增加对应字段，catsInfo + dogsInfo 等于本人 kills。乱斗入房均衡分配猫／狗标识，使两侧均有真实参与者；同队坦克仍属于个人战对手，出生、敌我判定和胜负沿个人模式规则。按被击毁方拆分计数，不再将总 kills 另加一次，也不使用 deaths 作为第二加数。

PlayerSnapshot 携带两字段；普通离场时冻结两字段，computeMatchResult 复制到本局 ResultPlayer。PLAYING HUD 使用实时值，FINISHED 使用冻结结果，零值可见；缺少权威字段时留空。新局清零，复活保留，离房沿现 HUD 生命周期清理。协议新增字段保留旧编号。

原乱斗唯一 txtInfo 将公告 CatsInfo 与 DogsInfo 相加，原本机覆盖只写 CatsInfo；原 DogsInfo 的在线生产者仍无来源。当前按被击毁方拆分是采用规则，原来源见 battle-ui-remaining-source.md。
