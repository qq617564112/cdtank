# I502 建筑工具客户端显示

服务端接受我方碉堡修复后，按既有 Castle 事件通道投影 `sceneObjectHealed`，携带 `castleDamage = {castleId, currentHP, maxHP, delta: -restored}`。Battle 只把该事件交给既有 `damageCastle` 消费者，不新增 Castle 网络字段、目标 payload 或快照重放。`SceneCastleState.damage` 以 `delta < 0` 进入修复事务，`delta >= 0` 的普通受损/销毁分支保持原样。

## 修复事务

修复只接受存活的正生命结果：`currentHP <= 0` 或当前已处销毁阶段0时不做任何显示。其余情形按当前生命重算动作阶段，显示 `n1`（三分之二以上）或 `n2`（三分之一至三分之二），不显示 `c2`/`c3`。

恢复不会重放任何打击/倒塌线索：不发 `GA48`、`se07`、`041` 或 `destroyCallback`，也不产生伤害浮字。曾进入过的五分之一烟层一旦高于当前生命对应的损伤档，就停止其保留的 `040` 效果与 `se03` 循环声，并清除对应 mask 位，使此后再受一次实际打击时能重新进入该源损伤档。存活且仍在其档内的烟层保留，不重复触发。

修复不改动 Castle 网格与资源的所有权，不 dispose 或重载动作容器，也不重建 presentation；`restore()` 仍用于载入/重连按权威 HP 恢复稳态，`restore()` 只在阶段变化时切动作，因此重复渲染快照不会变成逐帧重放。死亡、普通初始快照恢复与 mask 的既有语义不变。

## CPU 配置

CPU 槽5–8允许既有道具1–9与物件502；槽2–4仍限弹药2007/2011。界面过滤与 root 派发的共享/server 白名单 `CPU_LOADOUT_ITEM_IDS` 一致，数量上限仍取该物件 `BattleUseMax`。物件502只按普通库存/输入来源进入配置，不从零价目录免费发放或购买。

## 图形与文字

动态文字仍使用用户字体与原字号/字形来源；伤害、恢复与暴击图像不变。修复只切换碉堡源动作档与烟层资源，不新增 Effect、Sound、透明度或额外绘制来源。
