# 战车默认迷彩与拥有战车选择来源（M3-03 / M6-01）

原战车详情页有两个明确来源：商城预览读取 `tankshop` 默认 U/M/XY；拥有战车详情读取拥有战车记录 `+0x28/+0x2c/+0x30` 的已选纹理表 ID。拥有战车记录 `+0x24` 是战车定义 ID。这里的三槽直接与 `tanktexture` 表 ID 比较，资料 selector44 的顶灯实例不参与这条链。此有限切片确认详情页来源，角色属性32的生产写入仍待恢复。

## 商城默认配置的实际消费

原资源加载 `0x41bc20–0x41bc69` 将 `tankshop` 交给资源 manager `+0x98`；真实 getter `0x413d01` 返回该 manager。`0x4b6ce1` 的详情状态0在 `0x4b6d31–0x4b6d43` 保存传入战车定义 ID 到 UI `+0x1a4`，并查询 tank 基础记录。

执行 `0x4b6db6–0x4b6eef` 时，原代码按此定义 ID 查询 tankshop，再读取记录 `+0x10/+0x14/+0x18`，依次查询 tanktexture 的 U/M/XY 表记录，取原字符串 `+0x30` 并调用 `0x46cc73/0x46cd15/0x46cdb7`。TankType4分支只读取后两列，调用 `0x46926a/0x46930c`。这个路径把默认配置直接应用到详情页 actor，没有先写角色属性32。

实际原表11个商城战车配置全部对照通过。战车1实际结果为10011→001U_001.tga、10012→001M_001.tga、10013→001XY_001_A.tga；记录字符串两种 SSO/heap 分支均沿原指令处理。此结果确定三列的使用顺序，不能据此给空账户赠送战车或皮肤。

## 拥有战车的已选纹理

详情状态1的 `0x4b73f5–0x4b7432` 保存传入拥有实例到 UI `+0x1a0`，通过拥有管理器 `+0x40` 的 `0x421f36` 查原 map，再从返回记录 `+0x24` 取得战车定义并查 tank 表。该实例与定义分开使用。

`0x4b6603` 建立可选择的纹理列表。执行其 `0x4b6748–0x4b67c0` 后，原代码读取拥有战车记录 `+0x24`，遍历 UI `+0x1b0/+0x1b4` 的纹理表指针，要求纹理记录 `+0x48` 非零、表 ID 整除10000等于战车定义 ID，再按 ID 末位1/2/3分到 UI `+0x1bc/+0x1d0/+0x1e4` 的 U/M/XY vectors。实际表21个战车的过滤结果与原定义逐项相同。

原选择匹配循环使用真实 vector 数量与索引 getter：

| 组件 | 拥有战车字段 | 原比较 | 选中索引 |
| --- | --- | --- | --- |
| U | +0x28 | 0x4b67fc | UI+0x1cc |
| M | +0x2c | 0x4b68bf | UI+0x1e0 |
| XY | +0x30 | 0x4b6982 | UI+0x1f4 |

480个实际表候选值执行原三段查找循环，均在正确索引匹配。选择字段是显式夹具填入，测试证明客户端读取和匹配合同，不证明服务器给该账户发出了这些值。随后拥有详情预览 `0x4b74b9–0x4b7543` 读取三个 vector 的选中项，使用其原文件名调用 U/M/XY actor 设置入口；本测试没有执行该后段的完整图形加载。

## 验证

```sh
recovery/.venv/bin/python tests/role-tank-texture-producer-sol-native.py
```

PASS：11个 tankshop 默认预览、21个拥有战车定义纹理过滤、480个拥有选择字段匹配。输出 `recovery/output/role-tank-texture-producer-sol-native.json` 保留默认表 ID/文件名/入口、每辆战车过滤项及每次拥有字段匹配索引。

本检查识别默认 U/M/XY 顺序错误、TankType4分支误用、表字符串读取错误、战车定义与拥有实例混淆、候选列表跨战车混入及拥有选择字段错位。发生这些错误时，阻止把相应来源合同接入页面。

原指令覆盖上述有限段、真实资源 getter 和真实选择循环数量/索引 getter；表 lookup、vector 插入、末端 actor 设置由边界供给。测试输入使用已解码原表与明确拥有记录内存夹具；没有生产账户修改。

## 剩余来源

原 `specialtank` 加载 `0x41baca–0x41bb13` 使用 manager `+0x94`，其三个“坦克贴图”字段仍未证明如何转换成拥有战车字段或角色属性32。已确认的拥有三槽是后续恢复 producer 的具体入口：追踪拥有记录 `+0x28/+0x2c/+0x30` 的消息解码/初始化及选中战车到角色 `record+0x110` 的赋值。购买/赠送成功、账户授权、特殊战车转换、属性32生产写入和浏览器实载未在此切片验收。此交付不新增默认值或纯函数生产模块。
