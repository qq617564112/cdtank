# 本机坦克运动

手动控制的坦克由客户端计算位置、车体朝向和炮塔方向，每个渲染帧推进并呈现。服务端接受同一局、同一生命的姿态上报，沿移动与车体转向路径限制到其它存活坦克碰撞盒之前，记录后广播给房间；普通快照确认不覆盖本机姿态。最新快照中从服务端确认位置到本机位置的路径被其它坦克占用时，本机恢复该确认姿态。

`PlayerInput.pose`携带round、life（死亡次数）、原坐标x/y/z、yaw/bodyYaw/aim和运动command。既有输入sequence保持消息顺序。姿态在道具请求处理之前安装，开火、地雷和命中查询使用已接收的位置。出生、复活、新局及从自动驾驶恢复手动控制时初始化本机姿态。

`PlayerSnapshot.movement`提供统一数值链算出的速度、转速、TankType和当前运动许可。确定性运动数学、NAV采样、OBB判定和渲染面碰撞占用由`apps/shared/movement`供两端共用。客户端读取原NAV及已加载场景的完好渲染面，随破坏和Crush状态更新占用；Plant沿既有穿行接触消费者处理。

服务端不推进已上报姿态的手动玩家；CPU、自动驾驶和只上传按键的独立输入消费者继续使用服务端运动入口。伤害、弹药、技能、死亡和结算仍由服务端处理。其他坦克沿快照插值显示，相机跟随本机连续姿态。

所有存活坦克统一使用现有49×24×52车体OBB参与阻挡，不以完整属性来源或运动参数存在与否过滤。客户端与服务端共用`tank-collision.ts`，检查实际移动和车体旋转，死亡角色不占用车体位置。复活先选择未占用的原出生点，再选择其附近完整NAV落脚范围可用的位置；无空位时维持死亡状态并在后续节拍重试。同一节拍逐个确认复活位置，成功后才发布respawn事件。该生产占用与放置规则未执行真实双网页、连续复活或拥挤出生点验收。

离房或取消载入清除本机运动和地图导航所有权；同一生命的断线恢复保留本机姿态。客户端和服务端使用同一份更新后的TSRPC协议。
