# 原战车组合与炮塔

## 内容来源

`recovery/export_tanks.py`将原tank表的21种战车、84份M/U/X/Y INI及704条动作导出到 `recovery/output/web-assets/tanks.json`。每条动作保留原section、全部字段、GLB路径、MV3原duration及首个tag_c的初始位置。Windows文件名大小写通过原目录匹配，不改变源文件。

151–158的8份U配置只有MV3注释而无动作，与原程序三部件组合一致；其余13种战车有独立U。所有战车M/X/Y都有动作01，U有动作时也有01。01/02/03已分别用于静止、移动和开火；05–08用于普通受击，09用于死亡；04及部分战车的c系列动作已导出，其独立生产者和完整切换逻辑仍待恢复。

## 原程序证据

- EXE 0x469f70–0x46a066按M/X/Y依次载入三个actor，保存在0x2a8附近，分别使用独立INI。
- EXE 0x46d3dd–0x46d508按M/U/X/Y载入四个actor。
- EXE 0x46d520–0x46d569分别查询M和U的tag_c。字符串VA为0x5c8994；调用的是gbActor::GetTagNodeTM，导入表0x5c09f0。
- EXE 0x46d061–0x46d0db先平移到U挂点X/Z，Y为0，再围绕角色Y轴旋转`炮塔角度 - 车身角度`，平移回去后绘制U。不能用模型边界中心或世界原点代替该旋转中心。
- gbengine.dll 0x1000c4a0读取挂点名、帧数及每帧68字节；0x1000b800以时间循环采样，0x1000b87e之后分别插值位置并处理四元数。每帧time后16个f32是含位置/四元数的记录，不能整体直接当作4×4变换矩阵。解析器的旧`matrix`字段目前保留原16个数，前3个数是位置；运行时本轮只使用初始位置。
- EXE 0x46888f及0x46c2ab处理动作切换，原01/02/03等名称在启动时转为引擎ID。0x468a53选择03，0x46897a按参数选择04–08，0x468a03选择09；普通受击参数来自角色look方向分类。

## 动作调用依据

- EXE 0x46495d将速度向量清零并将0xd8标志设为1。0x469020–0x469030在动作完成后检查该标志，静止选index 0（01），运动选index 1（02）。0x468aa2/0x468925也对基础动作进行恢复，特殊动作index 2–8期间保留当前动作。
- 开火表现入口0x464e53通过vtable 0x3c调用0x468a53，后者选择index 2（03）、参数4；四部件实现0x46c42e同样选择index 2、参数4。
- 引擎GotoAction简化重载0x10009d10传入over消息与时间范围，0x10009bfa从参数bit 2设0xb0；0x1000a922在此标志下限制动作时间并发出完成消息。原引擎完成点还含100单位的偏移；Web本轮以导出的duration作为恢复期限，精确播放时间继续校准。

- 死亡入口0x4647fe经vtable+0x44调用三部件0x468a03/四部件0x46c3de，选择index 8（09）、参数4，并将角色+0x19c置1。复活入口0x464803经vtable+0x48调用0x468a2b/0x46c406，选择index 0（01）、参数0，清除+0x19c。0x464844读取该死亡标志；动作调用检查此标志。
- 死亡/复活中的vtable+0xb4调用（三部件0x468d92）设置导入0x5c0904 EnableOcclusionCulling；这是遮挡剔除设置，死亡模型仍可绘制。

- 受击入口0x464e72检查+0x19c后派发vtable+0x40；三部件0x46897a和四部件0x46c396均把整数参数0/1/2/3/4映射到index 3/4/5/6/7，即动作04/05/06/07/08，参数4。本地生产者0x4288fe确认incoming为当前本地玩家角色，0x428b1d调用0x435745(target,incoming)；双方0x431fe7读取look的+0x274/+0x27c，与车体forward+0x280独立。原夹角和叉积返回quadrant0–3，生产者加1成为参数1–4，即普通受击05–08。远端0x422877只在角色status2时把消息quadrant0–3同样映射为1–4；不选择参数0/动作04。详见combat-hit.md。

## Web运行

`apps/web/src/assets/tanks/tank-view.ts`按角色ID读取目录，将每个非空部件GLB放置在同一原几何坐标系中。01/02循环播放，服务端RoomEvent的fire触发03一次播放，hit中的显式hurtSelector1–4触发05–08；依据源整数时钟完成状态恢复基础动作。01及05–09在角色进入渲染世界前载入；其他动作资源按需载入并缓存，切换时一次启用完整组合、停用旧组合动画。异步载入以最新请求为准，离开后释放已完成与仍在载入的容器。全车root使用源尺寸和Babylon glTF的X反射。U通过独立炮塔节点与反向平移节点围绕载入时的01源tag_c X/Z旋转，各动作沿用这一缓存中心。移动触发依据权威快照的位置变化；开火由服务端事件触发，本地按键不能自行播放攻击。

对战入口提供21种原名称战车；Join发送选择的tankId，快照中的tankId决定本地与远端显示。炮塔相对角直接由服务端aim驱动，显示端反射角度符号；车身yaw独立更新，炮塔随车身整体转向。权威alive从true变false时播放09一次并保留模型，停止接受移动/开火/受击动作覆盖；复活切回01并清除攻击期限，位置/车身角立即落到权威出生状态；出生位移不触发02。返回时释放部件容器、动画和节点。房间退出使会话编号失效，旧载入结果释放，旧动作错误仅在原view仍属于当前房间时进入HUD。地图加载和清理也使用请求编号，退出后不再加入迟到地形或物件，不再修改相机或启动输入计时器。

## 原动作播放速率接入

原gbActor::Update 0x1000a7d5–0x1000a7ec读取delta double，乘节点f32 timeScale和原4800.0常量，再调用CRT向零截断为每帧时间步。基类构造0x1001e475写默认timeScale1，战车载入链未找到额外scale设置。原GLB转换将MV3时间除1000写入秒，因此TankView动画group speedRatio改为4800/1000=4.8，基础攻击持续时间由每帧整数时钟完成状态决定，保留原源数据和资源查看器的时间表示。

取证与原指令oracle由独立特效任务提供，详见effect-runtime.md的动作事件和actor章节。当前进一步接入下节原整数步进、stop夹持与原消息，基础动作回调与特效绑定仍待恢复。CRT启动53位精度已由原指令执行确认，但D3D设备创建未含FPU_PRESERVE，不能将启动控制字当作整个绘图过程的证据。


本轮test:tanks与TypeScript通过；真实浏览器test:tanks:browser加载全部21种组合，检查当前启动AnimationGroup.speedRatio=4.8、攻击期限前0.01ms仍为03、达到rawDuration/4.8切回01，并回归原顶点/炮塔三角度、morph推进、死亡优先及释放，通过。证据browser-tanks.json。期限检查使用明确注入的测试now，只证明TankView控制边界；真实联机攻击时序另由自然战斗回归。


## 原整数动作时钟接入

TankView每个部件现在独立使用EffectActorActionClock，初始原时间1，每个渲染delta×默认scale1×4800按原CRT规则向零截断，没有小数余量。GLB AnimationGroup暂停自主推进，以原time取余后换算GLB帧进行采样。01/02持续取余；03/05–09按原角色GotoAction flags4在time>=duration时夹为duration-100，并发送、清除一次over。攻击不再依赖墙钟期限，全部部件结束后返回当前基础动作；死亡继续按原停止分支采样，复活回01。

03/09的flags4在三部件入口468a53/468a03和四部件46c42e/46c3de确认；简化GotoAction10009d10传start1/end0，完整10009bfa由flags4设置actor+b0。各动作原消息以events发布在tanks.json，时间为原tags[].id，identifier经原字符串算法产生，全部704动作源核对通过。TankView.actionMessages发布part/action/time/identifier供后续特效绑定，不以网络fire事件直接替代原attack1/effect1时刻。

当前显式选择原CRT启动确认的53位精度；D3D创建后控制字仍未运行确认。原多动作混合、部件完成回调相互切换、动作消息立即修改其他部件的顺序和动态tag/world组合仍待恢复。目前基础动作返回等待全部部件结束是Web调度，不宣称角色回调全量恢复。

真实Babylon全21组合检查采用显式暂停渲染循环和原oracle delta序列，对152条03/09部件共2584更新逐项检查time/overMessage/消息identifier一致，并回归morph真实推进、原顶点/炮塔角度、动作唯一可见/死亡优先/复活/退出和加载期间释放，全部通过（browser-tanks.json.nativeTicks）。原oracle中的tag更新与消息接收为记录替身；这不是特效世界挂点或实际像素精度证明。


停止后小delta继续执行原时间加法，触及duration再回夹；在末100单位内可前进，不是永久锁死单帧。扩大的原oracle包含连续1/60、.001、.01和零delta。事件区间ending保留原u32 ADD回绕，避免回夹负差被误当巨量正跨度。全21种战车实际Babylon验证152部件×17步=2584个更新，逐项比较原time/over/事件，且实际morph influence与该原时间在GLB关键帧上的线性采样误差<=0.00001；全部通过。
