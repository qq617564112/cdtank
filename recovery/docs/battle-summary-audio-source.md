# 战斗结算音效

正式结算在面板、玩家行、胜负图、实际奖项、等级变化、四值奖励和新称号出现时播放原声音。颁奖阶段循环UI38，离开该阶段即停止；滚分和经验变化阶段按浏览器帧请求短音UI29。重复快照、再战投票及翻页不重播入场、奖项或称号音效。成长回执迟到只续播成长及后续提示。

## 原客户端依据

`0x4d650b`将声音ID和播放次数直接传给`0x4859d1`；该函数经`0x4178c9`查声音表，再调用`0x571c50`。这里没有技能声音的编号偏移。原`audio.json.soundIds`提供下表对应的原WAV文件，默认音效音量为0.5。

| 触发 | 全局ID / 原文件 | 调用点 |
| --- | --- | --- |
| 面板入场 | 35 / UI35.wav | `0x4aadc6–0x4aadd0`，播放次数1 |
| 玩家行入场 | 36 / UI36.wav | `0x4ab15d–0x4ab168`，播放次数1 |
| 胜负图 | 37 / UI37.wav | `0x4ab2c7–0x4ab2cf`，播放次数1 |
| 滚分 | 29 / UI29.wav | `0x4aba43–0x4aba6d`，帧分支先停止旧描述符，再以次数1请求声音 |
| 首个实际奖项 | 30 / UI30.wav | `0x4ab346–0x4ab351`，播放次数1 |
| 颁奖背景 | 38 / UI38.wav | `0x4ab356–0x4ab370`，播放次数−1，保存句柄至`0x893028` |
| 后续实际奖项 | 30 / UI30.wav | `0x4abcaf–0x4abcba`，播放次数1 |
| 经验变化 | 29 / UI29.wav | `0x4abcdd–0x4abce8`，每帧入口请求次数1 |
| 升级 | 31 / UI31.wav | `0x4abd3b–0x4abd46`，在等级递增前请求次数1 |
| 降级 | 39 / UI39.wav | `0x4abecc–0x4abed7`，在等级递减前请求次数1 |
| 四值奖励 | 40 / UI40.wav | `0x4ab3ab–0x4ab3b3`，播放次数1 |
| 每条新称号 | 40 / UI40.wav | `0x4aad11–0x4aad18`，此处ebx已经置1 |

状态6入口`0x4ab38a–0x4ab38f`将保存的颁奖句柄交给`0x48568d`。该函数进入`0x5705bb`，清除播放次数并调用`0x57520a`停止声音，证明UI38在成长前停止。`0x571ca6–0x571cdb`识别次数−1，经`0x5750cb`写入OpenAL的LOOPING属性并保存播放次数。`0x5718e3`负责从声音池选择对应或可重用声部；UI29的原WAV长约0.06186秒，重复的帧请求是短音声部，不是UI38式循环句柄。

玩家行阶段只在进入该阶段的入口`0x4ab15d–0x4ab168`播放一次UI36，与逐行provider及位置函数`4a722e`/`7265`/`72a0`/`72db`/`7316`/`7351`无关，这些函数不发声。各行按0.3秒间隔推进，不逐个发声。

只读取现有ASM、PE对应函数及原WAV头，未执行原生取证脚本。

## 网页接线

`audio/battle-summary-sound.ts`解码九个原音效，独立于现有结算音乐。UI38使用可停止的循环声部，UI29按requestAnimationFrame请求短声部；滚分帧先停止上次UI29，经验帧沿用原重复请求。其余声音由`battle-summary-audio.ts`按阶段、实际奖项索引、显示等级和新称号ID触发，快照刷新及分页沿用相同游标。音量函数引用更新时音效实例不重建，游标不重置，同局演出不重播。后台恢复仅消费当前演出状态，不补播错过的阶段。

原界面、字体和声音资源准备完成后才开始演出；音效载入失败显示状态并继续结算操作。音量读取当前Battle运行值，因此静音0和存储不可用时已调节的音量仍有效；未设置运行值时采用原目录默认值。一次性声音被浏览器拒绝时跳过，后续真实交互只恢复当前滚分或当前颁奖循环。换局、再战或结算页卸载停止全部声部、取消滚分帧并释放音频上下文。

## 限制

网页声部调度、后台帧暂停和原OpenAL声音池不同；没有证明逐帧听感或高清视觉一致。音效载入失败时不重试，本次结算继续显示。当前结算序列没有实际奖项时跳过颁奖阶段，不播放空奖项提示。未运行测试、浏览器、构建、类型检查或lint；M5-04/M5-05/M5-06父项保持未完成。
