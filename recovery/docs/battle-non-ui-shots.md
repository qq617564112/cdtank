# 非UI射击射程与推进

连续弹丸现在以当前查询射程为唯一行程上限。普通1000射程和FuncType23采用的百分比射程都从炮口前移到角色中心的剩余距离计算，不先按固定2.2秒删除，也不让查询端点落在弹丸实际可达距离之外。

## 最终行为

| 环节 | 合同 |
| --- | --- |
| 目标查询 | 普通查询使用1000；FuncType23按采用的总范围百分比换算。普通2001仍在03启动后约0.4秒进入该查询，FuncType22仍在该查询边界即时选择目标。 |
| 连续弹丸 | 查询半径为`range`，炮口沿瞄准方向前移30。弹丸从炮口到角色中心方向的查询上限需要`range - 30`的行程。 |
| 实际推进 | 每步只取`min(速度*dt, remainingDistance)`。末步截到查询上限并先完成扫掠碰撞，再按行程耗尽移除。 |
| 寿命 | `ttl`取`remainingDistance / 360`，与上述采用的360单位/秒和炮口规则一致；普通和百分比射程不再共用固定2.2秒。 |
| direct路线 | 普通2001与FuncType22继续在查询时完成单目标处理，不创建普通2001独立bullet。 |

`beforeShot`、约0.4秒后的`fire`、有限库存消费和连续弹丸对普通命中后效的复用均保持不变。

## Web飞行显示

连续弹丸的`x/y/z`、`vx/vy/vz`由`rooms/snapshot.ts`写入`MsgRoomSnapshot.bullets`。BattleProjectiles沿正式Battle帧按ID创建、更新和移除采用的金色自发光本体／短尾迹；从最新serverTime最多推演100ms，坐标保持Web的X反射。非PLAYING、地图未就绪、断线、换局、离房和scene销毁清理对应owner。炮口、场景端点和受害者命中特效保持各自入口。普通2001沿即时查询不生成独立飞行实体。详[battle-projectile-presentation-runtime.md](battle-projectile-presentation-runtime.md)。

## 来源边界

显示链的直接证据只证明`423956`至`489ba8`把入口XYZ和所选技能效果参数交给显示/声音接口，没有在该链创建弹丸，也没有提供权威出生点、速度、寿命、轨迹或命中来源。约0.4秒回调查询及普通2001不创建独立bullet来自原定时与接收链；普通1000查询、场景等距离选择及显示端点算术来自原4288fe/4289e7相关执行。

360单位/秒、水平30炮口和Y+20、连续3D扫掠及上述寿命换算仍是Web采用规则，不是已恢复的原弹丸创建参数。原独立飞行实体的创建与更新、原FuncType22/23服务端分派、原始X单位及玩家取得链仍未恢复；未知最终攻防公式不改。

本页只记录静态核对后的最终行为和来源边界。未运行测试、浏览器、构建、类型检查、lint、导出器或原生取证。
