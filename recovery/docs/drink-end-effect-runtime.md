# 四种饮料第二效果槽接线

攻击、防御、速度、回旋饮料 item4/5/6/7 分别引用 skill4/5/6/7。四份技能表都把首槽用于属性增益表现，第二槽一致为 Effect10、SE02、Tag0、Method3。当前实现由服务端在原临时状态存活自然期限到期时，先清除技能与属性贡献并发送原停止通知，再单次发送第二槽通知。

## 采用政策

- 只有角色仍存活且 `now >= expiresAt` 时判定为自然到期。
- 到期先执行现有 `clear*Drink`，保持原十秒期限、库存消费/CAS、属性重算和首槽寿命不变。
- 停止事件保持原 `skillStopped`/`stopSkillEffect`，随后发送独立的 `drinkEndEffect` 事件。
- 第二槽通知使用真实 skillId、`effectIndex: 1`、`duration: 0` 和真实 roleId；事件携带清理后角色的位置。
- 死亡、显式 `clear*Drink`、结算换局和离房均不发送第二槽。到期状态在首次清理后即不存在，后续时钟或输入路径不会重复触发。

原证据只确认 skill4/5/6/7 的第二槽表项，没有确认原服务端在增加、移除或到期时触发该槽。上述到期触发是本次项目采用规则，不视为原规则还原。

## 消费链路

`World.step` 与普通/托管输入路径已到达四个 `advance*Drink`；事件按数组顺序广播，既有 Battle 事件转发不需要新增协议字段。Web `BattleSkillEffects.event` 对每个事件先处理 `playSkillEffect`、后处理 `stopSkillEffect`，若停止和播放放在同一事件会立即停掉新第二槽，因此生产端拆成两条按序事件：停止在前，仅播放的新事件在后。

`SkillEffectNotifications.play` 以 `skill.effects[effectIndex]` 选择槽。skill4/5/6/7 的索引 1 因此沿现槽消费者创建 Effect10 并按 Method3/Tag0 绑定真实角色，同时分派 SE02；不需要修改客户端效果消费者。

## 静态边界

本次仅完成源码与表项接线，没有运行测试、浏览器、构建、类型检查或 lint。待实测覆盖：

- 四种饮料各自自然到期时收到一次停止事件和一次 `effectIndex: 1`，Effect10 与 SE02 只在角色当前挂点消费。
- 两条事件的实收顺序为先停止后播放，第二槽不会在创建当帧被停止。
- 十秒期限、消费/CAS、攻击/防御/移动/回旋属性、首槽 Effect106/108/110/113 寿命保持原状。
- 死亡、显式清理、结算、换局和离房不出现第二槽，重进或再次输入也不补播。
