# 原等待房间退出按钮来源

原`room_main.xml`的`btnClose`直接进入网络请求回调，没有确认对话框，也不是只隐藏等待房间面板。`recovery/.venv/bin/python recovery/evidence/rooms/waiting-room-exit-source.py`：PASS；证据为`recovery/output/waiting-room-exit-source.json`。

## 控件到回调

原EXE字符串`0x5d65a4`为`RoomPanel/btnClose`。初始化`0x50a1cc–0x50a207`用该名字查找控件，在`0x50a1fa`写入等待房间控制器`+0x4c`。

事件注册`0x50f9b2–0x50fa06`读取同一个`+0x4c`控件；`0x50f9bf`将`0x50c165`作为回调交给`0x50ce90`，随后通过控件事件对象虚方法`+8`注册并将连接保存至控制器`+0x250`。Ready、Cancel另有各自回调，不与关闭按钮共用。

## 请求行为

完整回调`0x50c165–0x50c18e`先执行按钮事件`0x4d650b`，然后读取全局`0x633588`的`+0x118`服务，调用`0x42704e`，最后返回`true`。该回调没有调用面板隐藏、销毁或确认对话框。

`0x42704e`读取当前场景对象的虚方法`+4`，只有返回3时才构造请求。构造函数`0x425774`设置消息虚表`0x5c3254`；其类型虚方法`0x424557`返回`0x3a9e`。消息经过`0x413e8c`写入本机身份字段，再执行原`0x402350`、`0x402090`编码并进入socket发送。

取证从已注册回调`0x50c165`完整执行到返回，供应场景查询、按钮事件和socket发送边界；消息构造、身份写入和序列化均运行原指令。身份fixture为`0x1234`时，场景3发送`9e3a341200`；场景2、4均不发送。关闭按钮因此应接到离房业务请求，而不是只关本地面板；请求发出本身不证明服务端已经完成离房。

## 限制

本证据确定关闭按钮的绑定、直接网络请求及场景门槛。未恢复消息`0x3a9e`的原服务器处理和响应后的房间清理/UI切换；Web的Leave请求与权威确认属于重建接线，不能据此声称采用原协议或原响应时序。
