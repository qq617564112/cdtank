# HUD 小地图逐图坐标映射

## 原客户端入口

原 `picMiniMap` 的内容矩形是192×192。`CDTank.exe` 的 `0x4cc726–0x4cc776` 取得 `picMiniMap` 绘制对象，将原场景对象 `global(0x635830)+0x60` 的纹理 `+0x184` 送入；它没有读取 `xiaoditu0`。`xiaoditu0` 的25个普通区域实际为106×86透视图，用于选图页，不是战斗俯视底图。

原世界位置通知链为 `0x424be9` → 场景虚方法 `+0x18` → HUD `0x4cc791` → `0x471684`。后者取得场景整数矩形并比较宽高，在较短轴居中留白，保留统一比例；原192.0常量位于 `0x5c92c4`，居中0.5位于 `0x5cd00c`。这些是直接读取原指令与PE常量的事实。

## 25图固定映射

## 俯视底图与标记

0001–0025与测试地图1001共26张底图由 `scripts/render-map-minimaps.mjs` 从真实三维场景离线生成，使用1024×1024正交渲染目标。`ScenePreview.load(id, effects)` 提供正式战斗的地形、建筑、植物、水面、原CVD首帧和城堡n1动作，渲染列表为已启用的 `ScenePreview.minimapMeshes`。室内0009、0015、0018排除整场天花板，保留下方真实地面和物件；不烘焙玩家、弹丸、伤害文字和运行时技能粒子。资源、生成命令及全部图像总览见 [map-minimaps.md](map-minimaps.md)。

相机中心为 `(-(minX+maxX)/2, height, (minZ+maxZ)/2)`，向负Y俯视，以正Z为图像上方；正交左右/上下范围同为长轴跨度的一半。GPU读取转换为PNG时翻转行，并反射图像X，恢复Babylon glTF反射前的原世界坐标。最终原+X向右、原+Z向上。底图与标记共用同一份每图lookup：

```text
pixelX = 192 × (worldX - minX) / (maxX - minX)
pixelY = 192 × (maxZ - worldZ) / (maxZ - minZ)
```

正式战斗通过 `mapMinimaps[mapId]` 加载源码PNG，离房释放雷达纹理。`BattleMinimap` 只供离线渲染器使用。启动图片预加载器通过源码图片glob包含全部26图，PNG随前端发布。

圆形雷达以本机为中心，沿战斗相机的水平轴采样底图；玩家、王和目标仍由权威快照及实时战车位置投影，超出范围的标记保持方位，中心固定在内侧白色细边框中线；标记允许向小地图圆外溢出一半。纹理使用原坐标的+X向右、+Z向上方向，与雷达着色器采样一致。 玩家标记使用21种实际坦克的64×64俯视图标，本人/敌方/友方分别采用白/红/蓝3像素外轮廓；图标按当前tankId选择并随车身朝向旋转，生成与接入见 [tank-minimap-icons.md](tank-minimap-icons.md)。

## 限制

25图的原坐标范围、原出生点与Web像素映射关系已建立。未执行原场景虚方法，原动态纹理生成相机、原整数矩形的完整生产来源及原GPU最终像素仍未全部恢复。NAV/RPT并集是本项目采用的固定窗口，不能称为原整数矩形的逐值复现。已完成26图真实三维俯视PNG生成及静态图像查看；未运行测试、构建、类型检查或游戏浏览器验收。实际对局标记对齐及高清显示仍待验收。
