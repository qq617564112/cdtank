# HUD 小地图逐图坐标映射

## 原客户端入口

原 `picMiniMap` 的内容矩形是192×192。`CDTank.exe` 的 `0x4cc726–0x4cc776` 取得 `picMiniMap` 绘制对象，将原场景对象 `global(0x635830)+0x60` 的纹理 `+0x184` 送入；它没有读取 `xiaoditu0`。`xiaoditu0` 的25个普通区域实际为106×86透视图，用于选图页，不是战斗俯视底图。

原世界位置通知链为 `0x424be9` → 场景虚方法 `+0x18` → HUD `0x4cc791` → `0x471684`。后者取得场景整数矩形并比较宽高，在较短轴居中留白，保留统一比例；原192.0常量位于 `0x5c92c4`，居中0.5位于 `0x5cd00c`。这些是直接读取原指令与PE常量的事实。

## 25图固定映射

## 俯视底图与标记

`BattleMinimap` 在地图资源就绪后，以768×768正交相机拍摄已加载的原地形及原场景物件。渲染列表由 `ScenePreview.minimapMeshes` 提供，不包含玩家、弹丸、伤害文字和运行时技能粒子。图像按地图缓存，捕获后释放纹理与相机；取消加载、离房与场景销毁清理未完成捕获。HUD清除旧图，不跨地图复用。

相机中心为 `(-(minX+maxX)/2, height, (minZ+maxZ)/2)`，向负Y俯视，以正Z为图像上方；正交左右/上下范围同为长轴跨度的一半。GPU读取转换为PNG时翻转行，并反射图像X，恢复Babylon glTF反射前的原世界坐标。最终原+X向右、原+Z向上。底图与标记共用同一份每图lookup：

```text
pixelX = 192 × (worldX - minX) / (maxX - minX)
pixelY = 192 × (maxZ - worldZ) / (maxZ - minZ)
```

原本机 `wotanke.tga` 的箭头朝上，当前原世界方向为 `(sin(yaw), cos(yaw))`，因此图标按 `yaw` 顺时针旋转。标记不通过截断坐标挤到边缘；显示边界由父图窗口裁切。未知mapId或尚无本图俯视纹理时不显示错误底图或标记。

## 限制

25图的原坐标范围、原出生点与Web像素映射关系已建立。未执行原场景虚方法，原动态纹理生成相机、原整数矩形的完整生产来源及原GPU最终像素仍未全部恢复。NAV/RPT并集是本项目采用的固定窗口，不能称为原整数矩形的逐值复现。未运行测试、构建、类型检查或浏览器；新增俯视捕获及25图实际画面对齐、高清显示仍待验收。
