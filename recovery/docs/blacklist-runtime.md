# 屏蔽与私信

玩家从正式大厅名单打开原玩家资料页，点击原屏蔽按钮。服务端认证账户是关系 owner；所选玩家的稳定账户ID是 target。独立 account_blacklist 表保存单向关系，不修改好友表、原角色资料或库存。确认后同位置显示解除屏蔽；自己和不存在的账户拒绝，重复添加和删除已不存在关系幂等，允许已建立的离线账户。

大厅与房间密语在解析身份、目标与当前发送资格后，检查接收方是否屏蔽发送方。命中时返回 WHISPER_BLOCKED，没有新消息投递，客户端保留文本；解除后继续使用现有私信确认与双方消费路径。此服务器过滤为明确重建规则。原公开、队伍、好友频道、家族及GM的过滤范围没有依据，不据此推定。

Blacklist store 拥有账户权威列表、请求代次和写入 pending。迟到查询不能撤销新写入，断线清缓存并隔离旧响应。LobbySocialView 拥有资料选择和目录状态，PlayerInfoView 拥有原按钮状态、键盘与焦点。进入房间停止大厅关系查询，回大厅重新查询；消息资格始终读取服务端持久关系。普通资料打开手势沿用当前右键和Shift+F10重建适配。

原角色 getter0x40cd6f 读取byte+0xc屏蔽标记，两个原消息入口0x48e377/0x4909af检测该标记并跳过后续；原Add/Remove按钮经0x4eff44/0x4eff97→0x426794选择不同请求发送。该静态依据保存在blacklist-source.json，不冒称完整原消息频道覆盖或原回调已执行。好友selector对应的两树另由角色上线/移除路径搬移，不能将其合计64门禁直接当黑名单上限。

来源、网络、正式网页和重启证据分别归M6-09-K及M5-13-R-K；原未知资料与全部社会功能仍由父项验收。本轮复用好友业务和原资料根整页的有效基线，新增屏蔽操作及实际消息拒绝单独验收。
