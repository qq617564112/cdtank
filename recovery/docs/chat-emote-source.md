# 原战斗聊天表情选择与编码

原表情1–30在输入框中是单个Unicode码点U+2581–U+259E。选择按钮在光标位置插入一个码点；手写`/01`–`/30`经原文本变化回调转换为同一码点。原发送转换将每个表情编码为双字节A262–A27F；收到文本的显示转换再生成`<emote name=001 red=255 green=255 blue=255 alpha=255/>`图文标记。三层表示具有不同长度，不能将显示标记当作原网络语法。

`recovery/.venv/bin/python recovery/evidence/chat/chat-emote-source.py`：PASS；结果为`recovery/output/chat-emote-source.json`。选择、手写token、发送特殊双字节和输入字体图片映射已确定；收到RichEditbox的解析与动画执行仍缺来源闭环。

## 原控件与选择

`GameMainShrinkedChat/btnExpandEmotion`在`0x4c9c2e–0x4c9c66`绑定HUD`+0xc0`，`0x4d54b2`注册`0x4cc5cc`。回调检查聊天面板`+0x84`是否已经包含表情列表`+0x698`；没有时添加并置前，已有时保持打开。它不是同一按钮点击关闭的切换。列表关闭回调`0x4cc295`移除该子控件。

初始化`0x4ca597–0x4ca62d`循环30项，将`GameEmotionList/%.3d`的001–030绑定至`HUD+0x69c+4*i`，同时设置ID0x252–0x26f。注册循环`0x4d5568`给这些按钮注册`0x4cc2c2`。

选择回调以事件对象`+8`控件搜索30项，得到零起始索引i。普通频道的`0x4cc471–0x4cc589`从`edtChat(+0xac)`复制文本，以控件`+0x334`光标位置分出前后两段，在前段追加`U+2581+i`，合并后设置原输入文本并置前，最后把光标加1。它保留前后普通文字，不插入`/NN`或XML，也不在该回调关闭表情列表。原输入上限72来自已恢复初始化；选择回调自身没有长度比较，最终超限处置委托CEGUI Editbox，尚未执行其完整行为。

## 手写输入与图映射

原`0x4cb169`读取普通输入副本并扫描三个连续字符：斜线、数字0–3、数字0–9；`atoi`结果必须1–30。有效片段`/NN`删除三个字符并插入`U+2580+N`；无效00、31–39保留字面。扫描从字符串begin到end，不限光标之前或末尾；`/010`将前三字符转换为U+2581并保留后面的0。转换后暂停输入事件、设置文本、恢复事件；本回调没有显式调节光标，setText对原光标的最终处置仍委托CEGUI。密语和普通文本变化属于不同输入路径，本证据限定普通输入。

原字体注册`0x45448e–0x4544fd`循环U+2581–U+259E，把每个码点映射到`data\ui\biaoqingfuhao\%.3d.tga`对应001–030，通过`CEGUI::Font::appendCharacter`注册。该图名映射来自原调用参数，不是根据图片文件名猜测。表情列表XML的图引用与这些基础图对应。

## 发送与收到文本

发送入口`0x4d332f`的`0x4d3385`调用`0x4119b0`转换输入。其U+2581–U+259E分支`0x4119fb–0x411a11`写入0xA2和0x62–0x7F，两字节表示一个表情；普通字符走系统宽字节转换。原普通文本发送使用转换后的字节串，表情不在线上发送XML标记。

收到文本的显示链已有入口`0x48ea74 -> 0x4127a0 -> 0x41242a`；同一转换也由`0x48edce/0x48f11c/0x490c41`调用。`0x4127a0`先通过`0x412649`将收到字节串转换成CEGUI字符，再由`0x41242a`展开内部表情码点。每个表情精确输出：

`<emote name=001 red=255 green=255 blue=255 alpha=255/>`

名字为三位整数，无引号，属性前有一个空格，末尾`/>`。U+2580不展开，U+2581–U+259E分别展开001–030。非表情字符分支逐字符保留，包括`<`、`>`；本函数没有转义普通文本。扩展结果写回收到聊天文本，再经观察者通知显示。普通文本与任意多个表情按原顺序组合，不能将文本里任意名字相似的片段识别为表情。

## 验证与缺失边界

脚本执行完整展开回调的已有/未有子列表两种情况、30个按钮索引搜索和码点追加块、七个`/NN`转换边界、完整30个表情专用发送转换和30个原字体图名选择。对应CEGUI操作由钩子记录；手写token与字体格式化钩子读取原参数。收到XML展开为保留原反汇编的静态证据，尚未执行完整混合字符转换或RichEditbox渲染。

源图集包含001–030基础图及`NNN_1`等动画帧。当前原字体映射明确使用基础图，收到RichEditbox是否选择动画帧、帧序与时间不能据此猜测。准确下一入口是`CDTank/CEGUIWindowsLook.dll`导出：`WLRichEditbox::onTextChanged`0x10027980、`formatText`0x10027370、`formatTextImpl`0x10026c10、`renderTextLines`0x100243e0、`updateSelf`0x10024920。收到图文标记的最终消费和动画定时需要在这些原函数建立调用链。

Web可用已恢复的单码点输入、`/NN`转换和基础PNG映射；若新协议采用canonical emote标记，应明确为重建传输适配，按解码后的逻辑字符校验72上限。当前证据不能声称原发送协议、RichEditbox动画和完整图文显示闭环已恢复。
