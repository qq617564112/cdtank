# 光学迷彩客户端通信推导服务端业务

原服务端程序缺失时，本业务依据客户端普通输入、接收确认和原表参数重建。以下区分已经取得的客户端/表证据与据此选择的服务端业务；不把推导写成原Windows服务端已执行。

## 请求与确认

普通使用43d4dc只在缓存角色存在、43293d状态为2、两库存中存在匹配实例且本局数量unsigned非零时发送。分类1物件9不要求已配置快捷槽，也不要求在请求中给出目标、生命、期限或技能参数。43c7bd/3c9e只编码实例及既有未知字段；当前推导不使用未知字段，并保持其原值语义未知。

3c92是独立库存扣量通知，原证据只证明接收后可更新拥有量/本局量，不能证明它绑定某个前序3c9e成功。当前服务端选择“保存成功后再完成作用”的事务顺序：先以拥有实例、拥有量和表ID调用既有CAS/CPU确认，成功后再减本局与拥有数量、加入临时技能并设置权威期限。CAS拒绝或异常时请求失败且不改变角色。sequence重放由现有输入门禁拒绝。

## 技能与期限

item9关联skill9，BattleUseMax2。skill9的Target1、TriggerType1、FuncType7、T10提供自用和10秒期限的资料边界；物件及技能Effect/Sound全0，故本业务不发送PlaySkillEffect或StopSkillEffect。服务端只在16槽技能数组存在空位且skill9未生效时接受；满16槽或重复使用不消费。成功加入的skill9只是本实例的临时状态，清理时只移除这项状态对应的槽位。

期限使用服务器milliseconds权威值，snapshot字段只是结果投影。普通输入处理前和World每步先推进到期；死亡、复活、结算、首次开局、再战及正常离房清理临时技能/状态。客户端不乐观扣除或本地提前生效。

## 观察与CPU

客户端通信没有提供本机、同队与敌对的原actor模型可见分支，因此该观察规则是明示重建：存活的item9状态对自身不可见过滤关闭，团队模式1至3只对异队隐藏，模式4至5把其他所有玩家视为敌对。共享`isHiddenByOpticalCamouflage`同时供CPU敌人选择，隐藏目标立即从可用集合移除，现有目标或路径因此失效重选。隐身只影响观察者选择，不改变碰撞和手动弹丸命中，普通开火也不取消。

CPUitem9不是购买或库存赠品。房主在WAITING可为槽5至8配置item9及1至BattleUseMax2的有限数量，临时实例只在CPU房间状态内；CPU策略在存活status2、可见威胁距离300以内且HP不高于半血时返回普通输入槽，后续仍由同一消费、状态和期限路径处理。零价格和GGet0不授权免费购买或免费发放，正式Shop目录保持不含item9。

## 支持条件

接受条件：显式拥有实例、正拥有量/本局量、角色存活status2、item9原表与skill9原表匹配、期限为正、16槽有空格、skill9未生效、消费确认成功。

拒绝条件：错误请求类型或实例、非item9、零拥有量/本局量、角色死亡或非status2、重复生效、skill9已在槽内、技能栏缺失或已满、消费确认失败/异常。拒绝不扣库存、不添加或移除其它技能、不改期限。

## 未执行验收
