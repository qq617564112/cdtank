# 装备准备生命同步

普通账户确认角色或装备后，等待房间按当前已确认来源重算上限，再通过现有 `setBattleHealth` 发布同一满生命值至权威玩家、角色属性记录及角色记录54/58。缺少完整拥有来源时使用既有战车生命原型；撤回来源不保留上一套装备的上限。装备变化沿原有路径取消准备，首局和再战仍由战斗启动模块初始化生命。

`battle/preparation.ts`拥有这项准备策略。属性重算模块继续只恢复原属性算术，不承担房间阶段或治疗。正常PLAYING库存刷新与已经参战的FINISHED角色不进入准备生命初始化；新加入、从未开局的角色沿现有来源绑定资格初始化。准备满生命策略属于重建服务端规则，原服务器等待生命时序与原攻防公式仍归M2-01未完成范围。

## 验收

`tests/preparation-health.cts`覆盖126组原拥有来源及部件组合：来源绑定不保留原型308/204分叉，普通装备/撤装后生命与来源最大值一致、部件变化取消准备、另一玩家不受修改、来源撤回恢复一致原型。普通CPU射击自然受伤后直接调用正式库存绑定，生命145→145/max200保持，覆盖真实绑定刷新不治疗；网络只读Inventory QUERY不等同重新绑定。证据为 `preparation-health-rules.json/log`。

相关既有检查 `world-role-attributes.cts` 在126组来源与21战车普通开火/首局再战上通过，`account-battle-equipment-sources.cts` 在32组原资料、准备取消、冻结来源及再战清理上通过。两脚本房间名称调整为现行8字门槛内，业务断言保持；记录为 `preparation-health-{attributes,equipment}.log`。

真实网络与网页按专属验收记录；规则和模拟对局不能代替普通玩家页面交付。等待阶段网页没有可见装备入口，页面验收从大厅“我的家”装备确认开始；等待阶段卸装与取消准备只能据实际账户API验收，不声称隐藏页面操作。
