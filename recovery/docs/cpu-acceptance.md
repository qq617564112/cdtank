# CPU自动对局验收

CPU通过普通PlayerInput进入World，与真人共享移动、碰撞、弹丸、伤害、死亡复活及胜负规则。验收连接只操作房间、准备、再战和退出；战斗期间不发送真人移动或开火，也不改HP、位置、时限或目标数量。

CPU接近路径拐角时，仅在当前位置能通过服务端半径20的碰撞扫掠直达下一航点后，才提前跳过当前航点。原0020拐角路线纳入`test:cpu`，通过实际移动验证绕过障碍。

破坏目标射击由炮口至实际792距离弹丸射线与原源盒体相交判断，不再用目标中心700距离提前拒绝。射线上玩家球体使用服务端同一segmentSphere求交；活人先于物件命中则不发射，死亡/高度分离/物件后方玩家不阻挡。规则和弹丸数值保持，CPU只调整普通输入。

## 运行入口

| 命令 | 验收范围 | 通过条件 |
| --- | --- | --- |
| `npm run test:cpu` | 寻路、目标选择、五种玩法各连续两局模拟时钟对局 | 两局CPU自然移动/开火/命中，适用模式复活，两局结算冻结、再战保留CPU并清零状态、退出清房 |
| `npm run test:cpu:objectives` | 独立真实服务端、两条TSRPC连接、三张破坏地图完整实时对局 | 0020六CPU、0021三CPU、0022三CPU均以OBJECTIVE全清，双端快照/事件一致，冻结、双方真人同意再战、重置及断线清理 |
| `npm run test:cpu:realtime -- 22 0 5 3 --require-objective` | 单张破坏地图完整实时对局 | 同上，目标截止未全清记录FAIL并非零退出 |
| `npm run test:cpu:browser -- <Chromium-CDP-WebSocket>` | 真实网页房间与CPU对局 | 页面添加CPU、准备、自动交战、展示结算、再战与退出 |

实时三图入口顺序执行，不自动重试；任一地图失败就停止。第二参数0表示等到自然终局。完整对局每30秒输出剩余时间、已清目标数和CPU击杀数。原始证据保存在`recovery/output/cpu-realtime-20-full-cpu6.json`、`cpu-realtime-21-full.json`、`cpu-realtime-22-full.json`。浏览器入口使用960×540并缩小内部渲染分辨率，其通过仅代表页面流程正常。

## 后续实施顺序

1. 保留以上自动对局作为战斗回归入口，发生失败时按目标、CPU路线和自然命中事件定位。
2. 接通真实账户库存和快捷槽配置，再接通道具使用、成功消耗和技能施放。CPU仍走共享输入；验收检查实际数量、角色状态和战斗结果。
3. 接入独立特效还原模块，以真实施放驱动效果；浏览器自动验证挂点、声音、停止和清理。
4. 扩展出生位置、队伍和地图配置，补充1920×1080画面与性能测量。

## 当前边界

CPU属于重建AI。自动获胜验证当前服务端规则的可玩性；原行为精度依靠二进制和资源证据校准。现有线上库存为空，非默认快捷槽与实际消耗品/技能未接通。三张地图各自已有实时全清记录，但这些记录不代表所有人数、出生配置都稳定通关。高清渲染性能需独立浏览器测量。

## 连续两局生命周期

`test:cpu`在五种玩法中各自动完成首局和再战后的第二局，逐局检查自然移动、开火、命中、默认弹药选择及结算冻结。再战检查CPU身份保留、生命恢复、击杀/死亡/破坏计数清零，第二局结束后检查最后真人退出清房。证据为`cpu-two-rounds.log`及`cpu-match-mode*.json`中的`rounds`。

这是模拟时钟的生命周期验收，允许TIME_LIMIT结算；本次团队模式第二局和破坏模式两局为TIME_LIMIT，不作为目标胜利。三图实时全清仍使用独立`test:cpu:objectives`入口。
