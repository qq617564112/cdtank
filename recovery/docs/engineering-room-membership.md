# 正式玩家插入与 CPU 管理

E-02将原World.insertPlayer拆成rooms/membership的成员迁移与登记、battle/create-player的正式角色构造，加入队伍的平衡政策收进modes/start。World仍提供权威注册表、ID分配和离场入口，没有复制角色或建立第二套房间状态。

已通过admission的加入先遍历注册表，找到同连接旧玩家时调用原World.leave，因此旧房间按原策略结算/冻结后再删除旧成员。随后分配新ID、解析战车、按队伍人数平衡且同人数优先队伍0、按当前成员数取原出生点、构造并登记新角色。个人模式仍使用队伍0。玩家名称清理/默认名、回退生命、战斗状态/库存/拥有来源/属性记录、输入/计数初值保持原行为；完整账户来源由原API后续绑定，不在构造时赠送或补造。

rooms/cpu在World核验成员/局号/WAITING后处理房主资格、存在/容量与战车门槛、CPU增删及准备名单。新增仍调用同一成员插入入口，只在实际插入时生成原CPU名字与连接ID，然后安装BotController；增删后清除所有准备确认并仅重新准备现存CPU。CPU不能管理其他CPU，拒绝命令不改名单。自主控制继续走普通输入，不添加直接战斗状态注入。
