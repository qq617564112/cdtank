# 26模式地图普通输入对局

`tests/cpu-all-maps.cts`逐一使用m001–m005的全部26个模式/地图组合，每个组合独立创建World，正常建房、添加CPU、开启本人托管及准备。每张图4人：托管房主战车105、三CPU战车1/105/1。原最低人数、最大人数及时限不覆盖；实际人数满足来源限制，团队双方都有参与者。场景source ID、原出生位置（按快照精度）、破坏场景目标placement及VIP生命均逐图核对。

每个组合连续两局：正常输入移动、瞄准、开火，经World碰撞、弹丸、伤害、死亡及目标计分自然结束。第一局结束后房主正常同意再战，CPU自动投票，第二局保留参与者与托管配置，恢复生命及目标并清零战绩。结算的逐人战绩、来源胜负奖励和总分核对后继续推进时钟，玩家、目标及排名结果保持冻结；房主退出后CPU房间删除。

验收要求整体CPU移动、开火与命中，记录每个角色的活动量；占领另要求实际目标得分，破坏另要求源场景目标实际被摧毁。自然超时有实际战斗及目标进展才能通过。擒王的近距离角色可以原地射击，短局中没有要求每个角色都移动、开火或击杀。

## 复现与证据

- `npx tsx tests/cpu-all-maps.cts`：运行全部26组合；任一检查失败时继续剩余组合，汇总后返回非零状态。
- `npx tsx tests/cpu-all-maps.cts 5-20`：运行单个来源组合。
- `recovery/output/cpu-all-maps/summary.json`：范围、全部检查结果及各图证据。
- `recovery/output/cpu-all-maps/<mode>-<mapId四位>.json`：来源完整配置、实际人数/战车、场景规模、初始/结束/途中快照、逐角色位移/开火/命中、死亡/复活事件、占领进度、剩余目标、终局原因及step耗时。
- `recovery/output/cpu-all-maps.log`与`cpu-all-maps-types.log`：运行及TypeScript检查日志。

## 限制

这是重建World的普通输入集成验收，使用50ms模拟时钟加速执行；不是实时调度或浏览器渲染性能验收。step耗时仅记录当前运行环境的观察值，不证明原最大人数12人和完整技能负载下的M7-03。每张图实际4人，不代表每个人数/战车配置。没有位置、生命、伤害、结算或时限注入。

原准备/房主开始、团队/占领/VIP/混战完整规则及技能仍有任务清单中的来源缺口。这里验证当前重建规则、来源地图加载及生命周期，不把26条MAP整体标为原版完成；网络双端同步、全部时间/判负分支和高清像素仍需各自证据。已有六CPU的破坏117目标全清证据属于另一配置，不能替代本次四人结果。
