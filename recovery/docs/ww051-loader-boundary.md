# ww051 原加载边界（M4-10-I04 / M4-06）

Effect106 的 Type4 节点2915将 `ww051` 作为 WAV 文件名主体传给原声音入口 `0x4858f2`。实际执行该入口得到 `data\sound/ww051.wav`；此调用链直接拼接目录、原引用和 `.wav`，不经过 MusicString 表或别名分派。

原启用声音管理器 `0x571c50` 先经 `0x572f52 → 0x572fff → 0x56f296` 调用 `SHLWAPI!PathFileExistsA`。当前发行目录中的这个路径不存在；原判断跳到 `0x571d00`，返回 validity 字节0、三个 identity 字段0的播放描述符，没有进入资源加载选择入口 `0x5718e3`。对该描述符继续执行原完成查询 `0x5702b0` 返回 true；原停止入口 `0x5705bb`直接返回，没有查找句柄或调用声音设备停止。

因此缺失引用的原行为已能在当前发行内容上确定：声音播放失败后被视为完成，不需要以另一份 WAV 替代。该证据只证明文件路径、缺失门禁和无效句柄消费者；不会产生 ww051 音频内容。

## 执行和验证

`recovery/.venv/bin/python recovery/evidence/audio/ww051-loader-native.py`

运行真实 EXE 的声音入口、字符串构造/拼接/析构、两个单例 getter、文件存在包装、播放管理器、完成查询和停止入口。供给边界为 heap 分配/释放、已初始化的启用单例状态及空文件前缀，以及 `PathFileExistsA`：该 OS import 使用原游戏目录实际文件存在结果。没有替换声音入口、存在包装、资源加载器、完成查询或停止实现。

输出 `recovery/output/ww051-loader-native.json` 保存节点、parameter、实际请求路径、OS结果、执行入口和句柄结果。断言捕获路径或扩展名错误、缺失门禁仍进入加载器、失败描述符被当作有效、失败声音持续等待、无效描述符触发设备停止；若出现差异，相应缺失声音合同不能接入。

## 限制

原 Windows OS实现、非空文件前缀、成功资源加载/解码和音频设备播放未执行。原24字节描述符的 padding 与尾部不作为有效身份字段比较。当前 ww051 音频仍缺失；本合同证明当前缺失引用的结束行为，不声称恢复该声音内容，也不使整体效果保真验收完成。
