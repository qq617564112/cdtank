# 防御饮料双网页验收

`node --import tsx tests/browser-defense-drink.mjs`运行独立真实服务器、Vite与Chromium，端口分别为3166、5208、9280。本次运行PASS，服务器与Chromium退出确认均为true。两个隔离账号页面均以1920×1080视口、1920×1080实际画布和hardware scaling1渲染。证据与截图写入`recovery/output/browser-defense-drink*`。

两个账号从空库存开始，显式导入原tank1/part0宠物、战车记录与绑定profile；购买账号profile为100金币、40软星币。通过正常商店选择物件5，核对原价20金币/20软星币，BUY购买三份后余额为40金币、40软星币。购得实例经“我的家”配置至快捷槽4；创建mode4/map7房间、添加三名CPU、第二网页加入，双方正常Ready开始比赛。

普通Digit5确认技能5首槽通知：effectIndex0、duration0、实际角色编号。两个WebSocket流同tick的玩家与defenseBoost逐项一致，正式itemUsed通知在两网页一致。状态携带原Def30、DefBonus20、十秒期限、重算前后装甲和original-attributes来源；HUD显示“防御提升”及剩余秒数。生效期间再次Digit5收到itemRejected，数量与期限保持。首次使用后的普通KeyW驾驶使状态存活至原服务端期限，随后两个网页状态与HUD自然清除。服务端期限为1791007712203，最早清除快照为1791007712239，相差36毫秒。

两网页正式EffectRuntime创建Effect108根2917、11节点与七个绘制节点2918/2919/2920/2922/2923/2924/3106。Tag0引用实际战车`tag_efcenter`矩阵；监控记录非零几何提交和实际网格render回调，首轮两页实际绘制回调分别为3和5。独立SE40以selector1启动，音频上下文running、非循环，实际playing与ended事件均记录。首槽通知不保留持续效果记录，动画树与十秒防御状态各按自身寿命结束。

普通KeyA调整观察账号角色方向，使原角色跟随摄像机看到施法角色；读取真实frustum和摄像机方向后释放按键，不改变摄像机。第二轮普通Digit5再次播放原效果和SE40。命中值与攻击者原tank配置产生的`35 + attack × 0.08`比较，逐项核对增量防御比率`(100 + baseDefense) / (100 + boostedDefense)`。到期后自然CPU命中恢复原伤害。本次原装甲171.52999997138977→191.82999992370605，比率0.930438954330866；自然CPU弹丸原伤害43，生效命中40.00887503622724，随后恢复43。该比率是重建弹丸链路的解释，原Def30不等于直接减伤30%。

两轮均由正常CPU战斗自然结算，双方结果一致；双方普通Rematch进入第二轮，生命与计分重置、防御状态为空，购得余量继续使用。数量依次3→2→1。正常Leave后效果实例和独立声音归零；真实服务器停启、账号页面重载后，剩余一份、快捷槽4与40/40余额保持。脚本在成功和早期失败路径均关闭页面、Vite、服务器及Chromium并删除临时数据库。

脚本只导入账号自有原资料、初始profile余额及发送普通UI/按键输入；不注入战斗HP、位置、伤害、时间或结果。渲染监控只读取正式路径状态，硬件缩放用于明确实际1080p画布。
