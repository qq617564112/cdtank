# 服务端治疗道具模块

E-02将普通道具输入中的治疗授权、数量消费及成功/拒绝事件收拢到battle/healing.ts。模块使用同一生产目录，验证实际库存实例、物品1/2、拥有/战斗数量、技能目标/触发/FuncType2及正HP量；通过World提供的生命上限读取函数和账户原子消费回调执行。它不持有账户存储、房间管理或独立角色状态。

World保留当前对局/序号/真人或托管身份门禁、普通输入保存与快捷槽分派，并先发出itemRequest再调用治疗模块。满生命不消费；账户消费拒绝或抛错只返回原拒绝事件，不修改生命和两类数量；成功提交后才扣房间数量、恢复生命并生成原skillId/PlaySkillEffect协议事件。World现882行。

物品/技能HP来源已恢复，自身目标、满生命拒绝与成功消费仍是现有重建规则；原FuncType2完整分派和3c9e成功语义继续按M1恢复。

迁移验收全部通过：普通CPU火力自然受伤后的治疗、账户拒绝/异常/隔离/重复序号、两局自然终局/冻结/再战/重进/重启；9次CPU自动治疗与数量耗尽；真实双连接治疗成功/效果广播/数量保存及重启隔离；编译账户与迷彩联机重启、CPU五模式各两局、构建/类型及183模块运行依赖边界。证据为engineering-healing-{world,network,compiled,build,types,boundaries}.log。该片验证服务端事件合同，没有新增客户端原效果像素结论。
