# 可玩对局验收与后续策略

主线目标是玩家能够从加入房间持续完成一局、查看一致结果并再战。完整原版复刻同时需要恢复模式规则、数值、动态场景、技能/道具和所有界面业务；两项证据分别记录。特效恢复由独立任务推进，不能代替对局验收。

## 继续推进顺序

1. 完成五模式自然结束→一致结算→全员再战的闭环，使用原最低人数和原时限。每个自然目标终局和时间终局分开记录。
2. 补足团队次数耗尽、混战击毁达标与破坏清空目标等分支，并处理实战暴露的移动、瞄准、障碍和重生问题。
3. 以原客户端证据替换重建伤害、装填、重生、目标HP与目标规则；破坏模型切换、动态导航、刷新和掉落须由原实例关联证据驱动。
4. 接通技能、道具、账号身份及结算持久化，使连续对局与重启后的数据一致。
5. 接入独立任务恢复的原特效事件和动态挂点，完成原等待/结算窗口及高清多分辨率多人实战验收。

## 规则与功能边界

五模式的准备、输入、弹丸、HP、目标、计分、截止、退出、结算和再战由服务端权威处理；原地图、战车、出生、地形/NAV/静态盒体与场景物件已经参与对局。原表Time/PlayerMin/PlayerMax和得分字段有源依据；胜负条件的服务器实现、目标布置及多项战斗参数仍为重建政策。原版数值/完整动态场景/技能道具/奖励持久化/全部界面及成长社交尚未完成，整体R0–R6保持进行中。

## 团队出击耗尽验收策略

新增可复用目标脚本：`npm run test:team:browser -- <CDP地址> 1`（混战默认mode4保持十次目标）。团队用正常选车105攻击者与1受击者、原木桶广场、原300秒和30次出击，不改服务端规则。脚本逐次核对死亡、重生及teamLives，并检查目标结算、冻结和再战；不完整结果仍不得记PASS。

单攻击者的串行30次在当前800ms装填/3秒重生与随机出生点下需要大量转向和弹道等待。本轮先记录两人完整实战的真实次数与终局；如果截止前无法达标，下一验收采用正常四人两队、两名攻击者并行处理重生对手，或者在正常准备阶段选择明确可达的站位路径。失败证据用于区分操作效率与规则不可达，不能缩短装填/复活、移动角色或减少30次数来获得通过。两人脚本失败不证明30次分支不可达。

本轮两人尝试实测300秒截止：14次自然击毁，teamLives=[30,16]，TIME_LIMIT结算。browser-team-objective-attempt.json是未达目标证据，不能替代团队OBJECTIVE验收。下一次采用上述四人并行策略。
