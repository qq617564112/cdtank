# 普通战斗动作选择来源

普通战斗按完整M/X/Y或M/U/X/Y组合选择动作。相同动作尚未结束时，重复开火或同方向受击保留当前进度；目标动作改变时切换全部部件。死亡覆盖其他动作，复活回静止动作。结构化来源见`../output/tank-action-selection-source.json`。

## 原选择与完成合同

| 行为 | 原入口与条件 | 当前消费者 |
| --- | --- | --- |
| 组合切换 | 三部件`46888f`、四部件`46c2ab`顺序遍历M/X/Y、M/U/X/Y；HasAction成功且当前槽不同才GotoAction，再清消息并写当前槽 | TankView将同名部件放入一个ActionView，跨动作整组切换 |
| 相同动作 | 当前动作槽等于目标ID则跳过，不重置时间或消息 | fire/hurt保留正在播放的同名动作；结束后的新事件仍可重新播放 |
| 开火 | `468a53`／`46c42e`选择03、flags4 | 权威fire事件选择03 |
| 受击 | `46897a`／`46c396`按selector+3选动作；普通生产者只给1–4 | 权威hurtSelector1–4选择05–08 |
| 死亡／复活 | `468a03`／`46c3de`选择09并置`+19c`；`468a2b`／`46c406`清死亡标志并选01 | alive门禁阻止动作覆盖，复活强制回01 |
| 动作完成 | `468b2a`／`46c4c0`任一部件收到over即返回；`46900a`／`46c95c`在非死亡时回基础动作 | 当前消费者等全部部件完成，再按当前motion回基础动作 |
| 基础选择 | `4670de`写`+d8=0`表示移动，完成选02；`46495d`写1表示停止，完成选01 | motion(moving)同样选择02／01 |

原部件加载顺序来自三部件`469f70–46a051`和四部件`46d3dd–46d4c9`的数组写入。名称表`6d26b8`／`6d2734`包含01–09。

21车型的01/02/03/05/06/07/08/09共168组动作，直接读取原MV3头offset8后，同一动作各有效部件的duration全部相同。现有时钟按同一delta推进，普通数据的任一／全部完成条件在同一tick成立。

普通重复受击可由多名攻击者在一个受击动作期间产生。RoomEvent经Battle、BattlePlayers进入TankView；相同动作保留进度，跨动作继续按最后事件覆盖。动作已经完成后的同名事件构成新的播放。

## 来源与验收边界

原M部件真正切换后才执行外层`+c8`再`+c4`，涉及原矩阵和效果查找；Web沿既有主挂点、消息与ELK消费者，未声明全部原callback顺序或多动作混合等价。原主更新在收到over的同一次调用内回基础动作，Web沿下一motion调度恢复。

受击selector0可映射04，但已覆盖的普通生产者只给1–4；04及c系列的独立生产者仍缺来源。原整数时钟、消息和挂点证据沿各自既有范围；本次只有静态来源与源码接线，没有新增对局、浏览器或高清验收，M3-04完整父项保持开放。
