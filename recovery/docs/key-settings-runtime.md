# M5-14-B 可改键与正式输入

正常页面“键位设置”打开模态编辑器，显示前进/后退、车体与炮塔左右转向、开火、数字快捷动作1–8，以及使用道具、上一/下一武器、上一/下一道具共20个动作。点击对应按键后再按新键，只改变草稿。保存校验完整配置与按键唯一性，先完成浏览器保存，再应用到 BattleInput；无法保存时保持已生效配置。取消、Esc关闭或无效/冲突键都不改变已生效配置。恢复默认只改变草稿，须保存后生效。

当前默认保持已验收的 Web 控制：W/S、A/D、左右方向键、空格和数字1–8；新增使用道具 `KeyH`、上一/下一武器 `Home`/`End`、上一/下一道具 `PageUp`/`PageDown`。原 SystemSetting.ini 记录 DirectInput 数值键码，包含主/附属移动、UseItem、弹药和道具轮换、备用动作与快聊；该原数据不是当前 Web 默认映射，`UseItem29` 不解释为 `KeyH`，不能将本片称为原全部按键语义恢复。网页动作映射、禁止组合键/重复绑定、模态编辑交互和 localStorage 保存键 `cdtank.key-bindings.v1` 为明确重建规则；原 settings.xml 控件/回调、全部原动作仍待父项验收。五新动作 runtime 接口另见 battle-cycle-controls-runtime.md，本模块只负责绑定与设置消费，源细节见 battle-cycle-controls-source.md。

模块：match/input-bindings 提供唯一动作与 `INPUT_ACTIONS` 共 20 项、Web默认值和完整无冲突校验；match/battle-input 负责现有普通输入/序号/50ms发送及动作到绑定键映射；interface/settings/key-settings 负责草稿编辑、保存恢复、中文状态提示和按键显示；Battle暴露配置读写给设置入口，不暴露战斗状态修改。main在房间入口注册前恢复保存键位。正式两端协议、CPU控制器、服务端输入判定和技能消费者不变。

开局前和对局中均可修改；配置替换先清空按住状态。设置按钮取得焦点也清空按住状态，编辑窗口不会向战斗发动作。聊天、表单、中文输入组合与Ctrl/Alt/Meta组合不会触发手动战斗；单独 Ctrl 物理键（ControlLeft/ControlRight）可在设置页捕获，Ctrl+字母等仍拒绝；快捷动作仅首次keydown请求，repeat不重复；五个新动作拒绝 `Shift` 组合，原15动作既有语义不变；托管期间依然拒绝手动输入。按键名称提示与当前保存配置同步，未设置的新动作显示“未设置”。保存记录先验证所有实际存在的主/备用键与冲突，原15动作缺字段仍拒绝；五新动作允许缺字段即未配置，不自动补默认，也不因未配置制造冲突。畸形/冲突/缺字段的保存记录回退默认值，未知额外字段不会传播。

本地保存仅属于当前浏览器站点，不跨设备同步或自动更改其他已打开页面。支持字母、数字、小键盘数字、方向键、空格、左右 Ctrl、首页/末页/翻页，不支持浏览器组合键/功能键。完整原备用绑定、全快捷动作、画质及教学见M5-14/UI-50未完成范围。

验收：`npm run test:settings:keys` 验整表与正式输入门禁；`npm run test:settings:keys:browser` 验真实页面改键/取消/冲突/恢复默认/保存重开及真实服务器动作。设备/键盘夹具明确区分，具体证据在 key-settings-browser.md。既有历史验收证据仅覆盖原15动作，五新动作未实测，其 runtime 接口见 battle-cycle-controls-runtime.md。客户端类型/构建和正式依赖门禁验证工程边界；CPU连续两局作为共同输入集成基线，无需重复所有原效果或账户重启。
