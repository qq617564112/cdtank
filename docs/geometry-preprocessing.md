# 几何数据离线预计算

手机与电脑、怀旧与两套 HD 素材共用预计算结果。AssemblyScript 0.28.20 编译的 WebAssembly 内核只由 Node 资产工具运行，浏览器不下载或初始化该模块。

## 计算与读取

| 数据 | 资产阶段 | 客户端加载 |
| --- | --- | --- |
| 静态描边法线 | 按 0.0001 模型单位归组位置，依源顺序累加法线并归一化，写入 GLB 追加的 float32 流 | 读取 TypedArray，仅合格网格首次注册描边时上传 |
| 平面资格 | 使用原首顶点法线及 0.001 距离阈值计算 | 对 alpha-test 网格直接读取标记 |
| MV3 姿态去重 | 按原生 float32 的基准值加增量还原位置与法线，哈希筛选后逐字比较，生成原目标到唯一纹理层的映射 | 根据映射选择目标，继续由 Babylon 原生流程打包、上传 |
| 静态 MV3 形变 | 根据转换器的零增量 accessor 边界省略静态目标及对应权重通道 | 不再扫描和修改该结构 |
| CVD 几何与包围盒 | 拆出首帧位置与 UV，对位置作原 X 反射，遍历全部帧生成边界 | 从同一二进制缓冲读取视图及六个边界数值 |
| CVD 动画帧 | 精确去重，打包 XYZ/U 的 RGBA32F、V 的 R32F、顶点编号和原帧到唯一帧的索引 | 直接上传纹理，保留原时间区间与插值规则 |

GLB 的 `CDTANK_precomputed_geometry` 扩展记录描边 accessor、平面标记及形变层映射。原 POSITION、NORMAL、UV、顶点顺序、目标顺序及动画时间不变；描边沿用原静态网格过滤，形变、骨骼和烘焙动画继续使用原生描边通道。克隆共享原生几何与内部元数据，描边流不重复上传；未参与描边的地形和透明网格不创建额外描边 VBO。

形变层映射仅由共享 MV3 采样器加载路径使用，涵盖战车、城堡、Hook 和宠物。仍由 Babylon 动画组播放的模型保留原目标纹理布局和原生索引。

CVD 模型文档的 `geometryLayout: 1` 记录各视图偏移。客户端不再保留原交错的五分量帧数组，同时创建另一份位置、UV 或纹理像素缓冲。帧纹理仅包含唯一帧，重复帧仍按原时间轴参与插值。纹理宽度最多 8192，受 WebGPU 默认二维纹理尺寸保证覆盖；当前资源最大顶点数为 498。

## 生成与发布

源模型和源库保留在 `art/hd`，模型预计算追加到 `art/compressed`、`art/compressed-mobile` 的编码成品，再随战斗素材发布到 public。没有重新编码或缩放图片。

```bash
# 修改内核后重新生成随源码保存的 WASM
npm run assets:geometry:wasm

# 对已有两套 compressed 模型增量预计算，并更新当前 public 的 GLB/CVD
npm run assets:geometry
```

`assets:geometry` 支持 `--compressed`、`--compressed-mobile`、`--output`。默认 public 路径也遵守 `CDTANK_WEB_ASSETS`。

完整 `assets:compressed`、`assets:compressed-mobile` 在图片和模型编码后执行模型预计算；`assets:sprites`、`assets:battle-artwork`、`assets:publish` 共用的发布整理入口执行 GLB/CVD 预计算。GLB 的资产标记避免重复追加流；源模型重写后会重新计算。CVD 每次从完整源库重新打包，再交给 WASM 整理。生成报告写入 `output/geometry/`，不进入运行资源目录。

模型源与成品示例：

- `art/hd/Data/scnobj/obj05425/obj05425.glb` → 同相对路径的两套 compressed 成品 → `apps/web/public/assets/models/{original,hd,mobile-hd}/props/obj05425/obj05425.glb`。
- public 的 `data/maps/<id>/breach.json` 源库 → `breach.models.json` 索引及 `breach-models/<序号>.json/.bin`。

发布代码与新 public 资源需要同步，CVD 客户端要求预计算后的布局。

## 目录静态规模

以下为当前全部发布目录的结构规模，不代表一局实际加载数量或实测耗时。

| 项目 | 数量 |
| --- | ---: |
| 每套模型目录 | 967 个 GLB |
| public 三套模型目录 | 2,901 个 GLB，均已更新 |
| 每套预计算描边顶点 | 727,674 |
| 每套参与去重的 MV3 形变目标 | 26,882，映射到 19,052 个唯一层 |
| 每套姿态去重原本需哈希的位置／法线 float32 数值 | 45,010,854，客户端不再遍历哈希 |
| 每套移至资产阶段省略的静态形变图元 | 373 |
| CVD 模型／顶点节点 | 72／397，均已更新 |
| 旧 CVD 已压平数据的帧顶点扫描量 | 31,697，客户端改为直接读取 |
| 新 CVD 唯一帧顶点 | 28,562 |
| 保留 CVD 帧纹理的节点 | 4 |

预存描边流会增加文件体积。每套描边 float32 流共 8,732,088 字节；计入静态形变元数据省略及新增映射，HD GLB 合计由 301,548,584 增至 307,999,808 字节，增加 6,451,224 字节（6.15 MiB，约 2.14%）。public 三套模型合计增加 19,353,660 字节（18.46 MiB）。正常一局按实际模型加载其中一部分；额外描边 GPU 流仅在原本合格的静态网格上建立。

CVD 二进制由原已折叠完全相同帧的 905,056 字节降至 878,308 字节，减少 26,748 字节（约 2.96%）。新数据已包含首帧位置、UV、唯一帧纹理、顶点编号、帧映射、颜色和变换轨道；包围盒与偏移保存在模型 JSON 中。生成时临时读取未折叠的源帧二进制 5,813,056 字节，该数值不是此前客户端实际下载量。

## 验证范围

已编译资产 WASM 并执行资源生成，完成一次集中源码走查。未运行应用构建、测试、类型检查或浏览器验收，尚无本次修改后的开局耗时、内存峰值或 FPS 实测；目录计数不能换算为这些指标的提升。
