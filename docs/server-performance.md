# 服务端对局计算优化

服务端继续按配置的固定 tick 步长推进权威模拟，并保持先广播快照、后广播事件的顺序。本轮优化减少导航和碰撞查询中的临时分配、场景来源重建及全量碰撞遍历。

## 性能依据

用户提供的 `1.txt` 记录了地图 2、1 人＋9 CPU 的真实服务端采样。采样对象为实际运行游戏的 Node 子进程。

| 指标 | 既有结果 |
| --- | --- |
| 目标快照频率 | 20 Hz，50 ms |
| 实际快照频率 | 约 12.15 Hz |
| 快照间隔 | 中位数 85 ms，P90 101.8 ms，最大 134.9 ms |
| Node 主线程 CPU | 约 99.4% |
| 已识别热点 | 动画碰撞重建；`accessorValues` 自耗约 23.3%；`sampleRoleNavigation` 约 5.0%；`searchBotPath` 约 4.7%；碰撞查询与临时分配 |

场景碰撞资产已经在构建阶段固定到动画首帧，正式服务端直接加载预烘焙三角面、包围盒、空间格和 NAV 占用。相关策略见 [animated-scene-collision-runtime.md](../docs/recovery/animated-scene-collision-runtime.md)。

## 导航采样与寻路

`NavigationGrid.isValidAt` 使用与 `sample` 相同的原 f32 逆格宽、向零截断、低字节通行字段及当前房间占用，直接返回通行状态，省去高度和字段结果对象。`sampleRoleNavigation` 直接计算每个采样位置，不创建二维点数组。49×52 足迹、原浮点运算、左右失败码优先级及逐行查询顺序保持一致；CPU 路线检查仍每 6 单位采样。

A* 使用 `z * width + x` 数值格编号，父节点和成本不再使用字符串键。八邻居和步长成本在模块内复用；有向边按起点格编号和方向编号缓存，不同运动政策保留独立缓存。房间 `navigationRevision` 变化会清空所有政策的边缓存，包括暂停中的规划器持有的缓存。数值编号之前先判断格边界，避免越界列与下一行发生编号重合；编号 0 正常参与路径回溯。

邻居访问次序、二叉堆优先级比较和路径几何保持原实现。路径简化复用同一次已通过的通行查询。规划器继续使用每次 2 ms、最多 256 次迭代的预算。

## 碰撞查询与场景来源

动态场景网格按预烘焙世界包围盒加入 128 单位空间格。射线查询先筛选半径扩展后实际经过的格，再进行三角面扫掠，避免对全部动态网格执行窄阶段查询。物件更新、隐藏、销毁淡出和复活同步维护空间格；NAV 占用及修订号继续由原逻辑更新。

静态物件仍按源数组顺序判定，动态物件仍按插入顺序判定，等距离命中保留静态优先和原动态顺序。已有无网格 OBB 的局部轴扩展规则保留完整查询。

三角形面内判定改用标量叉积和点积，省去临时向量数组。面与球的初始接触只在距离可接触时计算，面扫掠只计算 0–1 时间区间内的候选；边、顶点、半径和容差规则保持一致。导航采样与三角面查询属于共享运动模块，也供客户端运动预测使用。

场景 solids、breakables、castles、crushes 和 plants 来源数组按地图复用。来源保留初始 HP、启用位和首帧几何；对局可变 HP、隐藏状态和销毁时刻仍由房间实体持有。碰撞同步对持续生效的物件直接保留已有实例，仅在新建或复活时查找来源，销毁后超过 2000 ms 释放的时机保持一致。

## CPU 移动预测复用

每次 CPU 或托管决策建立一个局部预测函数，以精确的 `move` 和 `turn` 数值缓存结果。同一决策中的转向选择、瞄准位置、速度药和转向药判断复用相同输入的预测；不同转向量保留独立结果。预测只消费移动输入，`aim`、`fire`、道具选择和序列号不参与缓存键。

决策内的存活玩家列表、动态门禁碰撞体及实际扫掠障碍按需创建一次。碰撞体复用同一命令、同一预测时长的 OBB；动态门禁仍使用原 0.3 秒调用及运动核 0.2 秒上限，扫掠障碍仍按原玩家朝向重建，保留两条碰撞路径的区别。

缓存寿命仅为单个参与者的一次同步决策。输入提交、道具生效和权威移动重新读取当前状态并执行碰撞检查；下一名参与者及下一 tick 都建立新上下文。接触通知仅在权威执行期间发出。

## 植物与可碾压物件接触

每个房间的植物、可碾压物件状态数组建立独立的 128 单位接触索引。来源通过放置 ID 一次关联，候选按原状态数组顺序返回。索引持有当前房间状态引用，每次查询读取 `enabled` 和 `hidden`；再战替换状态数组时建立新索引，旧索引随旧数组释放。

索引使用原六面轴 OBB 判定的保守水平投影范围：来源的三个轴按半尺寸合成最大水平投影，乘 `sqrt(2)` 覆盖坦克两个水平面轴约束，再加实际坦克的半对角范围。中心、矩阵及尺寸按原 f32 取值，范围向外取整并保留 1 单位余量。原判定没有交叉轴分离测试，此范围覆盖其接受的接触，包括几何 AABB 之外的接触。

动态门禁按原预测 OBB 查询附近物件；真人停止或移动权限拒绝时按当前 OBB 查询。最终仍由 `intersectsOriginalObb` 判定接触，Plant 在 Crush 之前通知，隐藏事件和物件状态继续归所属房间处理。

## 验证范围

本轮仅进行集中静态走查及改动文件空白检查，未运行测试、构建、类型检查或浏览器验收。上述采样早于静态碰撞资产及本轮优化，不代表当前版本性能。1 人＋9 CPU 的新快照频率、tick 耗时和服务端 CPU 占用尚无实测结果。
