## 渲染优化

MV3 动画只采样相邻姿态，纹理形变着色器固定使用最多 2 个影响目标。城堡动作使用同一采样路径。固定布局的权重过零时不再扫描全场景并标记顶点属性重建，实际权重和目标索引继续同步。

屏幕 HUD、小地图和名牌使用始终通过的深度判定且不写深度，渲染层不再重复清空全尺寸深度缓冲。共享音频监听器合并位置、朝向写入，并跳过未变化的值。

粒子保留自身状态和向量数组，以原浮点存储顺序更新运动、角度和透明度。过期粒子移动数组尾项，保留原来的前向遍历及跳过尾项行为；节点复用控制器配置和更新回调。寿命、粒子数量、随机数消费顺序和特效绘制顺序保持原规则。

## 两个性能假设

高清纹理增加显存和采样开销，但不能单独解释持续卡顿。田野路草地、路面已在浏览器中确认实际为 1024×1024，部分材质为 2048×2048；幽浮地图的 `DI-1.tga` 为 1024×1024，`beijingshu.TGA` 为 2048×1024。高清配置下达到了上表帧率。原始分辨率资产的对照仍出现掉帧，不能把切回原始纹理当作充分修复。

浏览器移动场使用原 NAV 导出的 `/movement/0002.json` 或 `/movement/0005.json`。三角面碰撞和 CPU 权威模拟在房间进程内运行。下表显示当前碰撞路径仍有 tick 余量，没有为提高浏览器帧率替换碰撞语义。

开局诊断中，进入 PLAYING 后 120 秒仅创建 4 条新 GPU 渲染管线，测得同步创建耗时低于计时精度，没有新着色器模块或纹理创建。期间的图像上传主要来自名牌生命值更新。CPU 采样的持续热点集中在粒子更新、特效绘制和场景网格评估。

## 验证与证据

服务端及前端构建完成，CDP 采样确认地图、10 名参与者、9 CPU、真人托管、页面可见、分辨率和渲染配置稳定。帧率采样未同时开启 CPU 采样器或 Chrome trace。判定采用平均 FPS ≥59、P95 ≤18.5 ms、P99 ≤25 ms、超过 33.5 ms 的帧不超过 0.5%。记录期间未出现 JavaScript 错误或 WebGPU 无效渲染命令；移除服务端探针后的幽浮地图采样平均 59.67 FPS、P99 17.0 ms、最大 50.2 ms。

## 限制

结果覆盖上述设备、两张地图和每轮 120 秒，不保证不同硬件或同时运行其他 3D 游戏时的帧率。幽浮地图仍记录到偶发长帧，表中保留了最大值。战斗过程由实时 CPU 决策驱动，各轮场景并非完全相同。用户确认同时运行另一款 3D 游戏的采样段未作为优化结论的依据。

域名代理会缓存固定路径资产。资源对照采用临时 CDP 请求参数绕过代理旧缓存，并核对实际纹理尺寸；仅禁用浏览器缓存不足以确认资产版本。
