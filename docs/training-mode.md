# 训练模式

模式与地图选择页的第六个签页为“训练模式”，支持一个玩家单独开始，也可以添加、移除和配置机器人。训练沿用混战的个人战、碰撞、射击、掉落和 AI 规则。训练地图默认人数下限为 1，建房时可提高下限，房间容量沿用地图配置。

## 本地房间

`apps/web/src/training/worker.ts` 在浏览器 Worker 中创建独立 `World`，以 50 毫秒步长推进。建房、编辑、准备、机器人管理、托管、输入、物品操作和再战通过 `TrainingSession` 在页面与 Worker 之间传递。快照和事件复用现有战斗、等待房间、HUD 和结算画面。

训练房间没有服务端房间登记，不出现在联机房间目录中，也没有供其他玩家加入的入口。添加和配置机器人不发送房间 API 或 HTTP 请求。联机模式继续使用各自的服务端房间进程。

玩家使用所选战车和初始宠物的基础属性。训练库存从空库存开始，基础炮弹按原规则补充；拾取、使用和丢弃只更新当前训练库存。训练结束展示本局战绩，不写入账户物品、成长、奖励、战绩历史或退出处罚。

## 邀请状态

进入和退出训练时，通过 `TrainingPresence` 仅同步账户是否正在训练，不上传房间、地图、机器人或战斗状态。服务端从大厅成员与房间邀请接收列表中排除该账户的全部连接，即使训练房间中只有玩家本人，也不能被邀请。连接断开时清除该连接的训练状态；重连认证后先恢复训练状态，再公开账户上下文。

训练等待房间隐藏邀请按钮，发送邀请入口拒绝训练请求。页面进入房间时清空已有邀请，训练期间忽略新邀请，并禁止通过已有邀请跳转到联机房间。退出状态同步失败时关闭连接，服务端按断线流程清除状态。

训练期间不显示房间聊天输入、消息列表或移动端聊天按钮，等待房间隐藏玩家与好友侧栏。退出训练后，联机房间恢复聊天和侧栏。

模式选择的六个签页统一按可用宽度排列，并为关闭按钮保留空间；桌面窗口宽度为 754，移动端保持 720，地图和翻页栏居中。

## 模拟数据

`apps/web/training-plugin.ts` 在开发环境提供、在前端资源生成阶段输出静态数据：

| 路径 | 用途 |
| --- | --- |
| `/content/training/maps.json` | 模式签页和编辑窗口使用的轻量地图目录 |
| `/content/training/catalog.json` | Worker 使用的内容定义、规则表和场景目录；省略战车挂点动画轨迹 |
| `/content/training/maps/<四位地图编号>.json` | 选定地图的出生点、导航和碰撞数据，按地图加载 |

服务端与浏览器共用战斗实现，通过 `runtime/simulation-host` 隔离同步数据访问和房间密码操作。浏览器在导入模拟模块前加载所需数据。仅训练目录中的混战规则表将人数下限调整为 1，服务端原表保持原值。

## 图标

训练靶与箭头使用金黄、橙色、浅黄高光和深色粗描边，与现有模式图标共用配色和色块阴影。

| 阶段 | 路径 | 规格 |
| --- | --- | --- |
| 可编辑源稿 | `scripts/artwork/training-mode.svg` | 256×256 画布 |
| HD 源图 | `art/hd/ui/map-selector/mode-icons/training.png` | 1024×1024，透明 PNG，104,325 字节 |
| 压缩成品 | `art/compressed/ui/map-selector/mode-icons/training.webp` | 88×88，near80，6,824 字节 |
| 页面逻辑资源 | `/ui/map-selector/mode-icons/training.png` | 经 `sprite-images.json` 解析到大厅图集 |
| 发布图集 | `apps/web/public/assets/ui/atlases/lobby/ui-007.webp` | 区域 x=1661、y=152，88×88 |

最终尺寸依据 `game-mode-tab.css` 的 20×22 CSS 像素和 4 倍 UI 密度，保留正方形宽高比。编码使用 libwebp 1.2.4，透明度保留，RGB 最大误差为 1/255；成品比 HD 源图减少 93.5%。UI 图集使用无损 WebP 发布到 `apps/web/public/assets/ui/atlases/lobby/`，清单为 `apps/web/public/manifests/sprite-images.json`。

发布后仍为 32 张图集，总体积由 57,715,012 增至 57,727,890 字节，增加 12,878 字节。合图入口确认解码像素与 compressed 画布一致。

```bash
npm run assets:compressed -- --image ui/map-selector/mode-icons/training.png
npm run assets:sprites
```

## 限制与验证范围

训练会话保存在当前页面内存中，刷新或关闭页面后结束，不参与联机房间恢复。首次进入仍需取得静态资源，登录与社交连接沿用现有流程。

2026-10-15 完成集中代码走查，并按用户要求使用实际 Chromium 浏览器验收。前端使用独立 Vite 缓存，服务端使用独立端口和临时账户数据库；两个隔离浏览器上下文分别登录训练玩家与联机玩家。未运行单元测试、构建或类型检查。

| 项目 | 实测结果 |
| --- | --- |
| 人数下限 | 地图 14 设为 2 人时，单人准备后保持 `WAITING`；下限为 1 时可单人开局 |
| 房名 | 自定义房名“混战模式练习”在创建和编辑时保持不变 |
| 本地战斗 | 地图 14 单人局、地图 7 的 1 人加 3 CPU 局均完成 60 秒对局，并通过“继续”返回原训练房间 |
| 移动、射击与边界碰撞 | 持续前进时坐标变化，到边界后稳定在 x=1101.68、z=-979.71；开火使弹匣从 6 减至 1 |
| 机器人管理 | 页面新增 3 个机器人，移除 P2 后剩余 P1、P3、P4；通过页面现有 Battle 接口给 P3 配置槽 2 的 2002 弹药 ×5，快照返回相同配给 |
| 服务端通信 | 训练账号的网络记录中无 `CreateRoom`、`Cpu`、`EditRoom`、`KickRoomPlayer`、`Ready`、`Input`、`Action` 或 `Rematch` 请求；静态资源加载及社交连接沿用既有流程 |
| 单人邀请隔离 | 训练等待房间隐藏邀请按钮；另一账号在训练玩家单独等待和战斗期间各发送一次邀请，均收到 `INVITE_EMPTY`，训练页面没有收到邀请 |
| 房间目录 | 联机账号查询 `ListRooms` 时不包含训练房间，`LobbyPlayers` 不包含训练账号 |
| 服务端断开 | CPU 对局中关闭测试服务端后，训练计时、AI 移动、交火、击毁与复活继续，随后完成结算 |

本地原始网络记录、逐帧状态采样和截图位于 `recovery/output/training-mode/`。主要记录为 `browser-evidence-combat.json`、`cpu-completed.json`、`cpu-configured.json` 和 `online-comparison.png`。

当前容器的 Chromium 软件 WebGPU 运行中，战斗 HUD 可见，三维场景为空；普通联机混战对照也复现。三维画面验收未通过，根因尚未定位，不能据此宣称完整画面验收通过。物品拾取、使用、丢弃，旧邀请接受拦截，以及退出训练后的邀请恢复未完成浏览器实测。六签页间距已为关闭按钮留出空间，最终布局仍需在可正常显示的浏览器复核。
