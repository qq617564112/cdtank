# MV3 动画对象缩减

战车、城堡、Hook 场景物件及大厅宠物的 MV3 动作使用紧凑时间轴和直接权重插值。手机、平板、电脑战斗和大厅三维预览共用此实现。

## 加载与采样

`convert_mv3.py` 将首帧作为基础几何体，其余帧作为形变目标，导出的线性权重在每个时间点只有一个目标为 1，首帧全部为 0。MV3 加载器在 Babylon 解析动画之前提取时间轴并移除通用动画描述，避免创建逐目标的 `Animation`、关键帧对象及 `AnimationGroup`。

时间轴存入独立的 `Float64Array`，数值沿用 Babylon 的 float32 源秒数乘以 `targetFps`，不额外降低时间精度。同一模型内相同时间轴复用同一数组；同一场景内相同发布 URL、帧率和所需挂点的实例共用时间轴数据，场景销毁时移除缓存。各网格保留独立的形变权重与上次采样位置，通过 glTF 节点编号绑定，支持同一模型中的重复网格名称。

采样通过原有二分查找定位相邻帧。纹理形变直接写入实例自有的两项权重和目标索引；每次先清零缓冲，再写入当前相邻姿态，不修改共享目标。顶点属性路径更新最多两个独立目标，清零跳转前已离开的目标。起始基础帧、末帧、动作重播及时钟回退沿用相同的线性权重关系；纹理形变保持最多两个影响目标的固定着色器。战车与城堡继续使用各自的原生动作时钟、事件、挂点及完整入场准备流程。

同一源网格的全部图元、全部目标均只有全零 POSITION／NORMAL 增量时，在 Babylon 创建目标前移除该网格的形变和对应权重通道。导出 accessor 的三维 min／max 均为零作为判据，保留基础几何体、材质、动作时长和挂点；任一图元存在变化即保留整组。日志范围内四个城堡动作因此不再建立六个形变管理器、78个源目标及六个采样器；原动作仍按时钟播放。数值及全目录核算见[MV3 全零形变网格](scene-animation-memory.md#mv3-全零形变网格)。

## 静态核算

数据来源为用户提供的 `ios-game-monitor-20261014-234435.jsonl` 中 120 个已完成 GLB 响应，以及当前发布目录中路径、文件尺寸对应的 GLB。每个 URL 按一个实例计算，不计相同车型重复实例及 Babylon 临时加载副本。

其中 84 个战车模型和田野路 10 个城堡动作经过紧凑加载器；其余 26 个普通模型继续走原有路径。已核对这 120 个文件中的动画权重均符合原导出器的单目标帧规则。另对怀旧／HD 战车及怀旧场景物件中的 1587 个 MV3 文件完成数据核对：2801 个通道、1,490,504 个权重值均符合单目标帧规则，未发现非线性通道、交错时间轴、缺少首帧零时间或帧数／目标数关系不符。

| --- | ---: | ---: |
| 逐目标关键帧条目 | 118,358 | 0 |
| 逐目标 `Animation` | 4,559 | 0 |
| `AnimationGroup` | 208 | 0 |
| 采样器的逐目标包装对象 | 4,559 | 0 |

94 个模型共享时间轴的数值存储合计 14,328 字节，约 14 KiB，不包含数组头、网格绑定和缓存目录。以 `tanks/152/09M.glb` 为例，13 个网格原有 15,470 个关键帧条目、442 条目标轨道和 455 个采样区间数组，时间轴改为共享一个 35 项、280 字节的 TypedArray。

按以上表内五类被移除的对象／数组逐项计算，共省去 132,451 项；该数值是模型结构的静态核算，不是手机 GC 计数的实测差值。全部 120 个 GLB 原有 126,486 个关键帧条目，26 个普通模型中的 8,128 个条目继续保留。

## 形变权重绑定

纹理形变实例复用最多两个 Float32 权重及两个目标索引，采样后直接绑定；起始基础帧没有活动目标，关键帧时只有一个，插值时最多两个。权重顺序、Float32 舍入和共享姿态纹理沿用原值。单目标模型使用单项缓冲；不支持纹理形变的设备沿用 Babylon 顶点属性路径。

Babylon.js 9.29.0 的通用形变管理器在权重变化后的同步过程中，将索引数组扩容到全部目标数，再裁切到活动目标数。目标数大于 2 的 MV3 网格即使始终只有两个活动目标，每次同步也会创建两个索引 TypedArray；活动目标数变化时还会重新分配权重数组。当前纹理形变路径直接读取复用的权重／索引和活动数量，不扫描全部目标，也不执行这组扩容和裁切。

前述 94 个模型、每文件一个实例共有 208 个形变管理器，其中 206 个的目标数大于 2，另外两个只有一个目标。绑定所用权重和索引共 416 个常驻 TypedArray，数值存储为 3,312 字节；每个实例拥有自己的缓冲，随实例释放。

| 目标数大于 2 的活跃网格 | 通用同步 | 当前纹理形变绑定 |
| --- | ---: | ---: |
| 每次权重变化后同步创建的索引 TypedArray | 2 个 | 0 个 |
| 每秒 60 次权重变化并绑定时的索引 TypedArray 创建 | 120 次 | 0 次 |
| 活动数量在 0／1／2 之间变化时重新创建权重数组 | 有 | 无 |

这组统计只涵盖形变绑定缓冲，不包含引擎 uniform 上传内部的数据复制；208 个管理器包括尚未激活的动作模型，不能视为每帧全部参与渲染。

## 形变目标对象共享

纹理形变实例直接读取模板的只读目标，不再逐个克隆 `MorphTarget` 或注册目标权重／数据变化观察器。每个网格仍有自己的形变管理器、两项权重、两项目标索引、活动数量和采样位置；各玩家、动作与场景物件的时钟相互独立。模板目标不接收实例权重写入，避免同车型玩家互相影响。实例释放时解除共享纹理引用，再沿用原容器借用计数；最后一个实例离开后释放模板。

`AssetContainer.instantiateModelsToScene` 的目标编号映射通过 `numTargets` 和 `getTarget` 读取源目标；MV3 通用动画组已在解析前移除，没有动画组向共享目标写权重。材质、描边、阴影和纹理形变几何路径继续使用原支持标记及实例权重绑定。不支持纹理形变的设备保留逐目标克隆、目标更新及独立几何体。

按原日志完成的文件清单与当前实际 MV3 加载入口相交，排除不再加载的两份城堡 `c1` 后，静态范围为 84 个战车动作、8 个城堡动作，共 92 个文件、186 个形变管理器。以下仍按每文件一个实例计算，全部使用纹理形变；模板自身的目标继续保留。

| 实例结构 | 逐目标克隆 | 直接读取模板目标 |
| --- | ---: | ---: |
| MorphTarget | 4,141 | 0 |
| 目标 animations 数组 | 4,141 | 0 |
| Observable | 8,282 | 0 |
| Observable 的 EventState | 8,282 | 0 |
| Observable 的观察器数组 | 8,282 | 0 |
| 已注册 Observer | 8,282 | 0 |
| 上述对象／数组合计 | 41,410 | 0 |

按本地 Babylon.js 9.29.0 源码，每个克隆目标创建一个目标对象、一个 animations 数组、两个 Observable、两个 EventState、两个观察器数组和两个 Observer。表中合计不包含函数与弱引用；两次注册还各创建一个业务回调和一个移除回调，共少建 16,564 个函数。在支持 WeakRef 的环境中，另少建 8,282 个 WeakRef。按此前包含两份未使用 `c1` 的 94 文件范围计算，对应目标为 4,559 个、表内对象／数组为 45,590 个；该范围只用于与前文历史统计对照。

这项减少的是实例常驻对象与加载时创建工作，原克隆的顶点数组已经共享，不能再计为顶点或 GPU 纹理节省。相同文件的额外实例各自省去对应的目标克隆结构，保留自己的紧凑权重。数字来自当前 GLB 结构、实际加载入口和库构造函数，不是 GC 对象数或进程内存的实测差值。

## 限制

本次完成源码走查及发布数据静态核算，未运行测试、构建、类型检查、浏览器验收或新的手机内存采样。MV3 模板共享、CVD 紧凑发布和场景资源回收的后续实现见[战斗场景数据与模型内存](scene-animation-memory.md)。其它模型的通用动画及普通纹理继续保留各自的数据表示。对象条目减少量不能直接换算为进程内存、帧率或崩溃改善，仍需新的同机同图记录确认。
