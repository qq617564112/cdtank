# 资源加载与浏览器缓存

UI 分为大厅、手机战斗、电脑战斗三套独立资源。登录入口只准备大厅包、字体、界面布局和内容定义；战斗及结算 URL 入口根据设备只准备对应战斗包。地图、模型与声音在实际使用时载入。电脑登录页“加载资源包”提供一次性预下载，移动端隐藏此入口；入场流程另行准备本局模型及动态道具。各入口共用资源目录与浏览器缓存。

## 资源目录

Vite 的 `manifests/image-assets.json` 登记图片及全部已发布静态资源的 URL、字节数和修改时间，并附带 UI 精灵图映射。开发环境按当前文件生成目录，生产环境在构建时生成；发布图片或清单后需要同步发布新的前端构建。

| 清单 | 职责 |
| --- | --- |
| `manifests/image-assets.json` | public、内容定义及构建资源的目录与缓存版本 |
| `manifests/sprite-images.json` | 三套 UI 的图集区域、独立图片、预加载文件集合及旧资源路径别名 |
| `manifests/battle-artwork.json` | 怀旧／HD 战斗模型与图片的 URL 映射 |

public 的 `assets/`、`data/`、`manifests/` 分类见[目录规则](public-assets.md)。精灵图已经包含的图片及旧路径不再作为单图进入预加载目录。界面仍用原资源路径查询清单，相同图集共用一个下载地址和解码图像。

## 正常启动与按需载入

启动时先获取目录并登记全部文件版本，再下载、解码当前 UI 包的 `preload` 文件。每套包都拥有所需字体、光标、公共弹窗和聊天图片的副本；大厅与两端战斗的图集互不混装。模型皮肤、地图和场景贴图在相应页面或战斗使用时载入。加载进度区分下载、解码与内容／界面准备阶段。

缓存版本登记后，UI 预加载器只保留三套包 `preload` 的图片记录，其余目录记录随准备过程结束释放。当前 public 的 4,974 条图片记录缩为 103 条，三套包分别使用 40、28、35 条；切页仍按对应包选择，按需图片仍通过完整版本目录读取。此项只缩小常驻元数据，不改变实际图片和完整资源包的下载范围。

大厅包覆盖登录、频道、大厅、等待房间、仓库、商城和设置。手机战斗包包含本地宠物头像与触屏控件，电脑战斗包包含原版 HUD 与远端头像；两套战斗包都包含计分板、聊天、退出确认、结算、飘字及小地图所需图片。手机不加载电脑包，也不预加载电脑小地图车型标记。五张 4K 加载背景只由加载页准备当次选中的一张，18 张技能状态图在 HUD 显示对应状态时载入。

直接打开 `/rooms/<房间号>/battle` 或 `/rooms/<房间号>/results` 时，图片映射在加载画面出现前选择对应战斗包，再恢复账号和房间，随后按当前对局载入地图、模型与声音。启动、会话恢复和对局资源准备共用同一个加载页，背景与文字动画持续显示，进度连续推进；启动阶段不加载大厅包。快速开局及保存的房间恢复同样衔接启动进度。房间恢复失败、房间已处于等待阶段或用户返回登录页时，先准备大厅包再显示对应界面。

切换 UI 包时先从 DOM 卸载旧界面，再按旧包的发布文件地址释放解码图像、裁切缓存、Blob URL 和进行中的下载／解码，清除 CSS 背景与布局就绪状态。大厅控制器继续保存房间列表与建房选择。图片逻辑路径保持不变，切换后通过新包的 `images` 映射解析到新的图集区域。光标和页图标随目标包重新绑定。战斗资源就绪确认会等待对应 UI 包及布局完成；加载页卸载后释放当前已准备的大背景。

返回大厅、等待房间或登录页时，显示界面加载页，从 IndexedDB 读取大厅包并重新解码、绑定背景和准备布局，完成后挂载页面；失败可重试。该流程同时覆盖手机和电脑，磁盘缓存与资源版本保留，版本匹配且缓存未被浏览器清理时无需重复下载。富文本聊天若实际引用当前包外的图片，单独按需读取其发布文件；这类解码和 Blob 也在下次切换时释放。

模型解码通过全局队列，手机和平板最多同时处理 2 个模型，电脑最多 4 个。队列覆盖 GLB 读取、外部图片准备和 Babylon 容器解析，场景物件、战车各部件与动作、饰品及动态道具共用上限；动态道具的模型预加载也占用同一队列名额。等待中的任务不提前读取模型字节；实例所属场景已销毁时跳过加载，解析期间销毁则释放返回的容器，成功和失败都会让出名额。战车入场只准备待机与移动动作，瞬时动作在首次使用时载入。

正常实例加载由 Babylon 解析 GLB，通过异步 URL 处理准备外部图片 Blob，不额外解析一次 GLB JSON 来枚举图片。动态道具预加载只读取 GLB 图片清单并保存完整文件，不创建场景几何体。模型、陷阱、伪装与掉落物贴图由渲染器解码上传，预加载不额外保留 HTML 解码图像。MV3 战车、城堡、Hook 与大厅宠物按发布 URL、帧率和所需挂点共用解析模板、基础几何体、形变顶点数组和 GPU 形变纹理；各角色保留自己的网格、材质与动画权重，最后一个使用者释放模板。

车型定义只包含挂点索引，帧时间与完整矩阵按车型和动作分别发布二进制。大厅预览只读取待机动作，战斗入场准备待机与移动动作，开火、受击和死亡动作按需载入；同车型、同动作共用轨道视图，回到待机或移动时释放瞬时动作实例及其轨道借用，最后一个使用者释放后解除页面引用，IndexedDB 保留完整文件。其它车型的帧数据不在启动时加载。开发响应、生产输出与资源目录使用同一转换，格式代码修改时间也参与缓存版本。数据格式及静态核算见[车型挂点按动作加载](scene-animation-memory.md#车型挂点按动作加载)。

GLB 根部挂点帧在解析回调中按实际用途提取后解除引用；战车仅 M/U 保留四种饰品轨道，连续 Float32 数据由模板共享。节点和材质元数据保留。大厅宠物从同一次解析读取动作时长，直接使用紧凑采样器，省去重复 JSON 解析及通用动画轨道。原发布 GLB 完整保留，文件下载量不变。

战车和大厅战车预览先准备所选装甲贴图。动作模型仅为没有替换图或履带帧的网格准备实际材质引用的默认图，不预取整套默认目录；部分死亡动作中的跨部件贴图按原引用保留。默认图别名按同一文件共享请求和 Texture，失败后可重试；角色释放后清除目录并释放完成或晚到的图片。克隆等待图片时先挂入禁用的动作根节点，准备完成后按原动作规则显示。跳过材质的 MV3 模板只保存源材质参数，因此不同迷彩选择共用原几何体和形变数据。履带帧、所选贴图及各角色材质状态沿用原资源和归属。

战斗饰品与大厅装备预览在物品定义有显式贴图时，GLB 导入省去随后被替换的基色图，只准备原来实际显示的所选贴图。几何体与 PBR 材质继续完整载入，原 MASK 透明度设置、采样和挂点保持原值；没有显式贴图的路径继续由 GLB 准备默认图片。各实例沿用原容器、材质和贴图释放方式，详见[饰品模板贴图](scene-animation-memory.md#饰品模板贴图)。

掉落物、陷阱和伪装也在 GLB 解析时省去将被显式图片替换的默认基色图。掉落物按原模型／A/B 变体选择图片，陷阱与伪装在定义没有显式图时完整载入默认图；原材质、节点动画、采样和快照释放规则保持原值。动态资源预取仍可将模型默认图片写入磁盘缓存，不提前解码，详见[掉落物、陷阱与伪装模板贴图](scene-animation-memory.md#掉落物陷阱与伪装模板贴图)。

二进制读取仅共享进行中的 Promise，读取结束后移除页面缓存引用；后续实例从 IndexedDB 读取完整文件。Babylon 几何体和动画仍可能引用输入字节，这部分随模型容器的生命周期保留。声音解码独占从 Blob 读取的字节，直接交给 `decodeAudioData`，页面不额外复制或长期缓存 WAV 原始字节。背景音乐直接以完整 Blob 创建本地 URL，不先转为 ArrayBuffer 再构造 Blob。

战斗 loading 会等待开火、击毁、战车效果、战斗提示、技能与场景声音下载并解码为 `AudioBuffer`，完成后才发送资源就绪确认。二维效果音频按特效节点及物品第二技能第一效果选择；空间音频按技能定义及可破坏物、城堡、拾取的实际声音引用选择，两者按 URL 共享解码结果。播放事件直接创建缓冲音源，不再为每次技能或场景音效创建媒体元素并重新解码。当前地图启用的环境循环同样在 loading 中解码，离开或切换地图时停止音源并释放该地图的解码缓存。音频失败由战斗加载页显示，可重新载入；大厅入口不下载这些战斗声音。

背景音乐使用同一个媒体元素切换曲目。战场和两首可能的结算曲在入场时完整下载到 IndexedDB，不为尚未播放的曲目创建 Blob URL。选择曲目时读取本地完整 Blob，确认请求仍有效后才创建 MIME 类型为 `audio/mpeg` 的音源；停止或切歌先清空媒体元素的 src 并调用 load，再撤销旧 URL。稳定播放只持有当前曲目，停止和销毁后不保留音乐 URL；晚到的旧请求不能创建音源。播放许可拒绝后仍保留当前曲目，在实际鼠标、触摸或键盘操作中重试。同曲目选择、循环、音量和结算播放规则保持原值。切歌需要一次 IndexedDB 读取，下载副本继续复用，见[背景音乐源生命周期](scene-animation-memory.md#背景音乐源生命周期)。

音频交互监听位于捕获阶段，覆盖 `pointerdown`、`pointerup`、`touchend`、`click` 和 `keydown`，移动按钮和摇杆阻止冒泡也能触发。开火、战斗提示及效果声音的上下文在控制器创建时就绪，资源尚未加载时也接受手势解锁，玩家在进场前操作即可请求播放许可。资源准备完成后再次尝试恢复上下文。单次过期音效仍不补播，挂起上下文中的循环缓冲音源在解锁后继续；模块销毁时移除全部监听。

开启 FPS 显示后，第三行记录背景音乐状态、曲目 ID、播放秒数、媒体音量、静音标记与错误。`awaiting-interaction` 表示浏览器拒绝自动播放，`playing` 且秒数增加表示媒体正在推进；媒体错误码 3 表示解码失败，4 表示音源不受支持。统计每秒读取一次，不增加音频上下文或解码整首音乐。

战斗入场准备地图、场景声音、玩家战车、HUD 和小地图，还会在发送资源就绪确认前准备快照已有陷阱、存活玩家当前伪装及本局掉落物的模型与贴图。后续陷阱和伪装由对应呈现器按快照首次出现时异步载入；伪装替身就绪后才隐藏战车，失败后保留战车并在一秒后重试。陷阱恢复成功或消失后清除当前错误提示。掉落物资源清单来自服务端快照的 `groundItemResources`，完整覆盖本局可能出现的资源；不需要等待物品实际掉落后才开始下载。

移动端战斗资源按已保存的怀旧／HD 设置解析到 original 或 mobile-hd 目录，包括已有配置中的 HD 地址及动态道具。怀旧贴图使用原导出尺寸与 RGBA 像素，以无损 WebP 发布；移动端 HD 从 HD 源图生成独立压缩成品，尺寸与怀旧版一致。UI 使用现有素材，移动端两档画质的小地图底图均为 512×512，商城和我的家预览使用 mobile-hd。初始登录加载不预下载场景材质。

## 场景动画与资源回收

CVD/POL 按模型发布小型元数据及连续 Float32 二进制，先读取库的 `.models.json` 索引，再读取本图或本局特效实际引用的模型。同模型实例共用几何体、索引和动画帧纹理，各实例保留独立采样状态。退出和换图释放地图 JSON 与模型解析缓存；停止战斗同时释放特效纹理、模型及声音缓存。坦克与场景绘制复用元数据和矩阵对象。发布格式、生命周期及静态效果见[战斗场景数据与模型内存](scene-animation-memory.md)。

场景和特效范围查询读取 `data/maps/<地图ID>/placements.json`，每份包含该地图的完整放置数据，退出和换图时随地图 JSON 清理。特效读取 `data/effects/library.runtime.json` 与 `links.runtime.json`，包含全部 `online` 节点、显式游戏引用及递归子节点的完整控制和绑定，覆盖后续玩家、技能及道具；省去未被游戏引用的定义、十六进制记录及恢复证据。发布器从全部地图（含停用效果）、Hook 和战车动作绑定补齐显式引用，保留原编号与顺序，不按开局快照拆配置。library 文件将重复短向量及运动、轨道、出生等只读配置发布为共享池，加载时先还原池内向量，再将对象写回原控制字段；各池记录只解码一次。各实例的时钟、运动状态、端点、历史与 UV 缓冲保持独立，数值不量化。还原后不保留池外层列表和路径元数据，两份配置只由当前特效运行时持有，停止战斗后解除引用，IndexedDB 的完整文件保留。public 整理流程从完整源 JSON 生成这些文件，资源目录自动登记，前端代码与数据需一同发布。

客户端运动表 `data/maps/<地图ID>/movement.json` 仅在转换期间持有完整解析结果，不登记到页面 JSON 常驻目录。完成后保留 NAV source、解码字节及各 surface 的运行时 Set，原 surface 数组可回收；重新入场从 IndexedDB 完整文件重新解析。相同源对象的导航副本共享只读字节，各自持有动态占用，解码字节由活动网格强持有，目录以弱引用复用。

城堡与 Hook 读取对应源路径的 `.tracks.json` 和 `.tracks.bin`，以共享 Float32 视图替代逐帧对象与矩阵数组。城堡模型定义按既有地图映射读取，同模型放置共享动作数据；各实例时钟、喷口矩阵独立，释放时解除数据引用。城堡仅准备实际使用的 `n1`、`n2`、`c2`、`c3`，源 `c1` 未显示，不再载入。完整源文件保留用于发布生成及服务端碰撞导出。

## 登录页全资源预下载

点击“加载资源包”后，确认框根据目录总字节数显示预计 GB 体积。确认后进入独立加载页，最多并行下载 8 个资源，按文件完成数量更新进度。图片只保存完整文件，不把全部地图与模型贴图解码到内存；非图片也保存完整内容。

成功后返回登录页；失败时显示资源与原因，可重试或返回。返回会中止当前加载，已保存的完整文件留在缓存中；重试复用版本匹配的文件。账号、密码输入和已保存身份由原登录流程保留。

该操作仅对电脑端开放，预下载当前站点已发布的资源，包括怀旧与 HD 两套战斗素材；它与开发环境的 `npm run assets:install`、素材生成和服务器资源部署分别独立。

## 缓存与失败恢复

| 缓存 | 内容与复用范围 |
| --- | --- |
| IndexedDB `cdtank-image-assets` / `images` | 图片完整 Blob；UI 图集按最终发布地址去重 |
| IndexedDB `cdtank-static-resources` / `resources` | JSON、GLB、音频及其它静态文件完整 Blob |
| 页面内存 | 进行中的下载和二进制读取、已解析 JSON、活动模型／动画、图片 Blob／解码图像、本地音乐 URL 与解码音频 |

目录中的修改时间作为缓存版本；未变化的文件直接读取本地保存内容，版本变化后重新下载。源码内图片使用构建后的 URL 标识版本。失败的 JSON、二进制、模型准备及音频解码请求移出相应 Promise 缓存，后续重试可以重新载入。非图片下载及全资源预下载中的单文件操作使用 30 秒超时，错误由当前加载页面显示。

刷新保留 IndexedDB，页面退出时释放内存图片和本地资源 URL。账户身份、频道及房间恢复另由[会话导航](navigation.md)管理；清理整个站点数据也会移除本地身份和设置，应使用已注册账号重新登录。

预下载不提供离线联机能力，账户与房间仍需要服务端连接。缓存受浏览器站点存储许可和容量限制。生产更新需同时发布实际文件与新目录；代理缓存旧固定路径资源时，还需按既有部署方式更新代理缓存。当前加载改动尚未进行全资源下载或整局浏览器验收；音频交互改动尚未在 iPhone／Android 真机验听。
