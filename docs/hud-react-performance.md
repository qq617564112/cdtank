# 战斗头像与 React HUD 更新

电脑和手机战斗头像直接显示现有 WebP 图集区域。表情状态沿用 `PortraitState`，受击、攻击、庆祝、死亡与复活的时序相同；头像位置、大小和手机视口偏移沿用现有参数。

SVG 头像通过 `SvgImageArtwork` 读取图集，内层 SVG 裁剪原图区域，外层处理尺寸和宽高比。同一图集内切换表情只改变区域坐标；跨图集切换复用另一张已准备的图集。该路径省去逐表情 Canvas 裁剪、PNG 编码、data URL 缓存及独立 PNG 解码。电脑本地头像原本已直接使用图集，继续沿用。素材文件与三套 UI 包均无需重新生成。

## 更新范围

| 触发条件 | 之前 | 当前 |
| --- | --- | --- |
| 单个玩家表情变化 | 桌面 HUD 顶层重新渲染，遍历所有玩家和五种模式布局 | 对应玩家区更新；其余槽位保留原快照引用 |
| 本地血量变化 | 桌面与手机 HUD 根组件更新 | 本地血量组件及对应玩家区更新 |
| 手机装填进度变化 | HUD 根组件连带头像、摇杆、比分等子树更新 | 准星与道具冷却叶节点订阅装填进度，根组件不订阅 |
| 选中弹药的装填进度变化 | 八个道具按钮及其图案重新渲染 | 冷却叶节点直接更新原遮罩及剩余秒数，按钮保留原绑定 |
| 服务器时间戳变化，弹匣数值不变 | 弹匣组件随战斗快照更新 | 订阅可见性、容量及余弹数，数值未变时跳过渲染 |
| 桌面模式布局 | 五套模式布局常驻，共享整体 HUD 更新 | 只挂载当前模式的计分布局 |
| 桌面布局节点遍历 | 每次渲染过滤全部控件以查找子节点 | 按源布局缓存父子节点表，递归直接读取子节点 |
| 战斗信息面板透明度变化 | 同时重建静态纸纹、边框与 SVG 滤镜元素 | 仅更新面板，静态图案组件复用 |

`BattleHud.getLayoutSnapshot` 保持不含玩家区和本地生命值的布局投影引用稳定。各玩家区读取原有 `slots[index]` 对象，本地血量单独订阅；`clear()`、地图数据准备、模式与局数变化继续发布对应状态。原有订阅清理函数负责组件卸载，不增加定时器。连续准星和道具冷却只写原有裁剪与文字元素，订阅随组件卸载清理。

道具按钮比较覆盖物品、数量、选中状态、装填和效果剩余时间、禁用状态及操作回调。按钮触屏、键盘与点击行为沿用原实现。手机 HUD 根组件只读取操作许可、聊天显示和编辑状态、战斗资源是否加载完成，服务器时间与聊天内容变化不再单独触发根组件更新。

## 性能依据与验证范围

修改前在线房间 R1 的 12 人团队对战有两段未启动 CPU Profiler 的基线：20 秒平均 32.29 FPS、15 秒平均 31.19 FPS，主线程忙碌比例分别为 80.66% 和 75.60%。另两段 CPU 采样中，React 渲染与提交分别占窗口时间 19.70% 和 17.71%，包含 `HudLayout`、`HudItemSourceView`、`ImageArtwork` 等路径。这些比例属于整个 React 调用路径，不能全部归因于头像。

已完成源码走查和用户要求的电脑浏览器实战采样，未运行测试、构建或类型检查，手机浏览器尚未验收。表中描述订阅与组件结构变化；运行时结果按下述采样窗口记录，未测量头像内存下降量。

道具栏父组件读取稳定的物品绑定投影，连续时间由冷却叶节点读取最新快照。服务器时间、装填算法和特效有效期保持原规则。HUD 模型本身仍由战斗渲染循环更新。2026-10-16 的 12 人实战采样见[团队战斗性能](team12-performance.md)：第五局 React 路径占采样窗口约 2.01%，第四局约 8.85%，不同战况下的记录不是严格 A/B。
