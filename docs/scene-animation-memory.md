# 战斗场景数据与模型内存

手机、平板和电脑共用场景数据回收、紧凑 CVD/POL 数据、同模型资源复用、本局特效准备及逐帧对象复用。发布数据的统计日期为 2026-10-15。

## 运行行为

地图退出、切换或加载重置时，先销毁场景实例，再移除地图 JSON 和模型库的解析缓存。静态文件继续留在 IndexedDB，重新入场可从本地磁盘读取。全局资源释放也清理解析后的 JSON。

每个模型库独立持有索引和模型缓存。释放时将整个库从场景目录移除，仍在读取的旧请求只持有已移除的库；请求完成后不会向下一张地图的缓存写回模型，旧请求失败也不会移除新一轮请求的缓存。

CVD/POL 使用小型模型索引，每个模型分别发布元数据 JSON 与二进制。顶点以连续 Float32 XYZ/UV 保存，颜色另存连续 Float32；mode-3 变换轨道的采样时间、XYZ 和四元数也连续保存，数值保留原值。节点层级、材质和索引沿用原数据。运行时按实际引用读取模型，使用 TypedArray 视图，不展开逐顶点或逐关键帧小数组。怀旧与 HD 共用原有几何体，贴图继续按各自画质清单解析。

同一场景中的重复 CVD 模型共用基础几何体、索引及所需 GPU 动画帧纹理，各实例保留自己的采样时间、变换及材质。XYZ/UV 各帧逐字节相同的节点只保存首帧，并从几何体属性按原权重插值；真正改变顶点的节点保留完整帧纹理。最后一个实例释放共享几何体和帧纹理，地图清理同时移除模型数据缓存。

MV3 战车、城堡、Hook 及大厅宠物按发布 URL、帧率和所需挂点共享一次 GLB 解析、基础几何体、GPU 形变纹理及时间轴。纹理形变只保留一份打包姿态缓冲，CPU 读取时按需展开，不常驻逐目标位置和法线副本；各实例拥有自己的网格、材质和形变权重。最后一个使用者释放模板。不支持纹理形变的渲染设备保留原目标数组及各实例的独立几何体，避免不同动作的顶点属性相互影响。每个不同模型仍有一个未入场的模板及各实例的控制对象，单实例模型不会省去这些控制对象。

战斗准备按本局车型链接、玩家技能和当前地图收集特效树，递归准备所需纹理、模型和声音。常见烟尘、命中效果、所选宠物的死亡效果、城堡及 Crush 效果保留；全部已登记道具与弹药技能也保留，覆盖后续掉落及使用。重开一局时重新收集玩家选择并补齐新增资源。停止战斗释放效果模型缓存、纹理、空闲绘制器和该模块持有的音频缓冲，公共定义仍复用。

陷阱模型和伪装模型的启动预加载只覆盖当前快照中已有的陷阱及存活玩家的当前伪装；后续出现的对象由各自呈现器按快照异步加载并等待就绪。掉落物仍按服务端提供的本局资源目录预取，保证后续掉落可以即时建立。模型、贴图和动画保持原值。伪装替身就绪后才隐藏战车，失败时释放实例并保留战车，后续同步在失败一秒后重试；同身份正在加载时不重复请求。陷阱加载成功或消失后清除当前错误，旧快照及旧资源周期的异步结果不能覆盖当前状态。

原全目录范围包含九种陷阱定义和两种伪装定义，按资源路径去重后为八个模型、八张显式贴图。没有陷阱或伪装的开局快照不再准备这组资源；其当前发布文件合计为怀旧 372,274 字节（0.36 MiB）、HD 1,402,218 字节（1.34 MiB）。这些是启动预取范围的静态文件字节，不包含不变的掉落物清单，不扣除与地图或特效的重叠引用，也不是进程内存下降量；后续首次出现时仍会下载或读取这些文件。

坦克动作元数据、挂点读取器及姿态对象复用；位置更新直接写入 Vector3。CVD 绘制复用节点世界矩阵、环境颜色、材质颜色和网格列表，不在每次绘制中重建这些对象。CVD 场景网格的来源元数据在绑定时设置。

## 车型挂点按动作加载

浏览器启动读取全部 21 种车型的轻量定义，保留名称、属性、价格、皮肤、部件、动作事件、时长及挂点索引。帧时间和全部 16 个矩阵值独立发布为 `/content/tanks/<车型>.tracks/<动作>.bin`，每帧占 17 个连续 Float32 值；定义中的 `offset` 使用 Float32 元素偏移，`length` 使用帧数。服务端与恢复工具继续使用完整源定义。

大厅预览只读取所选车型的 `01` 动作。战斗入场只保留 `01` 和 `02`（待机、移动）的模型实例；`03`、`05`、`06`、`07`、`08`、`09` 在首次开火、受击或死亡时读取，切回 `01`／`02` 后释放该玩家的瞬时动作实例。同车型、同动作实例共用一个二进制及轨道视图；实例只保存自己的播放状态。最后一个使用该动作的实例释放后，目录移除对应 Promise；实例同时清除动作和待机数据引用。仍有待机预览时，已经没有战斗使用者的其它动作也可回收。失败请求解除借用，重试重新读取；进行中的旧请求不会占用新一轮动作目录。

这项调整只改变资源驻留时机，不改变动作选择、时间、挂点、形变采样或材质。首次触发瞬时动作时，原有事件仍通过同一个动作加载 Promise 后再激活动作；加载期间保留前一个动作，完成后按原时钟推进。来自本次 iOS 日志的 9 种车型包含 84 个战车动作 GLB，其中 `03`、`05`、`06`、`07`、`08`、`09` 共 42 个属于瞬时动作，入场阶段不再为每名玩家建立这些网格和节点；已经使用过的瞬时动作仍按需恢复，不能把这 42 个文件字节直接当作永久内存节省。

采样直接按偏移读取相邻帧，共用原位置与四元数插值公式，保留时间取模、比较和 Float32 运算顺序。原数组采样入口仍用于 GLB 中的饰品挂点、城堡和场景挂点。全部源数据的时间值均能精确表示为 Float32，全部 712,080 个矩阵值与 Float32 数值完全一致，没有额外量化。

## GLB 挂点引用与饰品数据

MV3 模板在解析回调中只提取动作时长和调用者需要的挂点，再解除 GLB 根部 `extras` 引用。Babylon 的节点与材质 `extras` 保留，原材质属性、模型几何体、形变帧和贴图不变。战车的主挂点和炮塔轴心从内容定义的动作数据采样，GLB 中的重复副本、左右标记等未被当前渲染路径读取的挂点不再常驻模板。

饰品只从 M/U 部件读取 `tag_iteye`、`tag_itwing`、`tag_ithat`、`tag_itside`，履带 X/Y 无需保留这些帧。所需轨道按每模型一个连续 Float32 缓冲保存，保留时间和全部 16 个原矩阵值，各轨道以视图读取；同模型实例共用数据，采样使用既有紧凑挂点公式。未请求挂点的城堡、Hook 和宠物模板仅保留动作时长；它们实际使用的场景挂点仍由原独立场景数据提供。模板目录包含所需挂点的选择，避免不同使用方借到缺少所需数据的模板。

## 大厅宠物模板贴图

## 变换与挂点采样

CVD 每个只读源动画节点持有一个 `AnimationTransformSampler`，复用位置、旋转、缩放、缩放旋转及三个矩阵，共七个数组；绘制实例持有独立输出矩阵。缩放旋转直接读取原关键帧的 5–8 字段，统一缩放的位模式在初始化时解码一次。逐帧采样不再复制整条缩放轨道，不再创建区间数组、四元数数组、矩阵数组、DataView 或 ArrayBuffer。相同采样时间直接复用结果，停止的动画和停在末帧的破损模型也适用；各实例的时钟与矩阵独立。

坦克主挂点和饰品、城堡喷口、Hook 场景挂点均写入保留的矩阵。主挂点和各饰品挂点分别保留自己的输出引用，临时采样矩阵在同步计算完成后复用；缺少主挂点时直接将原输出填零。炮塔补偿向量及世界合成的中间矩阵也复用。城堡动作元数据在动作加载时建立，逐帧仅更新数值。

地图 0012 的 Hook 物件 `obj05027/c1.glb` 使用同一 MV3 紧凑加载器。怀旧和 HD 模型均有两个线性权重通道，每通道 48 帧、47 个形变目标；每个运行实例省去原通用加载路径的 4,512 个逐目标关键帧条目和 94 条目标动画，两个通道共享一份 48 项、384 字节的 Float64 时间轴。该项独立于前述田野路数据统计。

战斗与大厅饰品各持有一个 Babylon Matrix，使用 `Matrix.FromArrayToRef` 读取挂点并原地进行 X 反射；`setPreTransformMatrix` 将数值复制进节点现有矩阵，不会让不同饰品共享可变的节点矩阵。

插值保留原有关键帧区间、严格超过持续时间才循环的条件、四元数最短路径、矩阵乘法顺序、各处 Float32 舍入点及原 180 度校正的小量。怀旧与 HD、手机与电脑均使用同一路径。

| 路径 | 原每次更新的临时分配 | 初始化后的当前路径 |
| --- | --- | --- |
| 一个 CVD 动画节点，缩放轨道有 K 个关键帧 | 至少 28 + 2K 个数组，另有一个轨道对象、一个 DataView 和一个 ArrayBuffer | 源采样器复用七个数组及一个区间对象，绘制实例持有独立矩阵；采样内不创建这些对象 |
| 一个非零坦克主挂点的采样与世界合成 | 至少 11 个数组 | 复用输入、输出及中间矩阵 |
| 一个城堡喷口或 Hook 挂点的采样 | 至少 6 个数组；Hook 另有一个乘法结果数组 | 复用采样和合成矩阵 |
| 一个饰品的节点矩阵更新，不含上游挂点采样 | 两个普通数组、一个 Babylon Matrix 及其存储 | 复用 Babylon Matrix |

以上仅统计源码中显式构造的数组和对象，未计入回调、迭代器及引擎内部开销。四元数负点积路径还会增加原表示的数组数。10 台车、每台七个有效非零主挂点、每秒更新 60 次时，主挂点一项可消除至少 `10 × 7 × 60 × 11 = 46,200` 次临时数组构造；位置和瞄准触发的额外挂点更新不在此数中。

田野路 60 个破损模型实例共有 404 个动画节点、4,304 个缩放关键帧。假设这些破损动画同时采样，每次完整更新对应原路径至少 `28 × 404 + 2 × 4,304 = 19,920` 次临时数组构造；60 次更新/秒时为 1,195,200 次。当前 35 个源采样器复用 245 个数组，404 个实例各持有一个矩阵，共计 649 个常驻数组；采样过程不再创建上述临时数组。实例与源缓存按各自生命周期释放，详见[CVD 变换采样器共享](#cvd-变换采样器共享)。这个同时采样场景是静态核算条件，实际只有可见的破损模型执行逐帧更新；临时构造次数也不等于堆中同时存活的对象数。

## 粒子与条带更新

粒子、精灵、条带、全屏覆盖层和独立精灵帧时钟共用原地帧更新，直接保存 `frame` 和 `frameRemainder`。每次更新最多推进一帧、先比较未舍入累积值、正向／反向／随机帧和边界停留规则保持原计算顺序。随机回调仅在原来需要推进随机帧时调用；精灵、条带及覆盖层复用实例回调。

追踪目标的粒子使用标量计算差值、力及归一化方向，不再为每颗粒子创建临时向量。归一化保留 `.005` 阈值及 +Y 回退；两种追踪模式的 Float32 舍入点、积分顺序、粒子寿命和发射数量沿用原值。公共向量归一化、旋转及坐标变换直接读取需要的分量，保留结果向量，去掉输入矩阵和向量的整份舍入副本。

条带复用速度、位置、角度、缩放、颜色及状态对象；无轨道运动时直接保留原轨道偏移。各段 UV 在几何体建立时分配，逐帧只写数值，滚动超过 1 才归零的条件不变。全屏覆盖层原地更新 RGBA 数组。

| 更新路径 | 原每次更新的临时分配 | 当前路径 |
| --- | --- | --- |
| 一颗粒子的动画帧推进 | 两个帧状态对象 | 直接更新粒子字段，无临时帧对象 |
| 追踪模式 1 的粒子方向 | 三个数组 | 标量计算，无临时方向数组 |
| 追踪模式 2 的粒子方向与力 | 四个数组 | 标量计算，无临时方向数组 |

以 1,000 颗存活粒子、每秒更新 60 次为计算条件，仅帧推进可消除 `1,000 × 60 × 2 = 120,000` 次临时对象构造／秒；若全部为追踪模式 1 或 2，还可分别减少 180,000 或 240,000 次临时数组构造／秒。各项可相加，但这不是设备上实测的粒子数量或分配速率。

当前效果库有 985 条粒子控制记录：模式 0 共 945 条、模式 1 共 7 条、模式 2 共 14 条、模式 3 共 19 条。全部模式均覆盖帧状态优化，模式 1、2 额外覆盖方向计算。条带有 585 条控制记录、567 个节点；556 条采用 20 段，同一节点切换控制记录时段数均一致，UV 存储可按节点初始化后复用。20 段且无轨道运动时，状态和 UV 更新每次少建 27 个数组、四个对象；以每秒 60 次更新计为 1,620 个数组、240 个对象。该统计不包含条带生成绘制四边形、活动轨道采样、粒子出生及生命周期管理的分配。

## 粒子出生的临时分配

## 过期粒子状态复用

每个 type-6 粒子池保留自己的过期状态回收区；过期时仍按原规则把存活尾项移入当前槽位并继续前向遍历，移出的状态进入回收区。下一次成功出生先从回收区取出一份，直接覆盖位置、速度、加速度、角度、角速度、RGBA 及全部标量；未命中时仍通过原独立初始化入口分配。各存活粒子的六个数组继续互相独立，不共享发射器或其它粒子的状态。

发射仍在年龄更新前执行，当帧刚过期的状态只供之后的发射复用；原尾项交换后跳过该项的更新顺序、容量门禁及出生数保持不变。控制器切换时按当前控制记录完整重置状态，age 和 frameRemainder 归零，visible 按当前父矩阵重新确定，保留点／盒／圆盘的 19／22／21 次随机抽样及原 Float32 舍入点。绘制端立即把状态分量写入自身顶点缓冲，不持有粒子数组的历史引用。

| 静态计数范围 | 原路径 | 当前路径 |
| --- | ---: | ---: |
| 一次命中过期状态的成功出生：状态记录 | 1 | 0 |
| 同一次出生：六个状态数组 | 6 | 0 |
| 每秒 500 次回收命中：状态记录 | 500 | 0 |
| 每秒 500 次回收命中：状态数组 | 3,000 | 0 |

当前发布效果库的 678 个粒子节点有 985 条控制记录。每个池新增一个回收数组；一个连续使用且未 clear 的池，活动状态加回收状态总数只增长到本次使用期间的并发峰值，生产容量为电脑 1–600、手机 1–300，不能把全目录容量相加当作单局占用。例如总共成功出生 1,000 次、该池并发峰值为 100 且中途未清空时，状态记录从 1,000 次构造减为 100 次，六个数组从 6,000 次减为 600 次。一次发射后结束的 burst 首批没有回收命中收益。

回收会让已过期状态在后续发射前继续驻留，代价上限为该池尚未复用的并发峰值状态；原活动数组以外新增一个回收数组及其引用。end 调用原 pool.clear，同步清空活动区和回收区；树销毁后池也随节点释放，没有建立跨节点或全局池。粒子数量下降时不宣称堆占用立即降低，此项针对持续发射的分配和 GC 压力。

手机、平板、电脑及两套画质共用，public 资源不变。以上为源码与发布控制记录的静态核算，没有新的设备内存、GC 或 FPS 测量；未运行测试、构建、类型检查或浏览器验收。

## 粒子发射器启动与重置

`EffectParticleNodeState` 在启动与控制器切换时写回创建节点时已有的 `spaces`，使用同一节点的速度工作区。位置与轨道偏移按控制器独立持有，切换时先复制前一控制器的位置，角速度为零时保留目标控制器自己的偏移；启用轨道时仍执行原轨道计算。启动先按原父／全局矩阵规则取得控制位置，完整执行 `delta=0` 的空间推进，再按原 Float32 顺序加原点，没有省略零时间算术。

## 精灵启动与控制段重置

type-1 精灵在启动时复用已有 origin 和逐帧工作区，直接写入初始化外观、位置、速度、轨道偏移及首帧，再由原历史构造器建立独立快照。各历史条目仍各自拥有六个数组，条目数量、初始化填充、拖尾采样和绘制顺序不变；没有把工作区放入历史列表。路径仍先 reset 再按零 delta 采样，保留原位置相加后的 Float32 舍入。

## 条带与模型启动状态复用

type-7 条带首次启动时建立一份状态记录及六个独立数组，后续启动和控制段切换直接写回。baseFlag 非零时继续保留位置、速度、角度和缩放，两种切换均重置轨道偏移、颜色、首帧和帧余量。原点维持逐分量 Float32 存储，首帧仍先判断反向、再判断随机；scroll 和构造时生成的几何体不因启动或切换重置。

## 精灵、条带与模型绘制

每个特效绘制实例按需建立四边形缓冲，保留角点、UV、中心和显示缩放数据。活动数量与已分配容量分别保存，历史缩短后再增长可复用旧记录；超过已有容量时仅补齐新增记录。缓冲随特效实例释放，不进入手机空闲网格缓存，也不在不同实例之间共享可变角点。`EffectSpriteMesh` 同步复制输入至自身顶点缓冲，后续更新不会改变已提交的数据。

相机朝向和保持竖直的精灵直接写入四个角点；非朝向精灵、条带和模型特效复用矩阵工作区。矩阵乘法使用交替输出，输入与输出分开，保留平移、XYZ 旋转、全局变换及缩放的原运算顺序，包括单位矩阵乘法和各处 Float32 舍入。模型特效原有缩放后的全局变换继续执行。精灵历史倒序、当前颜色、按历史索引计算的透明度、反射 UV、四边形顶点顺序和条带提交顺序均沿用原规则。

CVD 每个可见材质部分直接更新现有元数据中的排序优先级，保留其它来源字段。`alphaIndex`、渲染组及不透明／透明排序规则不变。

当前发布效果库的 1,088 条精灵控制记录中，648 条保留单份状态，启用拖尾的历史上限最大为 64；585 条条带控制记录的段数最大为 150，其中 556 条为 20 段。缓冲容量依据原数据增长，不减少历史或条带数量。

## 精灵、发射器与模型更新

精灵实例保留一份更新工作区和加速度向量，外观、运动、轨道偏移及路径位置直接写入已有数组。每个控制器的拖尾配置在实例建立时保存；帧推进继续使用原随机回调。独立调用的外观、运动、空间、轨道及路径函数仍返回新数据，生产逐帧更新使用对应原地入口。

拖尾当前状态与更新工作区分开，采样时把上一帧的当前状态留在历史索引 1，再写入新状态。已满时复用即将丢弃的最老记录，历史缩短时保留闲置记录，后续增长时优先复用。控制器切换后只在发生采样或关闭拖尾时缩短历史；未舍入累计时间的比较、Float32 余量以及每次最多采样一次保持原规则。各记录继续独占六个数组，不共享可变位置或颜色。容量由该实例实际经历的历史数量决定，随实例释放。

粒子发射器保留位置、轨道偏移、速度工作区和默认目标向量，路径参数及生成回调随实例建立。生成器同步读取发射位置，每个新粒子仍保存自己的运动数组；粒子数量、随机数调用顺序、发射与更新顺序不变。模型特效直接更新位置、速度、缩放、角度和轨道偏移；条带轨道也写入已有向量。原来 X/Y 与 Z 不同的乘积舍入和轨道四元数计算顺序继续保留。

## 动作时钟与履带更新

动作事件查询与时钟增加原地输出入口；战车、城堡和大厅宠物预览各自保留事件编号数组。时间增量仍按原精度截断，停止动作的完成消息仍先于并替代该次定时事件查询，循环结束消息与跨周期事件的顺序不变。独立调用时钟或事件查询继续返回新的数组。

战车的常规帧回调提供自己的消息汇总缓冲，各部件的事件编号在下一部件推进前复制成独立消息对象。默认调用 `advanceAnimations(delta)` 仍返回新的消息数组；传入输出缓冲时先清空并写入该缓冲。真实消息对象及通知中的烟尘位置数组继续独立，监听者保存它们后不会被下一帧改写。通知仍在各部件采样、元数据、挂点和烟尘处理之后执行；常规帧回调在通知结束后清空自己的汇总缓冲，解除消息引用。

## 网格上传视图

屏幕图片批次和世界特效网格保留最近一次活动数量的上传视图。活动数量相同且底层缓冲未更换时，直接复用这些视图；数量变化时只建立该次所需视图，不保存所有数量的历史。扩容或切换拓扑后，缓存立即改为新的底层数组并失效，下一次上传按实际活动数量截取，避免持有旧数组。隐藏空批次继续不上传数据。

上传数据、有效长度、顶点和索引数量、拓扑、边界及绘制顺序保持原值。Babylon.js 9.29.0 的 `Buffer.updateDirectly` 在零偏移上传后保留传入视图；WebGPU 直接使用它的字节范围调用 `queue.writeBuffer`，WebGL 传入 `bufferSubData`。复用视图不复制顶点数据，也不减少上传字节。

| 活动数量稳定时的一次非空上传 | 原显式临时分配 | 缓存建立后 |
| --- | --- | --- |
| 屏幕图片批次 | 三个 TypedArray 视图 | 复用三个视图 |
| 普通世界特效四边形或弹道条带 | 三个 TypedArray 视图 | 复用三个视图 |
| 着色器朝向的粒子批次 | 四个 TypedArray 视图 | 复用四个视图 |

每秒 60 次、数量稳定的普通批次可少建 180 个视图，粒子批次可少建 240 个视图。粒子数量频繁变化时仍会建立新视图，不能按全部帧计算这项收益。

普通世界特效和弹道省去未使用的形状数组，CPU 顶点数组从每容量顶点 44 字节降为 36 字节，减少约 18.2%；例如 1,024 个容量顶点减少 8 KiB。着色器朝向的粒子继续保留形状数组，GPU 顶点布局与上传字节不变。世界网格扩容时直接写入索引 TypedArray，省去每四边形一个或每条带三角形一个临时索引数组，索引值和方向保持原值。

## 名牌与飘字

名牌复用投影向量、单位矩阵、视口和六个视锥平面。文字与生命值图集 UV 随名牌槽位建立，血条 UV 写入保留数组，双方颜色使用原数值的固定数组。每帧仍按当前相机计算全部平面，保留 `dotCoordinate <= 0` 的裁剪条件、边缘限制、距离缩放和图层顺序。

战车、城堡和可破坏物的飘字投影共用同一工厂，各工厂拥有自己的位置、视空间和投影向量、单位矩阵、视口及结果对象。投影后立即消费结果，屏幕坐标继续取整数；可见距离、深度符号、位置偏移、透明度、比例和一秒寿命不变。原始记录继续保存捕获时的位置，逐帧投影写入队列自己的绘制记录，绘制后解除其中的原点引用。

## 弹道绘制

每个弹道绘制实例复用起点、终点、方向、观察方向、侧向和顶点记录，按活动顶点数提交，并保留已分配容量。每段的方向计算保留 `.005` 阈值、+Y 回退和原 Float32 归一化；坐标变换沿用 `count=1` 分支的加法顺序。左右边缘先按原式舍入，再与上一段平滑，末尾仍提交两份重复位置和对应 UV。生成和重建路径继续使用原随机数、频率及段数，不因绘制复用改变结果。

S 个非空弹道段的一次绘制，原路径显式构造 `15S + 4` 个数组（含调用方眼点数组）及 `2S + 2` 个顶点对象。容量达到所需顶点数后，该路径不再创建这些数组和对象。一个 20 段弹道以每秒 60 次绘制计，可少建 18,240 个数组、2,520 个顶点对象。

当前生成器最多生成 255 个中间段及一个末段，绘制最多提交 514 个顶点。各顶点保留位置、UV 数组及记录，缓冲由特效实例独占，随实例释放，不进入空闲网格缓存。

## 弹道分段重建

## 相机跟随与地面坡度结果复用

战斗相机按相机实例保留上方向、目标、视点、位置和手机旋转矩阵；炮塔的三个局部基准向量只在模块初始化时建立。电脑跟随改用 `TransformNormalToRef`、`TransformCoordinatesToRef`；手机从炮塔矩阵直接写入位置缓冲，再以 `RotationYToRef` 更新旋转矩阵。相机仍按原顺序调用 `upVector` setter、`setTarget(..., false, true, true)` 和 `setPosition`，保留 setter 的归一化、Y-up 转换矩阵、目标持有方式、位置相等短路及角度重建。

死亡绕行和直接角色跟随共用原地姿态计算。向量分量改为标量中间值，保留原 Float32 舍入位置、叉积、求长／归一化次序、X 反射及先计算已舍入的视点再相减的公式。死亡绕行继续使用每秒 30 度的转速和原身体高度偏移。独立 `originalBattleCameraPose` 仍返回三份独立坐标数组，供现有诊断入口使用。

每辆战车的坡度计算写入自己的采样器，未变化的显示姿态复用结果，详见[静止战车坡度与观察者查询](#静止战车坡度与观察者查询)。缺少导航、无效位置、离地、死亡或非战斗状态均呈现零坡度；需要重新计算时，49×52 的采样范围、五个地面查询、回退高度及 `atan2` 公式不变。独立 `tankGroundSlope` 仍返回独立结果。

## MV3 实例目标对象

战车、城堡、Hook 和宠物共用的纹理形变管理器直接读取模板目标，实例不再克隆逐目标对象及其观察器；每个网格继续独立保存两项权重、目标索引和活动数量。GPU 采样直接写入这组缓冲，不修改模板目标的权重。顶点属性形变保留原独立目标与几何体路径，容器借用及模板释放时机不变。

## 建筑、模型与阴影逐帧分配

每座破损建筑保留自己的可视状态和完整模型网格列表。逐帧状态写入该实例的结果，`root.metadata.sourceBreach` 指向同一实例状态，元数据其它字段继续保留；不再重建状态记录、根节点元数据和子网格数组。独立 `SceneBreachState.snapshot` 仍返回独立记录，已有诊断入口可保存历史快照。破损播放、Float32 淡出、严格小于零才隐藏、无破损模型时的完整模型淡出、同轮复活与换轮重置沿用原状态机。

普通 CVD 和破损 CVD 各保留一份绘制参数，破损模型每次可见更新只写入 `Math.max(0, alpha)`。矩阵、blend、priority 及绘制顺序不变，模型 renderer 同步消费参数。模型时钟与矩阵更新直接遍历，省去 `setTime`、`setRate`、`update`、节点矩阵绘制及隐藏绘制的 `forEach` 回调；仍按原节点顺序、每个动画分别读取 delta，并使用原矩阵乘法、材质与 GPU 顶点路径。

静态场景阴影根在注册时确定完整子网格列表，逐帧继续检查启用、可见、透明度、包围体及相机裁剪。战车与显式 meshes 提供者继续动态查询；战车的当前动作网格数组在动作切换时原地填充，省去每帧 `flatMap`，释放时清空。每个动作加载时记录其 U 部件炮塔节点，瞄准直接更新该节点；三部件车型没有 U，保持原无节点更新路径。动作切换、瞄准、阴影材质、接收标志及投射范围不变。

## 战车动作挂点查询

每个战车动作在加载完成时确定主挂点和饰品挂点的部件及轨道引用。主挂点保留 M 优先、四部件车型 U 回退；饰品挂点保留 U 优先、M 回退，只有超过一帧的饰品轨道参与选择。缺失的主挂点仍写入零矩阵，缺失的饰品挂点仍返回空值。采样每次读取所选部件当前的 `clock`，动作重播替换时钟后继续使用新时刻；各玩家的播放状态与输出矩阵相互独立。

动作同时记录是否存在非空烟尘挂点，车型是否含 U 沿用初始化时确定的值。履带触发烟尘时不再搜索部件和轨道，单位矩阵比较改为直接遍历。原烟尘坐标数组和动作消息继续逐次独立创建，通知顺序、坐标、触发条件和履带相位不变。

| --- | --- | --- |

| 一个饰品挂点采样 | 每查一个候选部件建立两个查询回调 | 读取预选引用，无查询回调 |
| 车型是否为三部件的查询 | 一个部件查询回调 | 读取已有车型标记 |

当前 21 种车型的 168 个实际动作，主挂点查询每次原来创建 14–24 个回调。按 10 辆已加载战车、60 次更新／秒、每帧动画和瞄准各更新一次计算，该路径每秒少建 16,800–28,800 个回调。饰品、额外位置更新和烟尘检查的节省未加入此例。

## MV3 实例材质与贴图归属

MV3 实例直接读取模板的源材质属性及仍需的默认图片，不克隆随后就会被替换的 PBR 材质及贴图对象。战车模板仅保留原材质描述，直接创建玩家 Shader，不建立模板 PBR。城堡、Hook 和宠物的 ShaderMaterial 由各实例容器持有；战车材质由各玩家的部件持有者管理，同一部件不同动作的相同参数材质共享。各玩家之间保留独立的透明度、颜色滤镜、皮肤及履带状态。需要再次替换实例已有材质时，只释放容器拥有的旧材质。

## MV3 形变姿态存储

Babylon 加载每个形变目标时，先生成位置与法线 Float32 数组，再将这些数组打包为 RGBA Float32 二维数组纹理。引擎保留打包缓冲用于设备恢复；原逐目标数组此前也一直留在模板。当前纹理形变模板保留原纹理、尺寸、层序及恢复缓冲，用轻量目标读取器替换逐目标数组。不支持纹理形变时保留原路径。

打包布局为每个顶点两个 RGBA 像素：位置 XYZ、法线 XYZ；目标层偏移按纹理宽 × 高 × 4 计算，包括行尾填充。CPU 调用目标的位置或法线读取器时，按原顺序生成临时 Float32 数组，不缓存另一套姿态。GPU 绑定继续使用原纹理，采样只更新实例独立权重与目标索引。模板姿态不可变，管理器同步保留原布局及纹理，不重新打包。设备恢复仍由 Babylon 内部纹理的 Raw2DArray 路径读取同一缓冲。

## 诊断快照与地面物件同步

战斗诊断输出保留 `data-world` 的全部字段、字段顺序与玩家动作顺序，手机仍按原 100 ms 间隔采样，电脑仍能读取当帧动作与加载状态。玩家和地图的大块 JSON 只在收到快照后第一次发布时序列化，随后复用；新的快照进入 `reconcile` 时直接失效缓存，接收方复用同一对象也会重新生成。快照的结算阶段调整在接收前置回调中完成，缓存记录的是调整后的值。缓存仅持有字符串，不延长旧快照对象图的生命周期，取消加载与离场同时清理。

呈现动作记录按玩家顺序复用，使用固定 Map 遍历回调，只有玩家 ID、顺序、数量或动作变化才重新序列化。原返回独立数组的 `actions` 接口保留，生产诊断使用缓存的 `actionsJson`；模型异步加入、离开、动作切换及地图加载完成仍会触发输出。身份、快照与呈现结果均未变化时省去整份 DOM 属性写入；每次检查仍序列化四项身份字段，未将这部分算作零分配。

地面陷阱和道具各复用一个参与者集合。加载入口保留原去重、移除、错误回收与换轮规则，加载完成后解除 `loaded` 引用，只等待仍在加载的实例；集合只在同步部分使用，跨 `await` 的待加载数组由各次调用独立持有。所有实例都已就绪时省去 `Promise.all`，返回的 async Promise 仍然存在。道具的拾取记录只保存需要的声音与位置，同一 ID 原地更新，不复制整个新快照；快照先移除、拾取事件随后到达时仍能播放原提示音，事件移除记录及换轮清理规则保持原值。

## 掉落记录回收与异步快照引用

地面掉落的成功拾取和到期删除都通过事件释放声音／坐标记录；快照只移除可视对象。客户端在同轮断线恢复时沿用现有呈现对象，服务端恢复接口只提供当前快照，不重放离线期间的拾取或删除事件，因此仅依赖事件会让这些旧记录留到本轮清理。

呈现入口现在接收当前快照 tick。记录第一次未出现在 PLAYING 快照时只保存 missingAt，保留给随后同一批的拾取事件；直到另一份 tick 严格更大的 PLAYING 快照仍未包含该 ID，才清除记录。同一 tick 的重复快照、资源加载等待循环及恢复响应不会消耗缓冲期；记录重新出现或收到 drop 事件时清除缺失标记。服务端仍按快照、随后本批事件的顺序广播，因此正常本地拾取继续只播放一次声音；未知 ID、他人拾取及显式删除的声音规则不变。非 PLAYING 阶段沿用原事件／换轮／离场清理，不按固定毫秒数猜测网络到达时间。

每条音效记录新增一个可空 tick 字段，复用原参与者 Set，不新增定时器或历史列表。新增清理遍历使用 Map.keys，不构造逐条键值对数组；成本是每份 PLAYING 快照额外查看当前音效记录。每个漏收删除事件的旧 ID 在缓冲期后解除一个记录及其 XYZ 数组的引用；字节降幅随真实漏收数量而变，不把所有掉落次数当作泄漏数量。

拾取提示直接传递已从记录表取出的坐标，省去原来对每次已知拾取建立的一个位置副本；实际声音后端立即写入 Panner 并保存自己的坐标副本，不保留可变记录。远端拾取和空声音编号也不再创建这份未使用的中间数组。

陷阱异步加载的状态回调改为比较接受快照的更新序号，以及原有会话、资源修订号和活动状态；等待期间不捕获整份房间快照。新的接受快照会使旧回调失效，只有最新对齐结果能修改 groundTrapError，取消加载与离场仍受原会话／资源修订保护。每个 Battle 新增一个数值字段，无逐消息工作区对象；这是解除回调对旧快照对象图的强引用，不移除仍由当前快照、导航同步或其它合法消费者持有的数据，也不把未结束 Promise 当作已经释放。

两端和两套画质共用，public 不变。以上为生产调用链和引用归属的静态走查，未运行测试、构建、类型检查或浏览器验收；没有新的进程内存、GC、FPS 或手机采样。

## 导航同步与坦克碰撞工作区

## 移动导航采样与手机转向

生产移动入口直接读取 `sampleRoleNavigationFailure` 返回的失败码：`undefined` 表示通过，0、1、2 保留原侧向失败含义。原 `sampleRoleNavigation` 仍逐次返回独立结果，成功时没有 `failureCode` 字段。采样中的闭包改为不持有状态的数值函数，同行的局部 Z 只计算一次；保留原 Float32 运算、首／末侧查询、逐行逐列查询和遇阻立即退出的顺序，以及相同的尺寸和方向异常。

## 垂直更新、地面采样与 CPU 路线

| 每次本地不更新状态的垂直步 | 1 个 step | 工作区建立后为 0 |

本地工作区初始化共 3 个对象，按原本地操控对象的生命周期保留；重置与离场只保留数值，没有场景引用。正常贴地或下落、每秒 60 次更新的指定示例，每秒少建 120 个记录并减少 60 次双线性地面高度查询。查询不创建原 NavigationCell，因此这部分只核算重复计算，不能再计为对象减少。

CPU 原导航策略按策略实例复用方向、候选点和最后通过点，只有完整通过中心与车体采样后才更新最后通过点；遇阻不会把失败候选作为路线终点。中心高度使用 `validHeightAt` 直接读取原单格 Float32 高度，坐标截断、低字节有效性及占用判定与原 `sample` 保持一致，完整车体采样仍在中心检查之后执行。

`reachable` 继续返回独立点，没有通过任何采样及零长度时保留起点的附加字段；通过采样时只返回原 XYZ。`canTraverse` 同步完成相同扫描并直接比较最后通过位置，省去返回点；原 6 单位采样间隔、朝向、0.01 距离阈值、缓存键及规划版本规则保持原值。策略内部没有异步暂停或用户回调，A* 的暂停发生在策略调用之间，各规划器持有的路线点不会被改写。

令 N 为一次非零长度路线实际检查的候选点数，M 为这些中心采样中位于网格范围内的次数，M≤N；这里只计路线点和原 NavigationCell，不重复计入上一节导航失败码的收益：

| 每次调用 | 原记录数 | 当前记录数 | 少建记录数 |
| --- | ---: | ---: | ---: |
| `reachable` | 2＋N＋M | 1 | 1＋N＋M |
| `canTraverse` | 2＋N＋M | 0 | 2＋N＋M |

策略初始化相比原实现增加 3 个数值记录和 1 个扫描闭包；它们不随路线采样数增长。零长度 `reachable` 仍创建 1 个起点副本，零长度 `canTraverse` 则省去这个副本。指定检查 10 个网格内候选的路线，记录数分别从 22 减至 1 和 0。A* 与出生选点使用的 `positionAtCell` 还省去每次网格内查询的中间单元记录，返回点继续独立，中心坐标 Float32 和存储高度保持原式。

本地垂直与地面采样优化覆盖手机、电脑，导航与 CPU 路线优化也覆盖服务端；没有改动资源、画质或画面效果。以上为源码静态核算，没有新的 GC、CPU、FPS 或 iOS 进程内存记录。服务端保留 NAV 预测中的台阶拒绝；最终 X/Z 改变或首次垂直拒绝时，在碰撞后重新执行垂直步，实际物理规则范围见[垂直物理](recovery/battle-vertical-physics.md)。

## 服务端垂直结果复用

`predictBattleMovement` 返回的 `BattleMovementPrediction` 明确记录 `verticalAccepted`：只有通过的垂直步才描述返回姿态的完整垂直结果。`predictControlledMovement` 仍先按步前物理 Y 扫掠其它战车，最终 X/Z 与该姿态完全相同时，提交已经计算的 Y 和独立垂直状态，省去重复积分及相同位置的地面查询。方向、yaw 和 command 仍从原碰撞结果及同一对象身份规则计算，没有提前返回 NAV 预测对象。

首次垂直拒绝意味着 NAV 候选超过采用的 18 单位台阶限制；该拒绝继续发生在战车碰撞之前，不能把原姿态及未推进的状态当作可复用结果。这个分支与最终 X/Z 改变的分支都从玩家步前状态重新执行原垂直步，使夹停、拒绝与静止时的下落继续在实际停留位置求解。无效地面、非正时间、贴地、重力、Float32 舍入与落地规则沿用共享垂直模块。

## 三维图片源缓存

三维图片只共享仍在进行的 Blob 读取，读取完成即移除 Promise。模型与本局动态道具的图片预加载将完整文件写入 IndexedDB，准备完成后不再把 Blob 和 Blob URL 存入页面级 `preparedImages`。无取消信号的预加载和三维图片读取共用待完成的读取，多个并行模型引用同图时不会重复下载；带取消信号的资源包继续使用原可取消读取。界面继续由原 UI 图片持有者管理图集、解码图和裁剪结果；三维读取若碰到界面已持有的同版本 Blob，只借用该数据。

GLB 加载器按本次加载复用相同图片的临时地址。Babylon glTF 在 URI 读取后以 `Uint8Array` 创建纹理，并保留原压缩数据用于设备恢复；加载完成或取消时，`GLTFFileLoader.onDisposeObservable` 撤销本次临时地址并清空记录。读盘尚未完成时加载器已释放的请求不会再创建地址。调用者原 `preprocessUrlAsync` 先处理地址，图片读取再使用处理结果；数据 URI 和调用者自己的 Blob URI 沿用原读取。

普通三维贴图保留发布 URL，底层图片入口从磁盘缓存读取 Blob 再交给 Babylon `LoadImage`。WebGPU 直接从 Blob 创建 ImageBitmap；HTML 图片分支由 Babylon 在载入或错误后撤销自己的临时地址。地面道具、陷阱与伪装不再把页面 Blob URL 写入 `Texture.url`，省去由 URL 的 Blob 类型触发的常驻解码 ImageBitmap 引用；设备恢复重新从同一版本的磁盘图片读取，GLB 的恢复继续使用原 Uint8Array。各入口的颜色空间、翻转、mipmap、采样及环绕参数保持原值。

## CVD 动画区间查询与反射矩阵

CVD 变换采样让缩放 XYZ 与其四元数共用已经取得的区间，不再对同一缩放轨道重复查找。四元数继续独立对插值系数作 Float32 舍入，点积、最短路径、角度换算、矩阵乘法及舍入顺序保持原式。时间未变化时继续直接使用原采样结果，没有停止任何活动动画。

## 隐藏特效与命中绘制工作区

世界精灵和粒子隐藏时直接调用 `EffectSpriteMesh.clear()`，清空活动顶点计数并禁用网格。观察者不可见、节点不在活动阶段及本地状态图隐藏三条路径不再构造空数组。后续活动绘制仍从 `begin` 重新计算顶点和边界，沿用原缓冲容量、上传视图及四边形／三角带拓扑。原空更新本来就跳过 GPU 分配和上传，本项仅减少 JavaScript 临时数组和空批次处理，没有计算 GPU 内存收益。

`ShotImpactRenderer` 每实例保留一个方向向量和四个数组：命中原点、烟团位置、颜色、固定 UV。每个存活命中继续读取当前相机位置，使用相同减法、归一化及乘 2 顺序移动绘制原点；同步提交四边形时，网格将坐标、颜色和 UV 写入自己的顶点缓冲，没有保留这些输入数组。烟团扩散、角度、尺寸、淡出、颜色量化和绘制顺序保持原值。

| 一次更新的指定范围 | 原临时分配 | 当前工作区建立后 |
| --- | --- | --- |
| 一个已有精灵或粒子网格进入上述隐藏分支 | 一个空数组 | 直接清空并禁用 |
| 一个尚未过期的伤害命中 | 三个 Vector3、三个数组 | 复用实例方向、原点、颜色和 UV |

手机和电脑的运行路径均为每个非伤害命中绘制三个烟团。以 10 个未过期非伤害命中、所有烟团均已开始、每秒 60 次绘制为指定示例：两端每秒都少建 1,800 个 Vector3；手机和电脑每端另少建 6,000 个数组。若每次有 20 个已有网格走隐藏分支、每秒更新 60 次，另少建 1,200 个空数组。实际数量取决于命中寿命、开始延迟及场景活动状态；这些是独立示例，不作为持续活动量或合计内存收益。

## 特效绘制状态键与参数

特效应用当前原 sourcePass，连续相同源 pass 复用上次结果，继续按 Map 原插入顺序继承前一次绘制及前一帧的全部状态。桌面完整状态键的字段格式和分号顺序保持原值，用一个实例字符串数组代替 Map 展开和 map 中间数组；键生成后清空工作区。手机不生成未参与手机判断的完整桌面键，仍应用所有原状态。

手机仍用原节点编号与 CullMode、DestBlend、ZEnable、MinFilter[0] 四字段构造复用键。每个 Draw 保存一份当前四字段和键，同值时直接沿用字符串，任一字段变化时使用原 mobileDrawKey 重新生成。各节点独立，控制器切换仍先应用新状态；缓存没有持有历史组合。原 draw.passKey 保留到旧渲染器释放完成，新键单独记录，不改变旧资源归还及新缓存查找的时序。字段缓存随 Draw 释放，空闲渲染器池不持有它。

渲染器参数直接按状态键遍历生成独立状态数组和记录，不再先展开条目数组再 map。新建精灵、粒子和全屏渲染器仍收到相同的完整参数值及顺序。手机命中已有空闲世界渲染器时不再建立无人消费的参数副本；命中后的采样、wrap、网格元数据、排序以及原 64 个空闲渲染器上限保持原值。预编译使用同一参数生成方法，仍读取它自己的局部状态 Map。

当前发布库有 11 份渲染脚本，源 pass 分别有 18 或 19 项状态；含全屏 pass 的全部状态名称共 21 个。以运行时当前继承表字段数 N 表示：

| 每次调用的指定范围 | 少建的显式结构 |
| --- | --- |
| 一次继承状态变化后的完整键处理 | 两端均少 N＋2 个数组和 1 个回调；手机还省去 N 个字段格式化及完整键 join |
| 手机同一 Draw 的原四字段未变化，工作区已建立 | 省去一次手机键格式化 |
| 确实新建渲染器的参数生成，含预编译 | 从 N＋2 个数组减至 1 个独立状态数组，少 1 个回调；N 个状态记录与 1 个 pass 记录保留 |

假定每帧有 20 次可见、非模型特效绘制、每秒 60 帧、当前继承表 19 字段，绘制之间每次都有 source 状态变化，同时每个 Draw 自身的四个手机键字段与上次绘制相同。预热后，两端每秒少建 25,200 个数组和 1,200 个完整键回调；手机另省去 22,800 次字段格式化、1,200 次完整键 join 和 1,200 次手机键格式化。该例不要求全局状态静止，但要求指定的绘制与继承条件，不是某张地图的实测。新建渲染器或缓存命中参数节省未计入此例；首次遇到、同节点字段变化、额外继承字段及活动节点数变化时，收益按表中实际路径计算。

## 技能计时器与文字队列遍历

技能队列计时器复用实例自己的两个数组，按 Map 原顺序保存本帧开始时的角色 ID 和计时器引用，然后再执行到期切换。保留原任务快照语义：`alternate` 删除旧任务并注册下一项，新任务不在当前帧重复推进。计算继续使用原 `Math.fround(deltaSeconds)`、严格 `remaining < delta` 到期判断及 Float32 剩余时间；恰好剩余为零时继续等待下一次正 delta。角色、特效停止、声音停止、下一技能激活和注册顺序保持原值。

工作区仅保存原计时器引用，不复制或替换任务记录，不向外发布数组；每次同步完成后用 finally 清空引用。生产 backend 只调用原 EffectRuntime 和声音接口，没有递归推进该计时器。`queueTimers` 仍返回原只读 Map，注册、替换、角色移除及回合清场沿用原数据归属，下一任务的计时器记录继续独立创建。

装备技能队列在长度相同后直接逐项比较，不再创建 every 回调。顺序、重复技能和任一条目变化仍触发原清队列、逐条 play 及 revive；保存的技能列表继续独立复制，权威数组不会成为可变的内部状态。

玩家伤害与回血文字队列使用 Map keys 读取，省去每个角色、每种队列的键值条目数组。`loadPlayer` 在文字资源就绪后为每个已加载玩家创建两种队列，空文字队列也按原方式推进；坐标投影、深度、Float32 时间、渐隐、隐藏角色及绘制顺序继续保留。没有减少文字、跳过队列更新或改变 GPU 上传。

| 每次调用的指定范围 | 原显式分配 | 当前对应分配 |
| --- | --- | --- |
| 正 delta、T 个技能计时器 | 1 个外层数组＋T 个键值数组 | 复用两个内部数组，不创建条目数组 |
| K 个同长度、内容未变化的非空装备技能队列比较 | K 个回调 | 直接比较，无回调 |
| N 名已加载玩家，伤害和回血队列均已建立 | 2N 个键值数组 | 按键读取，无条目数组 |

按十名玩家、两种文字队列均已加载、每秒 60 次正 delta 帧同步计算：没有技能计时器时，两条遍历合计少建 1,260 个数组／秒，其中计时器为空列表的 60 个、文字队列的 1,200 个。若有十个活动计时器及十个稳定非空装备技能队列，合计少建 1,860 个数组和 600 个比较回调／秒。两个指定示例不能相加，实际数量随已加载玩家和队列变化；计时器到期创建的下一任务记录及真正的播放、声音和文字数据不计为节省。

世界特效通知的 X/Z 位字段转换复用一份四字节 DataView，仍按 little-endian 的 Uint32 写入和 Float32 读取。单次转换无回调或异步边界，先读取的坐标是独立 Number，后一次写入不会修改前一结果。每个实际进入 world 分支的通知包含两次转换，从四个临时对象（两个 ArrayBuffer、两个 DataView）减至零；世界坐标数组及效果自己的原点副本继续独立，不计入逐帧示例。

## 灼烧与伪装状态工作区

灼烧表现继续由快照和战斗逐帧同步。每个实例复用在场 Set 及当前结束标记 Map；标记内的 Set 只在首次需要该角色时创建，连续同步清空后复用。权威确认角色死亡、离开、burn 消失或 startedAt 改变时删除不再需要的标记工作区；房间／轮次切换和清场释放全部条目。结束标记的移除直接遍历原 Map keys 和 Set，省去外层、键值条目及各标记的展开数组，删除当前项继续遍历。

原结束通知仍先停止匹配 startedAt 的特效和声音。旧快照继续携带该 startedAt 时保持拦截，不能重新开始灼烧；新实例不被旧标记阻止。逐帧继续查找坦克并检查 root 销毁状态，因此晚加载或替换模型仍按原时序创建首槽表现。播放、slot、tag、声音、停止条件和 phase 清理保持原值，没有按快照引用跳过这一检查。

伪装表现复用在场 Set，增删扫描直接使用 Map keys。支持判定按原顺序读取物品 Map，找到相同 use／skillRoles.primary 后判定样式，不再把全部物品先复制进数组。已有替身按 skillId、style、startedAt、expiresAt、x、y、z 七个原身份字段直接比较，沿用视觉对象已有的快照；无需每帧建立键数组和字符串。任一身份字段改变仍先释放旧替身并加载新资源，异步完成、错误记录、清场和坦克隐藏规则沿用原值。就绪读取直接逐项查看 ready，省去数组和 every 回调；清场直接遍历资源值。

## 阴影筛选与可见列表

启用场景阴影时，名称排除结果按网格存入 WeakMap。每次仍读取并比较网格名、材质名、地形源纹理名和绑定纹理名；首次遇到或任一字段变化时才重新拼接、转小写及筛选。销毁状态、顶点数量、祖先公告板模式和植物标记继续实时检查。正则不含 global／sticky 状态，只在模块初始化创建一次；缓存记录不持有网格、材质或纹理引用。

可见投影物写入当前阴影图已有的 `renderList`，按原顺序覆盖并截断尾部。首个网格令空列表变为非空时使用被观察的 `push`；非空列表变空时使用被观察的 `splice`，保留 Babylon 对空／非空切换的材质通知。持续为空或非空时不清空后重新填充，不触发反复通知。列表从当前阴影图获取，设备恢复或阴影图重建后不持有旧数组；场景清理仍释放列表中的网格引用。

安装版本的 Babylon 在替换 `renderList` 时会调用 `_ObserveArray`：为五个数组方法各创建一个观察函数及一个解除函数，另创建一个 map 回调和一个统一解除函数，共 12 个函数及一个解除函数数组。连同原可见数组，每次更新共两个数组。当前列表建立后，持续非空或持续为空的每次更新省去这两个数组和 12 个函数；按每秒 60 次更新的指定示例，分别为 120 个数组和 720 个函数。实际变为空时 `splice` 会返回一个数组，该切换不计为零分配。

名称字段稳定后，每次资格检查还省去一次字符串拼接、小写转换和筛选，且不再逐次创建 RegExp。代价是每个遇到的网格保存一个四字段名称记录及结果；WeakMap 不阻止网格回收。阴影距离、裁剪、投影矩阵、顺序、可见性及原名称排除规则保持原值。当前手机运行场景设置 `shadowsEnabled = false`，本项收益属于启用阴影的路径，不能计入默认手机优化。没有新的渲染或内存实测。

## 背景音乐源生命周期

背景音乐的完整资源预下载与播放源分开持有。`prepare()` 继续等待当前地图和两首结算曲下载完成并保存到 IndexedDB，完成的读取不保留 Blob 或 URL。`select()` 沿用同一媒体元素，先读取目标曲目的本地 Blob；目录和文件两次异步边界后均检查原请求序号及销毁状态，确认仍有效才创建当前音源。旧请求完成时没有新 URL 需要保留或清理。

目标完整文件准备好后，停止旧媒体元素，移除 src 并调用 load，再撤销旧 URL，随后绑定新源。创建和绑定之间没有异步边界；快速切页、停止、销毁及并行相同曲目的读取不会把旧结果重新放回播放器。稳定播放或等待交互解锁只保留当前曲目的一份 URL；停止和销毁后为零。自然结束的结算曲保留当前媒体状态及其一份 URL，直到后续切换或停止。同曲目选择、循环、音量、MIME、曲目映射、播放拒绝后重试及诊断字段沿用原值。

静态资源模块不再持有全页面音乐 URL 目录。项目生产入口仅创建一个 BattleMusic；PageMusic 使用同一个播放器，场景退出经 PageMusic 或直接调用播放器的 dispose。资源目录生成器递归登记 public 文件，ImagePreloader 在启动游戏前登记资源版本，因此当前十四首可访问音乐均使用既有 IndexedDB 完整缓存。切歌新增一次本地文件读取，旧曲在读取完成前继续播放；文件未变化时无需再次下载。正在读取和切换的临时 Blob 不计入下表稳定持有量。

## 静止战车坡度与观察者查询

## 特效节点生命周期方法复用

`RuntimeNodeState` 同时承载原节点字段与 `EffectLifecycleHooks`，七项生命周期操作和 `releaseState` 使用共享的原型方法。`EffectNodeLifecycle` 继续通过 `hooks.method(...)` 调用节点，状态机、时间轴选择、父子激活及逆序更新规则保持原值。每个节点仍有独立的生命周期、运动状态、子节点列表、复用状态与一次性释放标记；静态源节点编号、树创建顺序及首个 ID 匹配沿用原实现。

类型状态构造结束后才调用 `takeRetainedState()`，保留对象池领取及条带滚动恢复顺序。生命周期构造只保存字段、不触发钩子，启停入口在整棵树创建后使用。start 保留精灵、粒子、条带、声音、弹道、全屏、模型的调用顺序，精灵禁用拖尾时仍恢复原 elapsed；reset、update、end、声音 additionalEnd 和 screen 激活参数保持原值。

## 发布与静态核对

19 个 CVD/POL 库共 72 个模型已写入 `apps/web/public/data/`。原 JSON 合计 44,370,362 字节（42.32 MiB）；全部紧凑索引、模型元数据和二进制合计 1,388,151 字节（1.32 MiB）。这两个值比较的是可选运行数据表示，实际每局只读取所需模型。

已逐模型核对源帧对应的 1,385,485 个 XYZ/UV 数值及颜色，均与原数据转换为 Float32 后一致；恒定帧去重后实际保存 158,485 个 XYZ/UV 值。节点层级、材质部分、变换采样字段、时间和持续时长也一致。全部库原有 277,097 个逐顶点数组，紧凑数据以 397 个顶点 Float32Array 视图及 2 个颜色视图替代这组多层表示，变换轨道另用 1,083 个连续视图。

`scripts/asset_compression/cvd.py` 由 public 目录整理流程调用；`npm run assets:publish`、UI 发布和战斗素材发布均会生成对应紧凑文件。索引使用 `<库名>.models.json`，模型元数据及二进制位于同级 `<库名>-models/`。原库 JSON 保留用于再生成；资产包因此新增 1.32 MiB，运行路径使用紧凑文件。开发下载目录会登记当前文件的字节及修改时间，生产前端需与新数据一起发布。
