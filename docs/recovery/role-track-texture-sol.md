# role/001 履带 A/B 合同（M3-03 / M6-03）

原四组件 actor 的 X、Y 使用同一个纹理相位。选定 XY 皮肤时先设置 A；未完成的目标位置运动允许角色更新入口累加 delta，累计严格超过 float32 的 0.1 时切换一次 A/B，累计值归零。停止时保留相位和累计值，不自动回到 A。

## 原调用与字段

| 地址 / 字段 | 实际合同 |
| --- | --- |
| `0x46c239 / 0x46c23f` | 构造时 `+0x354=0`、`+0x350=0`，分别为相位索引和 float32 累计值 |
| `0x46cdb7–0x46cea2` | 选定皮肤加载 A 到 `+0x360`、B 到 `+0x364`，初始 A 设置给 X/Y |
| vtable `0x5c88c8 + 0x0c` → `0x46c483` | 接收 float32 delta，原样传给 `0x46753f` |
| `0x46753f` | 先写 delta 到 `+0xb4`，累加 `+0x1c8`，调用 `+0x60`，随后运行目标位置门禁 `0x4660a5` |
| `0x4660a5` | `+0xd8` 非零或 `+0x120` 为空时返回 true；否则由 `0x46ae9c → 0x465c6e` 取得目标位置，与角色 `+0x28` 相减，置差值 Y 为零，比较水平距离与 float32 `0.001` |
| `0x467579–0x467582` | 门禁 false 调用 vtable `+0x64=0x46e0e3`；true 改调用基础空间更新 `0x464fb3`，不更新履带累计值 |
| `0x46e0e3` | 先调用 `0x4654f1`，随后累加 delta 和 `+0x350`；比较使用尚未舍入的 x87 和，存储使用 float32 |
| `0x46e107–0x46e14c` | 和严格大于 `0x5c7e58` 的 float32 `0.1` 时，累计归零，索引为 `(旧索引+1)%2`；大 delta 也只切换一次，余量丢弃 |
| `0x46cec7` | 完整 render 对 X、Y 分别读取同一 `+0x354`，选择 `[+0x360,+0x364]` 并调用实际 `gbActor::SetTexture` |
| `0x46d329 / 0x46d352` → DLL `0x10009f70` | X/Y 两个 setter 都将所选纹理写到各自 actor `+0xa8`，然后提交 actor render |

前进目标 setter `0x4670de` 将 `+0xd8=0`、`+0x120=&actor+0xdc`、`+0x124=1`；后退 setter `0x467175` 同样创建目标运动，但 `+0x124=-1`。停止入口 `0x46495d` 将 `+0xd8=1` 并清移动向量。A/B 更新不检查前进/后退符号，也不检查动画动作编号。原门禁依据目标位置，不是用两帧位移或按键推断“正在移动”。目标距离达到阈值时门禁调用角色 `+0x70/+0x20` 后返回 true，该帧不切换。

`advanceRoleTrackTexture` 只实现已允许调用 `+0x64` 时的相位合同。调用方必须另有上述门禁来源。选定新皮肤入口设置 A，但没有重置 `+0x354/+0x350`；下一次 render 仍按当前相位选择。

## 验证

```sh
recovery/.venv/bin/python tests/role-track-texture-sol-native.py
```

结果 `PASS 7 actor tick scenarios, 70 XY phase/render steps`。证据为 `recovery/output/role-track-texture-sol-native.json`，逐步保留 delta、输入累计值/索引、实际输出、更新调用和两个履带的纹理提交。

执行完整 `0x46c483`、`0x46753f`、`0x4660a5`、`0x46e0e3`、`0x46cec7` 和实际 DLL setter。涵盖待完成前进/后退目标、不同输入向量、停止标志、缺失目标和已到目标；在每种状态下执行 0、两次 0.05、微小越界增量、0.1、0.10001、0.25 以及跨阈值连续 delta。检查可发现相等阈值误切换、舍入次序错误、大 delta 多次切换、停止清相位、左右履带不同步及 setter/render 脱节；其中任何差异都应修正相位实现或阻止错误门禁进入页面。

## 限制

完整空间运动/姿态设置及35/6原指令证据另见role-track-spatial-sol.md；网络姿态/全局时钟及死亡/Type4来源仍待恢复。

本相位测试供给基础空间运动 `0x4654f1/0x464fb3`、目标 getter、CRT sqrt、空附件表、矩阵栈和 actor render 边界，不验证完整空间插值、全局 delta 生产时钟及 D3D 绘制。测试中的“不同输入”仅改变方向和移动向量，未执行完整转向动作生产链。死亡是否调用停止入口、TankType4 的 vtable 和生命周期、页面目标插值与原 actor 目标运动的对应关系尚未验证，不能以页面动作名或每帧位移替代原门禁。
