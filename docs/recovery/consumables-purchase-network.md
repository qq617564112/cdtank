# 六种消耗品购买网络验收

2026-10-03验收通过：实际TSRPC服务出售源表ID1、2、4、6、7、8；六种道具分别金币购买1份、代币购买1份，形成12个独立实例。金币由1000扣至870，代币由1000扣至890。购买的大包饲料经自然CPU攻击后实际恢复43生命，符合 `min(400, 204 - 161)`，该实例库存由1减为0。实际停止并重启服务后，完整角色资料、12条库存、slot4和12笔请求重放账本恢复。

运行 `npx tsx tests/consumables-purchase-network.cts`。脚本在端口3163启动独立实际服务，使用临时SQLite库，结束时关闭自身服务并删除临时库。结果写入 `recovery/output/consumables-purchase-network.json`。

两个认证账户显式导入已拥有的宠物、坦克及角色资料，原生角色记录沿用 `role-owned-pair-native.json` 与饲料购买网络验收的夹具。购买账户金币、代币各1000；观察账户各9。两者初始道具库存和七槽快捷栏均为空。

验收覆盖：

- QUERY精确返回六条源记录，包含名称、完整说明、图标与两种价格。ID8的不对称价格分别扣40金币、20代币。
- 每次购买完整实例记录、余额与角色资料均精确核对，角色资料仅金币或代币字段变化。同参数重放不追加扣费或库存；相同请求ID改为其他道具拒绝。
- 未实现源表ID3、9及未知ID999999拒绝购买。余额各9的另一账户对六种道具的两种币种购买均余额不足，完整角色资料、库存和快捷栏保持不变。
- 普通创建房间、加入后保持WAITING。12个新实例分别通过真实Kitbag接口配置到允许slot4；认证入房间后的Inventory直接读取World投影，完整库存与七槽快捷栏精确匹配。RoomSnapshot不承载快捷栏，该断言使用实际Inventory投影。
- 金币购买的ID2重新配置到slot4，普通添加三个CPU和双方Ready后开战。双方人类保持静止，CPU普通移动与攻击自然造成损伤；真实PlayerInput `useItem: 5` 消耗该实例。两个独立客户端收到相同skill2、effect0、duration0事件，并收到相同tick的完整玩家快照；此次同tick为182。
- 一份大包饲料消耗后拥有数量、战斗数量均为0。重复输入序号及新序号再次请求该已耗尽实例均不追加使用事件或消耗。其余11条库存保留。
- 实际重启后精确恢复完整角色资料、完整库存及slot4；房间战斗数量投影恢复为0，持久拥有数量保留。12笔原请求全部重放原购买凭证且不改变恢复状态，12笔改道具请求全部拒绝。观察账户全程隔离，库存仍为空、余额仍各9。

ID4、6、7、8的实际作用、CPU消费和浏览器表现沿用 [攻击饮料](attack-drink-runtime.md)、[速度饮料](speed-drink-runtime.md)、[回旋饮料](turn-drink-runtime.md)、[无敌软星](invincibility-runtime.md) 的已完成证据。此次网络验收新增六种购买与持久化链路，并使用新购买的ID2完成普通战斗消费。购买ID2的两轮自然浏览器验收及效果资源验收见 [六种消耗品购买](consumables-purchase-runtime.md)。

## 限制

该脚本验证重建服务的购买、装配、实际回血、消费和持久化链路。浏览器像素、音频和源CAS有限生命周期由对应浏览器与效果验收承担；原始游戏服务器购买规则未由此脚本证明。
