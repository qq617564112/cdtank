# 原角色动态碰撞尺寸

原角色在创建、普通移动、预测、状态切换与复活位置重置中使用统一的49×24×52全宽OBB。当前共享运动、角色阻挡与出生占用采用的尺寸与该来源一致。车型定义与模型加载不另行写入这三个宽度。

## 字段与写入

`role+2b8`为`gbOBBox`：前64字节是姿态矩阵，`+40/+44/+48`分别为X/Y/Z全宽，对应`role+2f8/+2fc/+300`。原base构造器`431bcf`的`431d01/431d0b/431d15`写入float32的49、24、52。联网构造器`42275e`经`422770`调用该base构造器；正常创建点`422ea4/422ec8`分配并构造联网角色。

`433073`通过`gbMatrix4::SetAxisAngle`重建前64字节矩阵，并写中心的`+30/+34/+38`。位置重置`433112/43314a`、状态分派`433250`、普通运动`433190/435088`及预测`433d1c`沿该姿态合同处理，宽度保持。技能重算`433466`及已定位技能setter不写这三个宽度。

虚表`+6c`的`432107`返回`role+2b8`。角色接触`426b92`和静态接触`4272d7`将它作为`gbOBBox::operator=`的源，复制到局部OBB后查询碰撞。原operator=`10001580`复制64字节矩阵及后三个宽度；已定位的相关赋值没有以原角色OBB为写入目标。

`tank.dat`的30列没有碰撞尺寸字段。`LoadActorFile/GetCollideOBB`输出的是另一份局部模型碰撞盒，其加载与部件处理没有将模型宽度写入`role+2b8`。动态角色OBB与模型几何边界分别保留。

## 来源与验收

静态地址、宽度writer、别名复制和生命周期入口见`role-final-footprint-source.json`。既有构造器执行证据`movement-footprint-native.json`与碰撞内核证据`role-obb-kernel-native.json`继续保留原范围。本项未执行native、测试、浏览器、构建或类型检查；普通对局与完整原运动验收仍按M2-03追踪。
