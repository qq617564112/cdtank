# 宝物 CPU 客户端配置

## 可达范围

CPU 配给页的道具槽 5..8 只接入两个精确宝物 ID：20001 鱼骨和 20002 骨头。它们由真实道具目录记录进入下拉选项，不使用整类 category 6 放行，不自动分配，也不把账号库存或战斗库存默认给 CPU。

玩家仍沿用现有 CPU 道具配置流程：选择目标槽位、选择道具、录入数量，确认提交后由 authority 校验并返回确认结果；失败时保留原拒绝提示和未确认状态。槽 2..4 的弹药选择、槽位数量字段、待确认状态、已确认余量、更换角色和离开房间逻辑保持不变。

## 数量合同

普通 CPU 道具仍要求正有限整数，并且不超过该道具源记录中的 `battleUseMax`。

20001 和 20002 的源记录 `battleUseMax` 为 0，不作为 operator 可配置数量的上界。客户端对这两个精确 ID 显示并接受 `1..0xffffffff` 的正有限整数，作为真实库存表示范围；不新增 source 之外的每轮上限、免费赠予、自动分配或第二套控制项。

CPU 的地面拾取沿用同一资格：按真实已选 pet JSON `petType` 判定，猫 `PetType 1` 拾 20001、狗 `PetType 2` 拾 20002，错误种类或未选宠物不拾这两件且保留实体；其本局 local 库存不持久化。成功拾取按 `runtime.values.pickupHealing` 回血 15，与手动自用技能 30 分开。
