# 队伍聊天浏览器验收

最终PASS：四独立正常网页，13项检查与七截图，三名真人通过Ready进入PLAYING，九组pending禁用/恢复，专用服务/浏览器与临时目录全部清理。

运行 `node --import tsx tests/browser-team-chat.mjs`。脚本独占服务端 3187、Vite 5222、Chromium CDP 9292，并使用临时账户数据库和浏览器配置目录。

四个独立浏览器账户通过普通页面创建、加入房间。三个真人在同一团队房间，第四人在另一房间。鼠标点击原生频道选择器并用 Home、方向键、Enter 选择，输入框用普通键盘 Enter 发送。二进制 WebSocket 请求、响应和聊天事件使用实际服务协议解码。

验收内容：

- 队伍频道仅发给发送者和当前同队玩家；敌队及另一房间的日志与网络事件不增加。
- 房间频道发给当前房间所有玩家，另一房间不接收。
- 等待面板普通换队按钮提交 ChangeTeam 后，队聊立即按新队伍分发。
- 普通快捷设置保存 F5 后，等待阶段和开战后的 F5 均使用当前选择频道。
- 三位真人点击准备后进入真实 PLAYING，继续发送队聊和房间聊天。
- 频道选择器获得焦点时，移动、开火、道具按键不产生对应战斗输入；发送期间选择器禁用，响应后恢复。
- 离开并正常重新加入清空日志和草稿，频道恢复房间。
- 个人模式提交队伍频道收到明确服务端拒绝，保留草稿，不追加聊天日志或事件。
- 1920×1080 和 3840×2160 下检查聊天面板与输入、频道、发送控件的可见范围和间距，并保存截图。

证据位于 `recovery/output/browser-team-chat.json`、`.log` 和同名前缀 PNG。JSON 记录权威世界快照、请求和响应、各页面接收事件、布局尺寸及清理结果。脚本只读取 Battle 的资源就绪状态，未修改对局状态、房间、队伍、位置、生命或协议数据。结束时关闭专用服务端、Vite 和 Chromium，并删除临时目录。
