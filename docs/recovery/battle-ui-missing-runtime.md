# 战斗消息与结算展示

## 当前接线

`edtBattleInfo`与聊天共用`ChatEmotes`的原颜色、图片、表情和按像素换行。保留最近五条消息及现8秒透明度/hover恢复。击毁公告按本机队伍显示友方蓝色、敌方红色；本机击毁先显示连续击毁及实际积分，再显示公共击毁公告。昵称、道具名与称号名插入模板前转义`<`、`>`、`&`。普通命中和复活不挤占公告队列。

确认使用的道具事件带原表名称，只有使用者看到原`你使用了…`提示。弹药选择在服务端接受后产生`ammoSelected`，显示原`你将炮弹更换成…`。请求或拒绝不会生成成功消息。已定位的五类原公告模板583/584/585/586/591均已有消费者，本次未取得额外已证但未消费的原公告模板。

`destroy.killCombo`来自服务端`roundCurrentKillCombo`：实际敌方击毁递增、死亡归零、再战归零，独立于累计击毁和本局最大连击。第三字段大于1且本机存活时，击毁者显示原Combo数字与`zhandou00/2_baojixianshidanwei.tga`附图；文字保持原46/17偏移，沿既有一秒浮字生命周期。角色删除、换型、换局、离房释放对应记录和资源。

占领模式在真实Castle所在的11张地图加载原CAS碉堡，初始HP取模式表`BunkerHP`。实际扣除的敌方碉堡HP累计到`RoundStats.bunkerDamage`；己方碉堡及修复不计入伤害。结算占领列显示此值。占点计分仍沿当前项目规则；击毁碉堡未扩展为新的占领胜负规则。擒王列继续累计实际移除的敌方VIP HP。

结算使用原胜负大图、模式列头及本人绿色条目。`ResultPlayer.petId`冻结真实宠物，胜者每0.5秒轮换原yeah_1/2，败者/平局显示die。左右/底部面板0.7秒入场，玩家行间隔0.3秒入场，胜负图0.7秒缩放/位移，随后3秒滚分。实际九类`RoundAward`依次展示，每项2秒：中央奖项图按原0.9秒缩放/透明度曲线播放，获奖者行奖章按原0.4秒缩放曲线弹动，分数逐项加入实际奖项分。再以真实成长回执按每等级1秒演出经验变化。

四值奖励页0.2秒滑入，在3.2秒自动衔接`game_summary_title.xml`，逐个显示本局持久授予的新称号，采用原红色模板。每条0.2秒滑入、3秒停留、0.2秒滑出，自动进入下一条；Enter/Escape可提前跳过。最后奖励层1秒渐隐，保留最终名单与再战/退出入口；提示结束焦点回到结算页，换局和离房取消剩余定时器。

结算音效沿原阶段播放：面板UI35、玩家行阶段UI36、胜负图UI37、实际奖项UI30、升级UI31、降级UI39、四值奖励及每条新称号UI40。UI36在整个玩家行阶段入口播放一次；各行仍按原0.3秒间隔入场。颁奖背景UI38循环至成长阶段前停止，滚分与经验阶段逐帧请求短音UI29。音量取Battle当前运行值；重复快照、翻页及再战投票不重播，换局和离房停止声音。具体来源与网页调度见`battle-summary-audio-source.md`。

GM入口按原频道6提交客服问题。服务端核对当前房间角色与登录账户，将问题持久保存至`gm_requests`后向发送者返回原自动回复。问题和回复不广播给同房玩家；发送失败保留草稿。战斗、等待及普通聊天呈现共用此入口。

战场退出先向服务端取得权威报价，成功场景破坏计数>7时显示原593及实际可扣积分，否则显示829；确认后发送带报价金额的Leave并执行账户扣分，报价变化须重新确认，取消/Escape继续战斗，失败保留确认框。断线清理不扣分。结算经验条与HUD共用原图平铺、整数显示像素裁切及三段色消费者；动态文字保持用户选用的香蕉字体。采用规则见`battle-equipment-exit-melee-rules.md`，原来源及奖励通信身份见`battle-ui-exit-progress-source.md`。

Home/End在默认弹、已绑定弹药与槽2–4陷阱间切换，PageUp/PageDown在槽5–8选道具后立即请求使用。端点保持当前索引、不回绕；保留已配置零库存项，由统一UI28数量门禁拒绝，空绑定不生成owned实例。Ctrl主/备用保存与运行已接，新默认使用键ControlLeft，旧合法用户绑定保留。数字槽、HUD点击与切换共用权威请求，库存与成功消息沿服务端确认。普通页面/保存重启与高清实测仍待做，见battle-cycle-controls-runtime.md。

战斗提示音沿原四个调用消费GA01死亡倒计时、GA02 Fight、GA31本机射击后装填开始及UI28已确认数量耗尽。具体触发和生命周期见`battle-ui-sounds-source.md`。原`4d650b(28, 1)`是声音入口，数量耗尽由客户端已确认库存拒绝请求，不生成成功消息。

装备提示消费`game_summary_dialog.xml`的原图标和获得说明，本局新称号提示结束后先遍历已发放道具、再遍历已发放坦克；每条采用原横移动画，提示结束后奖励层渐隐。数据仅来自结算回执的实际拥有记录，见`battle-summary-equipment-source.md`。

协议保留既有字段编号，`ResultAward.grantedItems`(10)、`grantedTanks`(11)分别承载本局已持久发放的道具和坦克记录。道具记录保留实例ID、定义ID、定义名称及图标ID；坦克记录保留实例ID、型号ID和实例名称。既有`ResultAward.rankPointsBefore`(9)取账户事务内的实际旧积分，`MsgRoomEvent.killCombo`(22)、`destroyScore`(23)、`itemName`(24)、`RoundStats.bunkerDamage`(9)及宠物、新称号和VIP伤害字段继续使用。结算时序与常量见`battle-summary-sequence-source.md`。

## 限制

道具/坦克奖励回包证明服务器供应实际记录，未携带发放条件或概率；奖励显示与回执合同已接，结算事务已按battle-equipment-exit-melee-rules.md的采用资格/概率实际写入道具与坦克拥有记录。GM问题、operator单条回复、认证查询/推送及Web回复入口已接，实测待做。家族持久归属/operator、服务端路由及三页Web入口和收发消费者已接，实测待做；当前状态见battle-remaining-integration.md。

乱斗仅有一个`txtInfo`，原更新将CatsInfo与DogsInfo相加；CatsInfo由本机击毁覆盖，DogsInfo由公告+0x10提供；其上游生产者和乱斗业务含义未取得。当前按用户“DogsInfo参照CatsInfo”采用同一真实击毁链，分别累计本人击毁猫方/狗方坦克并相加，终局冻结、换局清零；采用规则见battle-equipment-exit-melee-rules.md，原来源见`battle-ui-remaining-source.md`。

原退出计数字段完整业务名和服务端事务规则仍无来源；当前已接原593确认与实际账户扣分，成功场景破坏计数>7后×100，权威报价与确认金额一致，详见battle-equipment-exit-melee-rules.md、`battle-ui-exit-progress-source.md`。循环和使用动作已接线，新增键位、选中圈和实际请求尚未实测。

名单入场、滚分、成长及音效时序已接线，原GPU像素、高清视觉及逐帧听感一致性尚未验收。此次仅静态代码走查，未运行测试、浏览器、构建或类型检查；M5-04/M5-05/M5-06与相关UI父项保持未完成。
