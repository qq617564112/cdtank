# 防御饮料首槽运行验收（M4-10-I05-B）

正常商店购买物件5、库存配置到Kitbag槽4后，普通Digit5经持久数量确认消费一份，添加技能5并重算属性，取得10秒防御提升。本人Autopilot和CPU经普通输入使用同一道具消费链。期限、死亡、结算与再战清除提升状态；再战和重入只装载剩余真实库存。

## 来源与重建边界

原物件5/技能5提供每局上限5、Trigger1、Target1、FuncType1、t10、Def30、DefBonus20。首槽PlaySkillEffect5的effectIndex0和duration0沿现有通知链执行；原药效10秒与首槽资源自然播放寿命分别处理。原属性累加、限制和setter保持现有实现，浮点0x7c与整数0x88在加技能前后分别重算。本验收拥有来源的防御值171.52999997138977→191.82999992370605，快照记录source=original-attributes和这两个实际值。

实际角色受击在既有弹丸伤害之后应用明确重建的增量减伤：`damage = rawDamage × clamp((100 + baseDefense) / (100 + boostedDefense), 0, 1)`。无完整属性来源时使用当前tank.defense及`float32(tank.defense × 1.3 + 20)`，快照标记source=rebuilt-tank。结束提升后恢复既有原始伤害。把两个原属性字段合成防御和上述受击公式均是重建解释，不声称恢复了原服务端伤害公式。

活角色、自用、16技能槽空位、技能5不叠加、数量CAS先于库存/技能写入，以及药效清理属于重建服务端资格与消费规则。自主策略优先治疗、无敌，再在HP不高于75%且500范围内有活敌人时选择已配置的防御饮料；策略只申请普通PlayerInput，道具权限仍由已有权威入口处理。

## 运行证据

- `tests/defense-drink-world.cts`和`recovery/output/defense-drink-world.json`：持久账户初始真实库存3、槽4→Digit5；普通手动消费1，原属性+技能重算与精确10秒恢复；CAS拒绝、保存异常、零量、初始满技能表和不叠加均不多扣量。随后本人Autopilot消耗剩余2、三CPU各有明确初始1份，普通输入完成两自然局；每个实际hit事件与攻击者既有`35 + attack × .08`及提升状态逐一比较，覆盖实际减伤、普通伤害、死亡/复活、结算/再战和零量重入。Store重开数量0、槽及原始位值保留，CPU再战也不补回。
- `tests/defense-drink-network.cts`和`recovery/output/defense-drink-network.json`：隔离3165真实TSRPC双客户端、SQLite和明确初始拥有角色/profile余额，库存从空开始；源商店20钱/20券商品5实际BUY3后钱1000→940，WAITING Kitbag槽4→本人普通Digit5。自然CPU命中造成受伤后施放，两端首槽通知、同tick防御快照、实际hit精确减伤及死亡清除后的普通伤害一致，并记录两端命中所在serverTime/tick、HP和提升状态；旧序号和不叠加不重复消费，数量3→2。实际服务重启后库存/配置/profile恢复，购买回执重放不发新库存，另一账户库存保持空。

所有对局HP、位置、伤害和结局来自正式输入、弹丸碰撞和自然结算。World私有读取只用于观测；显式库存、拥有角色与初始满技能表是测试起始夹具。网络服务由测试独立启动并在结束时关闭。

## 已知边界

原服务端完整FuncType1资格、成功消费和伤害公式尚无完整来源；完整第二槽业务入口保留原父项。World与网络验证权威业务和首槽通知，真实网页像素、资源几何和音频播放由相应效果及双网页验收分别提供。
