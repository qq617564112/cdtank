# CPU队友与自动对局

这是重建AI，不是已恢复的原客户端AI。房主在等待界面添加/移除CPU，CPU与真人共享PlayerState、地图/NAV/静态盒体、输入归一化、移动/转向、弹丸、装填、伤害、重生、目标、计分和结算。BotController仅产生普通MsgPlayerInput，不能修改HP、位置或终局。TSRPC Cpu请求带round和ADD/REMOVE，服务端限定房主/等待期/容量/实际战车ID；密码房CPU走内部成员创建，不绕过真人密码检查。

CPU自动准备；添加/移除/换队使真人重新准备。CPU再战票只在真人发起再战时提交，不会自行跳过结算；最后真人退出删除CPU房，避免后台空转。快照isCpu和cpuManagerId用于身份和控件显示。

行为：NAV八邻接A*与实际field.move确认路径，缓存静态边通行性；追击定期重规划，固定破坏目标保留可执行路线，由目标切换、移动卡住和无伤害反馈触发调整。按目标方向输出限幅turn/aim和move，原静态墙遮挡、友军射线阻挡时不射击。团队/混战追击敌人，擒王优先敌王，占领接近圈中心并交战；破坏新任务优先选择当前炮口射线能命中源盒体且早于静态障碍的原Breach。同样可射中的目标优先分工，只有同伴负责的目标可直接射中时允许协助；没有有效射线时寻找周围可通行射击点。目标选择、当前视线和本步转身/移动后的开火检查共用原盒体求交顺序。仍未恢复原技能道具、原AI策略、动态物件导航、战车互相阻挡和高级避弹/队伍配合；不可把一次达标当所有地图/CPU行为完成。

验证入口test:cpu为正常50ms世界步进、原人数/时限下CPU自主输入，测试时钟可推进，因此不代表实时性能。test:cpu:browser通过真实浏览器/真实服务端时间运行，用户只创建房、添加3CPU、准备、旁观、再战和退出，不发送战斗输入。原木桶广场混战实际106.518秒，CPU达到十次OBJECTIVE，成绩冻结、全部CPU自动再战、第二局满血/清零与退出通过；960×540/hardwareScaling3仍不代表高清性能。证据browser-cpu.json/png。

最终五模式World回归通过（cpu-match.json）：团队截止、占领/擒王/混战目标、破坏截止均含普通输入交战、冻结结果、真人一票触发CPU再战和退出。破坏实测71/117个原物件摧毁，416次开火/361命中；没有证明全清。团队此前一次目标胜利，最后一次随机重生下21次击毁后截止，目标终局不是每局必然结果。

真实密码房协议测试覆盖添加105CPU、非房主拒绝、旧round拒绝及移除；实际browser-cpu-room.json覆盖等待界面添加3CPU、移除1个/补回、CPU准备人数、房主管理身份及退出。下一优先级：26地图/模式的CPU可达性、真实实时团队/破坏自动目标终局、CPU卡住重规划/目标切换，再用1920×1080与多人客户端核对渲染帧率及同步。CPU自动对局不能替代真人键盘/鼠标交互、完整原AI行为或高清性能验收。

## 自动验证路线

CPU对局作为战斗回归的主要入口，正常输入经过服务端权威规则。按以下顺序推进：

1. 改善不可达目标切换、友军挡线后的站位和团队集火，复验团队次数耗尽、混战0017及破坏0020/0022的目标分支。截止结算仍单独记录；不改时限或降低目标要求。
2. 恢复原战斗数值、技能和道具，并为CPU加入相应的普通输入。原行为精度通过原指令／资源对照验证，对局脚本验证实际接入和生命周期；CPU能赢不证明规则正确。
3. 持续检查死亡、复活、结果冻结、多人一致结算、真人发起再战及退出。快速World推进覆盖地图，真实浏览器运行检查网络、画面和资源生命周期。
4. 单独验证真人键盘／鼠标操作、真实GPU高清性能和原画面一致性。精确特效恢复独立推进，完成后接入同一自动对局入口。

## CPU射击站位与失败路径
