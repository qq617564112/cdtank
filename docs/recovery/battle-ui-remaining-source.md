# 战场剩余来源：退出处罚、乱斗计数与装备奖励

本文只记录原客户端可直接取得的事实、代码接线影响和尚未取得的边界。读取
`current-exe.asm`、原 PE、已验证布局及表；未执行原代码、Unicorn、浏览器、构建、类型检查
或新取证脚本。

## 装备奖励显示接口

`game_summary_dialog.xml` 只有 `wndDialog`、`picItem`、`txtMessage` 三个控件。对话框原始矩形为
235,326–564,422；图标为 34,31–66,63，文本为 84,18–300,75。`wndDialog` 的九宫图集是
`lobby_ditu0`，图标本身没有 Image 属性，显示时由 `picItem` 按记录查表后设置图片。

### 字段与读取偏移

原结算消息 `UMsgFtGameOver` 的显示回包在 `0x4ac736`：

| 消息字段 | 容器语义 | 读取路径 |
| --- | --- | --- |
| `+0xe0` | 道具记录指针队列 | `0x4ac7b9` 读取 begin/end，`0x4ac39b` 把每个 4 字节指针复制到 summary `+0x2c` |
| `+0xe4` | 坦克记录指针队列 | `0x4ac7e5` 同样复指针到 summary `+0x40` |
| `+0xec/+0xf0` | 新称号队列 | `0x4ac811` 读取并复制到 summary `+0x54` |

`0x4ac39b` 把传入元素的首 DWORD 追加到 summary 队列；`0x4a8119` 取队列当前元素。原消息
`+0xe0/+0xe4` 的迭代步长为 4，队列元素是指向记录的指针；显示端 `mov edx,[eax]` 或
`mov eax,[eax]` 解引用记录。

道具 `+0xe0` 的元素属于库存记录的线合同（`0x42dddd`）：`+4` 是 `instanceId`、`+0xc`
是 `itemTableId`、`+0x10` 是 `ownedQuantity`、`+0x20` 是 `battleQuantity`；`+8` 的业务名
仍未定。坦克 `+0xe4` 的元素由 `0x42195e` 序列化：`+0x1c` 是拥有实例索引键、`+0x24` 是
坦克定义号、`+0x28/+0x2c/+0x30` 是纹理槽，名称字符串在 `+4`，`+0x18` 是 SSO 容量判据。该坦克记录
没有道具 `+0x10` 式的数量字段。道具分支 `0x4aa7ab`：

- `0x4a8119` 从 summary `+0x2c` 队列取当前元素；`0x4aa7b3` 解引用并读记录 `+0xc`，即
  `itemTableId`。
- `0x413c74` 取得全局游戏，`0x411068` 以该 ID 查原 Item 表；Item 表记录名称字段用于
  `txtMessage` 模板参数。
- `0x4aa800` 以 `+0x28` 的 SSO 容量与 16 比较：容量小于16时读取 `+0x14` 起的内联字符，
  否则 `0x4aa806` 从 `[表记录+0x14]` 读取堆字符串指针。显示名称来自 Item 表该 ID 的记录；显示链不读取队列元素的 `+4` 实例 ID、
  `+0x10` 拥有数量或 `+0x20` 战斗数量。
- 图标资源：`0x5cde00="daoju0"`，图片路径模板 `0x5cde08="data\\ui\\daoju\\%.5d.tga"`。
  `0x4aa85b` 用 `[表记录+0x4c]` 作为图片参数；`0x5cdde0="tanke0"`、`0x5cdde8=
  "data\\ui\\tanke\\%.3d.tga"` 则用于坦克分支。这里的 `%.5d` / `%.3d` 是图片编号，
  不是装备实例 ID。

坦克分支 `0x4aa998`：

- `0x4a8119` 从 summary `+0x40` 队列取当前指针；`0x4aa9c1` 以记录 `[edx+0x24]` 作为图片
  编号；`0x4aaa83–0x4aaa8e` 以记录 `+0x18` 的 SSO 容量与16比较，小于16时读取 `+4` 起
  的内联字符，否则从 `[记录+4]` 读取堆字符串指针，再格式化 `txtMessage`。因此坦克显示名来自结果记录本身，图片编号直接来自记录 `+0x24`；该分支
  不读 `+0x1c` 实例键，也不查 Tank 表名称或纹理槽。
- `0x4ac7b9`/`0x4ac7e5` 在初始化时把每个记录指针复制到独立队列；原始结果显示链不携带
  数量字段。对话框的一次显示只表示“获得了该记录”。道具显示项的名称来自 Item 表记录，
  坦克显示项的名称、图片编号来自结果记录本身。记录首 DWORD 在复制后不再用于名称或图标
  显示，不能从这个显示链反推数量。

### gamestring140 与显示时序

gamestring140 精确模板为：

```text
你获得了<colour red=255 green=0 blue=0 alpha=255>%s</colour>。
```

`0x4aa7ab` 的道具分支把 `Item` 表名称作为 `%s` 传给格式器，再把结果写入 `txtMessage`；
坦克分支 `0x4aa998` 使用同一 `gamestring140` 模板和结果记录名称。图标写入 `picItem`，
文本写入 `txtMessage`，随后把队列游标向前推进。

### 状态 9、两条队列与 UI40

- `0x4ac304–0x4ac339` 是结算状态 9 的自动推进块：若 summary `+0x504==9`，`0x4ac312` 先
  在 summary `+0x300` 动画对象上调用 `0x4738ef`。该函数是红黑树成员判断，不是队列耗尽
  判断；成员存在时跳过本帧推进。动画结束后清该对象并调用 `0x4aa78b`，显示下一项。
- `0x4aa78b` 在道具队列 `+0x3c` 为 0 时直接跳到 `0x4aa998`；坦克队列 `+0x50` 为 0 时
  返回 false，状态机推进到状态 10。两条队列是“道具优先，耗尽后坦克”的顺序。
- `+0x4ac304` 的推进块本身不要求 `+0x308`/`+0x304` 文本控件非空；状态入口 `0x4ab422`
  调用 `0x4aa78b`，返回 false 才切到状态 10。`0x4aab77` 到 `0x4aab92` 的尾部会清理本轮
  临时字符串和图片对象。
- UI40 声音在 `0x4ab3ab–0x4ab3b3` 播放，该调用位于状态 7 的四值奖励页入口，不是状态 9
  的装备奖励入口。装备奖励显示链本身没有独立的 UI40 调用点；当前结算音频只在四值奖励页
  请求一次 UI40，后续新称号在 `0x4aad11` 也复用 UI40。
- 状态 9 只在状态 8 的称号队列耗尽后进入，显示实际存在的道具/坦克记录；没有记录时不合成
  空奖励，也不进入额外显示。

### 原表是否提供发放规则

已核对的 `item`、`tank`、`dropitem`、五份模式表和 `datascale` 只提供定义、展示属性、货币/
成长倍率和地面掉落模型，没有给出战斗结束时向 `+0xe0/+0xe4` 生产记录的规则。`Item.GGet`
是展示/获取字段，`Tankshop` 赠品列属于购买记录，`DropItem` 是地面模型和金额区间，均不能
替代战斗装备发放条件。`0x436678` 的结束处理只调用
`0x436233`、`0x42721f`、`0x488693`、`0x43cd7e`，其中 `0x42721f` 做结束遍历/观察者转交，
没有在客户端选择奖励定义或计算概率。因此可确认的接口是“服务器结果消息已带实际记录 ID，
客户端只显示”；发放条件、概率和是否按胜负/奖章计算仍未知。

## 战场退出处罚

退出确认分支 `0x4cf8af–0x4cf9dc` 先取当前角色：`0x4cf8af` 读 global
`0x633588+0x118`，调用 `0x4269c4`。该函数按当前阶段索引取 `+0xe0` 阶段数组中的对象；
阶段对象 virtual `+4` 返回阶段编号。编号为 2 时返回阶段对象 `+0x40+0x20`，否则返回阶段对象
`+0x3c`。因此 getter 的真实 this 是当前阶段选出的角色/资料对象，不是固定的全局角色指针。

分支对返回对象调用 virtual `+0x18`，参数为 `0x15`：

- 联网角色 vtable 的整数 getter 链 `0x422b64` 对 selector `0x15` 直接返回
  `role+0x314`；其他 selector 转 `0x432417`。
- `0x432417` 的基础跳表没有为 `0x15` 提供额外字段分支；`0x422b44` 的另一条 getter 对
  selector `0x15` 读取 `role+0x2a0` 记录 `+0x10`，这是不同 getter 类/对象上的字段，不能与
  `0x4cf8af` 实际调用的 `role+0x314` 混用。
- `role+0x314` 在联网角色构造 `0x422790` 中初始清零，另一处初始化 `0x422bbd` 也清零；
  已确认的递增点是 `0x4247aa` 的场景对象消息处理 `0x424807`。对象存在、类型不为2且前置
  virtual `+0x48` 查询非空后，先调用 `0x44e081`，再直接执行 `inc [role+0x314]`，不检查
  `0x44e081` 的返回值。这与 `0x42912e–0x429136` 对本机击毁者
  `role+0x28` 的递增是两条不同计数链。
- `0x4247aa` 的输入记录来自场景对象消息，`0x44e081` 先按对象类型和字符串/属性检查；因此
  `+0x314` 的可证语义是“本机角色在非类型 2 场景对象事件中累计的属性 0x15 计数”。现有
  静态链没有给出它等价于击毁数、破坏目标数或退出扣分次数的证明。

确认逻辑在 `0x4cf8ca` 比较 getter 返回值与 7：大于 7 时构造 gamestring593，否则构造
gamestring829。gamestring593 的精确模板是：

```text
现在退出会扣除%d积分作为处罚，仍然要退出吗？
```

大于 7 的分支在 `0x4cf92a` 执行 `imul eax,eax,0x64`，把 getter 值乘 100 后作为 `%d`；
因此界面显示“扣除 getter×100 积分”。getter 值不是击毁数或时间，现有源码没有给出
`×100` 与账户扣分事务之间的服务端写入。

确认回调 `0x4ce1dd` 依次执行 `0x436233`（战斗状态清理）、`0x427109`（当前角色/战斗对象
结束处理）、`0x485735` 与 `0x485ef0`（离场/界面动作）。这条回调链中没有找到扣减账户积分、
写奖励流水或发送独立扣分消息的客户端调用。`0x4cf8af` 所在函数还有另一处相同确认分支
`0x4cfa9c–0x4cfbab`，逻辑一致。

因此可确认：退出确认使用当前阶段角色对象，selector `0x15` 读 `role+0x314`；值大于 7 时显示
处罚文案并把该值乘 100。当前证据不支持把 `+0x314` 命名为击毁数、破坏数或已证明的退出扣分数，
也没有确认确认后客户端会发送“扣分”通信。需要真实对局才能确定 `+0x314` 的生产触发和显示值
是否进入服务端扣分事务。

## 乱斗 DogsInfo

`game_main_info_melee.xml` 只有一个 `txtInfo`。原更新 `0x4cb6cb` 收到公告记录：
`+0xc` 是 `m_iCatsInfo`、`+0x10` 是 `m_iDogsInfo`；界面对象把两值暂存到自身 `+0x38`
与 `+0x3c`。模式 `esi+0x80==3` 的 `0x4cbad3` 分支执行 `[界面+0x38]+[界面+0x3c]`，再用
`%d` 写 `txtInfo`。初始化 `0x4d2d32` 只写 `CatsInfo` 到 `+0x38`。公告记录字段由
`bulletin-schema.json` 确认：`m_iCatsInfo` 为 `+0xc`、`m_iDogsInfo` 为 `+0x10`，
`m_iDogTankNumb`/`m_iCatTankNumb` 是不同字段。

原模式 3/4 的覆盖入口 `0x436307` 通过本机角色 virtual `+0x14` 读属性 0x0a/0x15：模式 3 读
`role+0x28`（本机击毁计数链 `0x42912e–0x429136`），模式 4 读 `role+0x314`（`0x424807`
场景事件计数）。读到不同值后写公告 `+0xc`；`+0x10` 保持原值。乱斗可见 `txtInfo` 因此是
“本机击毁覆盖的 CatsInfo + 公告 DogsInfo”，不是单一 score，也不是本地击毁数；第二加数的
在线生产者、初始公告、重连/补偿语义和结算使用仍没有静态来源。

当前按用户“DogsInfo参照CatsInfo”的要求采用同一真实击毁生产链，分别累计本人击毁猫方与狗方坦克，快照与冻结结果提供catsInfo/dogsInfo，乱斗txtInfo显示两数之和。这是当前项目采用规则，不是原DogsInfo在线生产者的证明，详见battle-equipment-exit-melee-rules.md。

## 当前采用实现

装备资格/概率与真实拥有事务、原593/829报价确认及账户扣分、乱斗猫/狗击毁同链计数均已接入；规则及接口见battle-equipment-exit-melee-rules.md。原来源事实与当前采用规则分别保留，新增实际到账、扣分、双端计数与页面演出未实测。

## 限制

道具结果记录提供 `+4` 实例 ID、`+0xc` Item 定义 ID、`+0x10/+0x20` 数量，坦克结果记录
提供 `+0x1c` 实例键、`+0x24` 图号、`+4/+0x18` 名称。显示链实际只读道具 `+0xc` 加 Item
表名称/图，坦克 `+0x24` 加记录名称；它不按数量决定显示行数，也没有携带发放条件或概率。
退出 `role+0x314` 的真实业务名和确认后扣分事务、乱斗 `m_iDogsInfo` 的上游生产者仍未知。
未运行测试、浏览器、构建、类型检查或 lint。
