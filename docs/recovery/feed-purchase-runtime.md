# 首件饲料购买与使用（M6-06-I01）

正式入口为大厅「道具商店」。查询服务器确认的物件1名称、说明、D2图标与ItemMoney/ItemCoin两列10/10单价；购买后通过「我的家」选定新增拥有实例并配置槽4，对局普通Digit5沿现有权威治疗链施放。页面属于重建入口，完整原商城26控件及204物件仍属于未完成父项。

`PtlShop`只接受操作、目录ID、数量、货币与请求ID。认证身份来自现有连接映射；服务器`accounts/shop-api.ts`限定物件1与原表字段，`accounts/shop.ts`用同一账户SQLite连接完成扣费、追加拥有物件和持久回执。请求不能决定价格、账户、余额或实例。无账户角色资料则不能支付；生产不赠送余额或物件。当前账户成长/奖励公式尚未恢复，新账户不能靠虚构奖励购买。

购买资格为已认证账户、已有角色资料、1–10份，以及不在房间或房间WAITING阶段；PLAYING及FINISHED购买拒绝。金钱和软星币支付选项、资格、上限、实例分配、初始未知字段0、不合并和请求幂等全部明确为重建规则。原GGet2不能据此解释为付款资格。完整原服务器商城权威入口与回包未恢复。

等待房间购买确认后同步账户库存和余额资料至现有玩家，并广播房间。新购买实例尚未配置，不改变现有战斗装备/部件选择，沿现有准备模块保留已准备状态；余额字段本身不是战斗装备来源。确实更改战斗来源仍由既有准备模块处理。这是明确重建购买接线规则，不声称原商城准备权限已恢复。失败和幂等重放不重复接入或变更库存。客户端只在成功响应后显示购买成功；未确认请求重试复用相同请求ID，变化数量/货币生成新请求。网络结果不明确时，应重试原请求确认购买；页面刷新后未确认请求ID未保留是当前明确限制。

支付用角色profile `+0x70/+0x74`已存余额；扣费保持其他字节与字符串不变。购买回执为历史收据，库存消费后重放仍返回原购买数量，当前剩余量须读Inventory。消费沿既有CAS事务，资格或持久失败不先改生命。原饲料自用/满血拒绝的权威规则仍属于M1-09-B重建范围，不能声称原M1-09/M1-10原因果已恢复。

验收入口：`npm run test:accounts:shop`（事务、资源消费与真实联机）及`npm run test:accounts:shop:browser`（正常双网页）。测试只预置显式已归属角色与余额，从空库存通过正式Shop购买；不得注入生命、位置、伤害或结局。各专项的实际结果记录在feed-purchase-{store,network,effect}及browser-feed-purchase文档和输出；只有真实闭环全部通过后才勾选任务。
