# 房间目录浏览器验收

M5-02-S 普通网页验收通过。真实服务器、Vite 和 Chromium 分别使用端口 3184、5221、9291；1920×1080 与 3840×2160 均通过原生鼠标和键盘操作排序、房间选择及密码输入。

执行：`node --import tsx tests/browser-room-directory.mjs`。

正常 WsClient 账户调用 CreateRoom 创建 R6–R10（混战 mode4/map7，最少 2 人，容量 2/4/6），保留系统 R1–R5；其他正常账户调用 Join 提供实际人数差异及满员房间。网页中的所有刷新、排序、选择和加入动作均由 CDP 鼠键完成。

- 默认 ID 按房间编号自然数升序，R2、R6 位于 R10 前；满员 R6 不可选择加入。
- EMPTY 先排可加入房间，再按空余位降序、人数升序、编号自然数升序；切换排序及刷新保留合法当前选择。
- 正常账户将已选 R7 加入至满员后，刷新将其禁用，并回退至可加入房间。
- R10 错误密码由服务器返回 `ROOM_JOIN_REJECTED`；页面保留大厅、密码、选择及 EMPTY 排序。
- 正确密码普通加入 R10 后，页面进入 WAITING；玩家身份与服务器 Join 返回值一致。
- 4K 页面可正常切换 ID/EMPTY 和编辑密码，保留所选房间。

证据：`recovery/output/browser-room-directory.json` 包含逐项断言结果、实际房间列表、原生页面状态与解码后的真实 WebSocket 请求/响应；同名前缀 PNG 提供 1080p EMPTY、密码拒绝、WAITING 及 4K 控件截图，`.log` 保存服务器输出。

空目录和全部不可加入的回退规则由房间目录纯专项验证。浏览器验收使用实际服务器房间目录。测试结束断开 fixture 连接、关闭独立进程并删除临时账户数据库及浏览器 profile。
