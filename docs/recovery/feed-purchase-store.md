# 饲料购买存储（M6-06-I01）

`AccountStore.shop → accounts/shop.AccountShop`接收服务器限定的table1商品目录。查询返回目录和现有角色资料的金钱/代币；无资料账户仅返回目录，不赠送货币或物品。购买要求真实账户、已导入角色资料、目录内物品、1–10整数数量、MONEY或TOKENS及8–80位ASCII字母/数字/下划线/连字符请求ID。目录提供单价，当前饲料源单价为金钱10/代币10；客户端不能提交价格。

购买在`BEGIN IMMEDIATE`事务内读取余额、扣减角色资料uint32LE `+0x70`金钱或`+0x74`代币、追加库存记录并保存购买回执。其余资料字节和两个字符串、既有库存字段、快捷槽和角色拥有记录保持原样。余额不足拒绝整笔购买。新记录数量为请求数量，战斗数量/状态/未命名字段均为0；不同购买不合并既有堆叠。实例ID取当前账户inventory与role_records共同未使用的最小正uint32值。这些是明确的重建存储规则。

持久ledger以`(account_id, request_id)`唯一。同一请求ID与物品/数量/货币相同，返回原购买回执及当前余额，不再次扣款或发物品；库存后来消耗不会改变历史回执。不同购买内容复用请求ID拒绝。已保存回执跨关闭重开恢复，目录变动不阻止原请求重放。不同账户的请求ID互不影响。

`npx tsx tests/account-shop.cts`验证金钱/代币各自扣款、无资料/非法输入/余额不足拒绝、新实例避开两类已有角色ID和库存ID、无合并、完整字节与未知字段保留、账户隔离、消费后重放、SQLite写入失败整笔回滚及真实Store关闭重开后的ledger恢复。失败触发器分别拒绝库存写入和最后ledger写入，证明扣款与发物品不会留下部分成功，失败请求可重新提交。

## 来源边界

目录价格来自table1；货币选择资格、实例分配、追加记录与请求幂等属于重建规则，不作为原服务器行为证据。该存储不实现赠送、角色购买、其他目录、GGet回包或货币奖励。
