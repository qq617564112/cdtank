# 地图渲染模型碰撞

服务端地图碰撞在资产构建阶段从渲染几何生成，并写入 `scene-collision/<地图编号>.json`。`scene-placements.json` 指定地形 GLB、物件 GLB/CVD 和实例变换，`battlefields.json` 提供出生点和原始 NAV 通行区域。运行时只加载预生成的三角面、AABB、空间格和 NAV 占用，不再读取 GLB/CVD 或按动画时间重建碰撞。静态地图射击碰撞不读取 `.box` 导出的虚拟包围盒。

| 对象 | 几何来源 | 参与规则 |
| --- | --- | --- |
| 地形 | 场景条目的 `terrain` GLB | 三角面射击碰撞、地面高度查询；垂直面生成导航占用 |
| Breach | 放置记录的 `asset` GLB | 完整模型三角面；销毁后严格超过 2000ms 移除 |
| General | 放置记录的 GLB 或 `animation.library/reference` CVD | 构建阶段固定首帧三角面 |
| Castle | 地图 2/5/6/10/11 的 `scene-castle-*.json` 中 `n1` GLB；其余场景使用放置资源 | 构建阶段固定 `n1` 首帧三角面 |
| Crush | 放置记录的 GLB | 启用且可见时参与；隐藏后立即释放；普通射击的高度无关查询使用三角面的 XZ 投影 |
| Plant | 原模型首帧摆动顶点形成的放置包围盒 | 固定首帧接触 OBB，沿用接触隐藏和可穿行规则 |

## 放置与判定

GLB 加载器在构建阶段读取节点层级、矩阵/TRS、POSITION、索引、bufferView/accessor 偏移及步长和初始 morph 权重。CVD 加载器在时间零读取变换轨道、父节点、顶点帧和分部索引。

物件放置采用记录矩阵的线性部分，平移替换为 `position`。记录矩阵原有的平移是包围盒中心，不能作为渲染几何原点。服务端保留原始坐标，网页显示时反射 X。

弹丸半径通过球体扫掠与三角面的两侧、边及顶点求交。128 单位空间格和模型 AABB 仅筛选候选，最终碰撞由三角面确定。零厚度薄墙正常参与，无额外厚度。地图 20 的所有 Breach 目标，包括 obj05434/05435/05436，采用同一规则。

导航占用由构建阶段模型首帧三角面与 12 单位网格的站立棱柱相交生成，棱柱高度为 NAV 地面上方 0.5 至 24 单位。地形只将垂直面计入额外占用；立面顶端不高于当前格地面加项目落脚限高 18 时，可作为低台阶跨越，不额外封路。场景物件仍按完整站立棱柱生成占用。角色保留原来的 49×52 足迹采样；移动路径补充不超过 6 单位的中间采样，CPU 路线使用相同导航占用。移动路径阻挡时保留原地转向；车体扫掠范围内的当前模型占用格合并为接触矩形，与其它坦克共用水平分离处理。让位另检查完整车体足迹和中心路径，受模型占用约束。可破坏物体的接触矩形随原有 NAV 占用一起释放或恢复。

0003 蛋糕南路的四座木桥由原 POL 的 `line712`、`line736`、`line737`、`line738` 网格提供桥面。导航导出时只投影各网格第一个分部的顶面 6..13 号三角面：格中心位于顶面内时写入模型 f32 高度，补齐原无效的桥面通行字段，并保留其它字段字节。栏杆、支柱不提供桥面高度。该修正在碰撞烘焙前完成，服务端和网页消费相同 NAV。

0016 仙剑岛秘密仙境的 12 座桥面由 `box10625`、`box10638`、`box10641`、`box10642` 至 `box10648` 的桥板顶面提供高度。其中 `box10641` 的第二个分部包含三座桥，其余桥板使用第一个分部。导出只校正原有效格中心的 f32 高度，所有通行字段、原无效格及桥外格均保留。桥板与栏杆分部独立选取，栏杆不提供桥面高度。

网页移动读取发布的 `data/maps/<地图编号>/movement.json`，每张地图包含原 NAV 和按原放置 ID 记录的阻挡格。`npm run assets:movement` 默认读取服务端 `battlefields.json`，地形和启用物件直接复用同版本 `scene-collision` 的烘焙占用格，写入 `art/hd/movement/<地图编号>.json`，再经 compressed 与 public 发布；`BATTLEFIELDS` 可覆盖 NAV 输入，`WEB_ASSETS` 可覆盖导出根目录。模型、放置或导航规则调整时先更新服务端烘焙资源，再导出移动数据。客户端只载入当前地图的数据，物体破坏、恢复及 Crush 显隐通过增减对应阻挡格处理；初始禁用的 Crush 按同一导航占用算法保留完整阻挡格供后续启用。

`assets:battlefields` 导出 NAV、木桥桥面修正和场景地形数据，同时保存 `art/hd/battlefields.json`；`assets:collision` 先同步 NAV 与场景记录、完成服务端碰撞烘焙，再自动执行 `assets:movement`。完整 `assets` 链路在场景、自定义地图等资源导出后执行该碰撞与移动步骤，使两者消费同一批 NAV 和模型。若单独更新 NAV，继续执行 `npm run assets:collision`，之后按 HD → compressed → public 发布导航与移动 JSON。

动态目标接管对应 `SCN:<placement>` 静态实例，使用目标业务 ID 返回命中。销毁释放动态碰撞及网格占用后，静态副本仍保持停用；下一轮目标恢复时重新登记。重叠占用通过现有网格引用计数分别释放。不可破坏的静态实例保持常驻。

普通模式和破坏模式的 Breach 到达重生时间后，先检查完整模型的烘焙导航占用格是否与任一存活坦克的 49×52 车身足迹重叠，车身朝向沿用角色 OBB。导航阻挡与高度无关，空中坦克同样占位；玩家、CPU 和托管角色使用相同规则。占位期间保留零生命、销毁时间和原重生期限，保持碰撞释放；所有坦克离开后在下一次规则推进中恢复生命并重新登记碰撞。

## 限制与验收

- CVD／GLB／Castle 和 Plant 碰撞在构建阶段固定首帧；动画仍由客户端渲染，不再逐帧更新服务端射击三角面和 NAV。破坏碎片不产生独立碰撞，Breach 破坏淡出期间保留主体网格。
- 0003 按模型桥面修正通行字段及高度，0016 只校正原有效桥面格高度；其它导航保留原始 NAV 通行边界和高度。新增模型占用按 12 单位格离散；解除模型占用不会把原 NAV 禁行区域改成可通行区域。
- 三角面碰撞不按材质透明度裁剪。没有发布渲染模型的物件不生成模型碰撞。
- 本次只进行集中源码走查，未运行测试、构建、类型检查或浏览器验收；地图实测和运行时开销仍待验收。
