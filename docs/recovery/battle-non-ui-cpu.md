# 战斗AI有限道具输入

## 来源与正式执行器

现有注射剂执行器解除burn、ammoSlow、radarJam和三类陷阱限制；AI异常识别同步包含radarJam。原物品/弹药定义、真实库存实例和快捷槽决定选择资格，使用仍沿普通MsgPlayerInput、权威请求与既有持久CAS事务。

有限弹药选择覆盖当前已接基础弹丸执行器的原category3物品2002–2021，排除普通2001和医疗2006；建筑目标跳过仅对玩家有后效的2007、2008、2010。该选择不扩大现有弹药技能语义。必须存活status2、当前2001、owned/battle两量均为正、真实槽2–4且有ready射击机会，不从目录授予2022/2023。

普通CPU配置链只接受共享显式名单：槽2–4可由物品类型3或4的弹药、武器和3001–3005陷阱填充，槽5–8可由12、13、502及已支持消耗品填充；数量仍限定为1到该项source BattleUseMax，20001/20002沿用显式uint32配置政策。目录载入不新增默认配给、购入或持久规则，未列入名单的物品不能自动获得。

## 采用决策

陷阱选择仅取真实槽2–4的3001–3005，并读取现trapPermission低字节门禁。根据可见敌人距离和普通撤退输入决定投放，附近已有有效自身陷阱时避免重复；自身身份由陷阱ownerId与actor.id判断，个人模式下同队他人的陷阱不会抑制投放。位置、模型、期限、扣量与触发仍由正式placeGroundTrap处理。扫把12只从槽5–8选择，使用现readTrapSweepRule/selectSweepTraps的实际范围和有效期资格；破坏模式mode4/5把其他参与者全部视为敌对，其它模式只把不同team且非ownerId的陷阱视为敌对。普通物品优先级和一次useItem保持，AI不直接修改世界、库存、生命或位置。

这些选择时机是明确Web决策，原AI producer未恢复。原表决定支持项目，现执行器决定实际效果与消费；医疗弹自动治疗策略和全部原AI不在本轮实现范围。

## 验收范围

本轮只做静态实现与集中走查；没有测试用例或测试、浏览器、构建、类型、lint、生成器、原生取证的运行结果。新策略的实际对局、双端及持久验收仍待对应父项完成。
