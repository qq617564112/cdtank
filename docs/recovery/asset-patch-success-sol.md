# M3-01 成功替换入包

32份下载运输文件可经CPKUpdate原成功入包主体替换现存条目；隔离归档重读的有效条目与原解码内容逐字节相同。成功路径执行原运输解密、压缩分派、空闲空间选择、排序索引插入/移动和归档数据/元数据写入。原CDTank目录未修改。

## 原执行链

测试先执行完整`42bf40`删除包装器，再从`42bc00`进入`42e000 → 42d4b0`，模拟更新循环的逐条替换顺序。`42d748`读取真实download文件加密字节，`438c50 → 43b330`原XXTEA逐指令解密。`435630`原过滤分派调用LZO压缩外部边界；测试用现有lzokay执行实际压缩，原返回判断/长度与状态写入保持执行。

`42d090`原排序索引分配/移动及空闲索引反向引用更新、`42d290`原空闲块选择、`430a30`原payload/文件名/文件信息写入执行。`430fa0/431040`保存头/容量索引到隔离bytearray。每份先复制现存111554805字节归档及原活/删索引，重建加载器的空闲索引数组；后续索引移动与改写由原代码执行。

小XML `game_main_chat_shrinked.xml`（17424字节）及DDS `imagesets_dds/gy0.dds`（1048704字节）先通过，随后对全部32份候选执行相同完整链路。原程序不比较内容摘要或跳过相同文件，测试也不添加这种规则。

## 隔离归档再打开

每次将原写入后的bytearray写成临时data.cpk并重新读取，独立解析持久化活索引：同CRC恰好一个有效条目，文件名及parent与原条目相同，按该新条目的原存储flags读取/解压payload，与原运输解码结果逐字节比较。然后将持久化头/索引重载入仿真对象，执行原`430d70`二分查找，确认同CRC返回该新活索引。

生成的是隔离临时归档，验证后自动清理；输出证据保留32条新索引、存储标记、原/压缩大小、原写入次序及原指令来源。暂存归档不作为网页最终资源来源；当前安装归档已包含相同内容，见asset-patches-sol.md。

## 边界与范围

供给CRT字符串/内存/内存池、系统文件/磁盘容量/文件时间、LZO压缩外部接口及debug栈检查；读取边界供给真实加密运输字节，写入边界写隔离bytearray。路径标准化和CRC取自本安装对应原条目。原压缩排除谓词仅排除mp3/bik/ogg（三字符串取自原程序），32候选均不属于这三类，测试供给false。最终再打开使用独立CPK格式读取及原CRC查找，不宣称执行完整gbengine CPK.Load/Open或Windows更新器UI。

成功样本没有触发原调试断言。失败入包会触发`bResult`断言（cpkcore.cpp line1248），UI选择/abort策略仍在外部边界；已取证的断言继续后错误位和旧条目不回滚合同见asset-patch-transaction-sol.md。原更新器没有在这条路径实现现代原子替换，复刻无需添加该保证。
