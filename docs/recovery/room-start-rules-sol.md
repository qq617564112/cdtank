# 原房间准备、取消与进入战斗信号

`tests/room-start-rules-sol-native.py`在Unicorn执行原`CDTank.exe`完整函数。输出`recovery/output/room-start-rules-sol-native.json`：1296条原按钮至原网络编码请求、48条完整准备确认链、12条角色属性通知、3条进入战斗通知，全部PASS。

## 按钮与原请求

原`RoomPanel/btnReady`保存到面板`+0x90`，`btnCancel`保存到`+0x94`。注册链`0x50fab7`/`0x50fb0c`分别绑定`0x50c0cf`/`0x50c0fb`；完整回调调用角色服务`0x426e02`/`0x426e96`。

| 请求 | 原完整函数的发送条件 | 消息构造与类型 |
| --- | --- | --- |
| 准备 | 当前场景状态为3；本地角色存在；角色虚方法`+0x3c`返回0；角色状态不是1；`0x4353b4`返回真 | `0x4255ce`，`0x3aaf` |
| 取消准备 | 当前场景状态为3；本地角色存在；角色状态为1 | `0x425624`，`0x3ab0` |

基础角色vtable为`0x5c41b8`。虚方法`+0x3c`实际是`0x43291e`，只有角色记录`+0x2a0`、角色字段`+0xa0`和`+0xa4`均非空才返回0。状态读取`0x43293d`从角色记录`+0x90`取值，无记录返回0。

`0x4353b4`要求房间服务`+0x28`存在，随后读取其`+4`房间数据的模式`+0x38`。模式值3直接通过；其余模式要求角色记录存在且角色属性`0x11`大于0。基础角色的属性`0x11`来自记录`+0x5c`。因此模式3可以在该属性为0时发准备，模式1和4的相同输入被拒绝；属性1、2均通过。这条原函数没有人数、房主、所有成员准备、两队平衡或最少人数判断。

请求经原`0x413e8c`写入身份字段，再执行`0x402350`、`0x402090`及原位流编码。身份fixture为`0x1234`时，socket边界收到准备`af3a341200`、取消`b03a341200`；两个消息没有额外业务载荷。测试仅供应socket发送函数，消息构造、类型虚方法和编码均执行原代码。发送后角色状态与按钮未改变；原请求并不自行确认准备。

## 准备确认与服务器属性来源

原角色属性观察函数`0x42f385`在当前场景状态不为1、角色ID解析成功、属性通知tag为`0x1b`时，读取角色状态。状态0、1、3分别进入原生命周期分发`0x4259ae`；测试执行状态0、1的完整观察函数。消息`+0xc`用于角色ID解析，tag来自属性通知对象。这里消费已经更新的角色记录；不是独立的准备响应消息解码证明。

`0x4259ae`对状态0执行原虚方法`+0x44`，状态1执行原虚方法`+0x48`，写角色记录状态并调用记录观察者，随后通过角色服务`+0x60`通知`(角色指针, 准备布尔值)`。面板注册`0x50f89f`绑定确认函数`0x50e877`；不是把角色指针当作角色ID。

完整确认函数的结果：

- 在面板角色树中按节点`+0x10`角色指针查找，找到后更新节点`+0x1c`准备字节。
- 本地角色确认准备时隐藏Ready、显示Cancel；取消时显示Ready、隐藏Cancel。其他角色的确认只更新名单，不切换本地按钮。
- 本地角色节点存在时将节点`+0xc`槽索引保存到面板`+0x38`。
- 准备时禁用当前所处队伍的对侧按钮；取消时模式3、4不执行这项重新启用，其他模式启用。面板`+0x40`为0时作用于`btnDogTeam`，为1时作用于`btnCatTeam`。
- 最后刷新房间名单。记录观察发生在按钮可见性改变前。

测试供应记录观察者、CEGUI显示/启用函数和最终名单绘制；完整状态写入、旗标清理、面板树查找与按钮条件均执行原函数。

## 进入战斗由原通知驱动

`0x42be1d`注册`0x427189`作为`UMsgPrRCNotifyViewBattle`处理器，原名称位于`0x5c3adc`。完整处理器读取消息`+0xc`：等于1时调用场景切换到状态4，再遍历角色列表，将各角色置为状态2；其他值不执行这项场景切换。它同时将角色服务`+0x39`置1。测试在原空角色列表执行整个处理器，覆盖结果0、1、2，验证只有1触发状态4；角色列表非空的战斗生命周期另有`respawn-rules-sol-native.py`证据。

## 恢复边界

已恢复的是客户端准备/取消权限、原请求编码、角色属性准备确认，以及原服务器通知进入战斗的处理条件。原Ready回调没有房主Start分支；不能把同一个按钮推断为独立的房主开始请求，也不能从客户端请求缺少人数检查推断服务器不检查人数。原服务器可执行文件与接受准备后触发战斗的规则尚未取得，房主启动权限、最少人数、全员准备、队伍平衡、启动倒计时和拒绝码未由上述证据确认。

原面板初始化`0x50f555`之后的路径显示Ready、隐藏Cancel；这是初始化源代码定位，完整面板初始化未在本测试执行。当前重建应由权威状态决定准备、取消和进入战斗，任何另加的房主Start或人数政策应明确属于重建政策。
