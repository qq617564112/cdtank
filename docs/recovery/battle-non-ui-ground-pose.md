# 战斗视觉车体 NAV 坡面

## 高度直接来源

`NavigationGrid` 直接保留原 NAV v2 每格 f32 高度与四个附加字节；`sample` 使用原 `0x433f92` 的 f32 `1/12`、向零取整和 `width * z + x` 下标，`valid` 使用附加字段低字节大于 1。查询证据见 `navigation-format.md` 与 `role-movement-real-nav.md`。贴地与坡面使用独立的项目方法 `groundHeightAt`，在原有效格子中心之间双线性插值；动态碰撞占用不改变地形采样值。原 NAV 字节、通行边界与碰撞占用数据保持原有来源。

## 视觉采用规则

`BattlePlayers.render` 在权威 `bodyYaw` 与物理 Y 更新后，按当前插值显示的根节点水平朝向设置视觉根节点 pitch/roll。当前运动构造尺寸为 49×52：前方/后方沿源车体前向各采样 `52 / 2`，Babylon 根局部 +X 对应源 `(-cos(yaw), sin(yaw))`，两侧各采样 `49 / 2`。五个高度点使用连续采样；中心不通行或没有高度时回到平面，某一侧没有原有效高度贡献时只用中心高度补该点。侧面物件占用不把整车姿态重置为水平。车体实际显示 Y（本机为 local pose 物理/插值 Y，其余为快照插值 Y）高于同一连续采样面超过贴地容差 `0.5` 时直接回到平面，使下落、腾空或跨落差经过坡面时不会仍按地面坡面倾斜；离地归平只用本人显示 Y，不借用对方权威 Y 顶替。角度按两端高度差与完整尺寸计算，不设未知最大坡度。

根节点继续使用 `rotation.y = -bodyYaw` 保存原 X 反射后的车体水平朝向；pitch/roll 影响渲染车体及其子节点世界变换，电脑炮塔跟随相机继承该姿态，手机独立水平朝向相机跟随炮塔位置，见[战斗相机](battle-camera.md)。本坡面角不回灌移动、炮塔水平 yaw 或命中 authority。物理 Y、重力与地面接触由共享 `tank-vertical.ts` 单独处理（见 `battle-vertical-physics.md`）。死亡、换车和再战走平面或新根节点，不保留旧坡面角。

## 原物理缺口

原 `0x433190`、`0x433073` 之后的完整垂直后处理、gravity、各车最终 OBB 尺寸或原始斜坡物理仍未取得。垂直运动已按明确项目采用规则接入（`tank-vertical.ts`），不是原垂直 physics 等价实现；坡面姿态是视觉采用规则，物理 Y 由独立垂直步负责。
