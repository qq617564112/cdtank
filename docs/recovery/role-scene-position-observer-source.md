# 原角色场景坐标观察者

`424be9` 将角色当前位置与朝向交给正式注册的二维角色标记消费者。原 `428348` 收到 state0 后调用它；状态2生命周期及安装新观察者后的已有角色回放也进入同一入口。此证据为来源与参数合同，尚未接正式网页。

## 执行合同

入口先要求 `owner+c4` 观察者存在，再要求角色参数存在，随后要求全局场景 `635830` 的 `+60` 查询对象存在。全局场景本身由原运行环境提供，该入口没有空场景门禁。

有效路径依次为：

1. 原 `431fff` 复制 role+25c 的三个 float32 位置分量，保留Y。
2. 场景查询对象 virtual+18 接收位置指针与两int32输出指针；该坐标算法由provider供给，本片不把它假定为世界X/Z取整。
3. 角色 virtual+14 读取 selector18 的signed32朝向角。
4. 原x87将角乘 float32 `5c2864=0.008726646192371845`，写为float32弧度参数。
5. `owner+c4` virtual+8 接收角色指针、场景两int坐标指针和弧度。

`tests/role-scene-position-observer-native.py` 执行完整 `424be9` 与原位置getter，五条件通过：三个缺provider/角色门禁，以及180与-90角的有效通知。测试验证实际调用顺序、原Y保留、坐标provider输出不变及signed32/x87→float32数值。查询算法、朝向getter和终端观察者为显式供给边界；不冒完整原场景查询或显示验收。

## 正式注册与消费者

| 入口 | 原作用 |
| --- | --- |
| `4d4428→4cd952` | 创建绑定context与函数`4cc791`的回调对象 |

| `4d4455→4277f8` | 安装owner+c4；释放旧观察者后遍历owner+10原角色树，对已有角色逐个调用`424be9` |

| `4259ae` status2 | 已有复活通知合同中的同入口，复用旧状态来源证据 |

`471684` 查找显示对象的角色条目，读取关联对象+20/+24尺寸、场景virtual+30四int范围与全局635824/635828。其矩形运算按场景长宽比较分支、使用0.5居中；最终提交条目+74矩形，并把收到弧度加原float32 `61ea68=1.5707950592041016` 写到条目+84。原192常量参与目的框初始化。此为静态已定位的真正显示消费者，不将192解释成当前网页固定布局，不将该常量推成地图比例。

## 限制

场景virtual+18的坐标转换、virtual+30的范围生产、角色条目的建立/context+2c资源归属及`471684`完整矩形数值尚未连续执行。需要恢复这些provider后才可形成小地图显示接线合同。当前不请求World/Web/socket接口，不改变玩家键位、出生、位置权威或服务器生命周期。

证据为 `recovery/output/role-scene-position-observer-native.json` 与 `recovery/output/role-scene-position-observer.disasm.txt`。五条件首次运行检测入口门禁、顺序、Y丢失和角宽度错误；差异应修正本参数合同，不改正式玩家数值。既有3aa6 codec、生命周期及分离证据直接引用，不复跑。
