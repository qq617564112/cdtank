# 房间目录分页浏览器验收

M5-02-P 使用独立真实服务端、Vite 与 Chromium（3188／5223／9293），通过原生鼠标和键盘完成 1920×1080、3840×2160 房间分页与正常加入。

执行：`node --import tsx tests/browser-room-pagination.mjs`。

正常账户 CreateRoom 创建 R6–R30，与系统 R1–R5 形成 30 房、每页十房、共三页。R21–R30 由另一正常账户 Join 至满员；不注入战斗或房间状态。

- ID 全目录排序后分成三页，第一页上一页、末页下一页禁用；原生按钮前后遍历准确页号与十个房间。
- 第二页原生选择 R20；错误密码服务器拒绝，保留第二页、所选房、密码草稿与大厅状态；刷新保留合法选择。
- 第三页十个房间均满员，所有选项禁用，选择为空且加入禁用，不跨页选择其他可加入房。
- 切换 EMPTY 后，全目录先排序再分页并返回第一页；刷新维持当前排序。
- R21–R30 的正常账户断开后删除最后十房，第三页缩至第二页。所选 R19 房主断开后，当前页选择合法房回退；保留 R20 并删除前面的十房，刷新跟随 R20 到第一页。
- 4K 原生上一页／下一页遍历三页，边界与房间内容准确；分页、排序与房间控件可见。正常编辑密码、选择房间后，在 1080p 点击加入进入 R20 WAITING，身份与真实 Join 返回一致。

证据：`recovery/output/browser-room-pagination.json` 保存逐项断言、实际房间状态、解码 WebSocket 请求／响应、隔离和进程清理结果；同名前缀 PNG 保存 1080p 跨页密码拒绝、全满末页、WAITING 与 4K 翻页及控件；`.log` 保存服务端输出。结束后关闭所有 fixture、独立进程并删除临时账户库和浏览器 profile。

实际服务器始终保留五个系统房间，空目录 0 / 0 与禁用状态由分页规则专项验收覆盖，不声明真实浏览器空目录。页码与刷新保留语义为重建规则；本验收不替代原十张房间卡片及原收发回调恢复。
