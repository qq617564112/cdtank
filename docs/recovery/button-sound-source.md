# 按钮点击音来源与接线

界面按钮有效操作时播放原版 `UI01.wav` 一次，使用当前音效音量。覆盖启动页重新载入、横屏提示、登录、大厅、房间、我的家、商店、设置、聊天及结算页，包括原生按钮、勾选／单选控件、登录页木牌链接和键位设置入口。战斗场景只在计分板、聊天入口按钮点击时播放，其他战斗控件不播放按钮音。禁用按钮和被控件取消的点击不播放。

鼠标、触屏及原生键盘激活共用 `click` 入口；登录、昵称、购买、出售、大厅与物品列表等自定义 Enter 操作显式触发同一声音。

## 原版来源

- `CDTank/CDTank.exe` 的登录设置回调 `0x4bfefe–0x4bff2b` 在 `0x4bff02`、`0x4bff08` 分别压入播放次数 1 和声音 ID1，`0x4bff0d` 调用 `0x4d650b`，随后执行设置动作。该按钮的事件订阅见 [登录设置入口来源脚本](../../tests/evidence/ui/login-settings-entry-source.py)。
- 等待房间退出回调 `0x50c165–0x50c18e` 同样在 `0x50c168`、`0x50c16e` 压入 1，在 `0x50c171` 调用 `0x4d650b`，随后请求离房。控件到回调的绑定见 [等待房间退出来源](waiting-room-exit-source.md)。
- `0x4d650b–0x4d6524` 将参数直接传给 `0x4859d1`；后者在 `0x485a27–0x485a2a` 将原声音 ID 传给 `0x4178c9` 查表，没有技能声音编号偏移。
- 直接读取原 `CDTank/Data/table/musicstring.dat`：ID1 的 `String` 为 `UI01`。原 `CDTank/Data/sound/UI01.wav` 为双声道、22050 Hz、约 0.086485 秒；现有 `/manifests/audio.json` 将 ID1 指向 `/assets/audio/sfx/UI01.wav`。

## Web 接入

`audio/button-sound.ts` 使用已有音频目录、静态资源缓存与共享解码缓存预载原 WAV。`main.ts` 在加载页及横屏提示出现前安装全局声音实例，并从已保存设置恢复初始音效音量。

全局捕获 `click` 后，在当前事件处理结束时检查 `defaultPrevented`，从而覆盖会停止冒泡的按钮，并沿用共用按钮对拖出释放的取消规则；指针点击同时检查按钮边界。点击回调将按钮设为忙碌或卸载按钮时，仍保留此次有效点击的声音。木牌链接及键位输入通过 `data-button-sound` 标记参与点击入口。

自定义键盘动作通过 `playButtonSound` 调用同一音频实例。`App` 按当前对局的 `PLAYING` 阶段同步战斗限制，全局点击入口在战斗中只接受计分板和聊天入口上的 `data-battle-button-sound` 标记，自定义播放入口在战斗中静音。阶段切换和页面卸载同步清除限制。

`Battle.setSoundVolume` 通过 `setButtonSoundVolume` 同步更新增益，音效 0 为静音；离房与切页保留按钮声音，页面 `pagehide` 时移除交互监听、停止声部并关闭音频上下文。原生鼠标、触屏及键盘交互使用已有音频恢复监听；首次点击遇到挂起上下文时，恢复后播放该次声音。

## 限制

上述原始来源通过静态反汇编和直接读取原表确认，支持 ID1 的按钮点击用途；统一覆盖 Web 按钮属于本次接线范围。声音尚未载入或载入失败时，按钮动作照常执行。未运行测试、浏览器验收、构建或类型检查，未作听感一致性结论。
