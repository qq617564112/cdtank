# AI 训练

训练主机为 `192.168.10.179`，GPU 为 RTX 2080 Ti（计算能力 7.5，驱动报告 22528 MiB 显存）。游戏模拟在当前开发虚拟机运行，通过 `http://192.168.10.140:40101` 提供服务；训练主机仅执行 CUDA 模型训练和评估。历史数据、训练依赖与缓存、训练日志和模型全部保存在 `D:/ai/cdtank`。Python 使用该目录的虚拟环境，复用主机已有的 PyTorch 2.3.1+cu118。

## 数据来源

账户数据库 `match_history` 只保存结算，没有逐帧操作。`scripts/learning/export_history.py` 以只读事务读取数据库，根据房间、回合、地图、模式、结束时间关联 `state/cpu-traces/*.ndjson*`，选择最后采样距结算不超过 3 秒的进程会话。导出仅保留结算参与者中标记为 `HUMAN` 的状态与普通输入，不导出账号、令牌、凭据或显示名。托管 `AUTOPILOT` 和脚本 `CPU` 不作为真人标签。

历史轨迹约每 500ms 在模拟推进后采样。它不能提供按键发生前的完整观察；初始模型使用当前自身状态预测下一采样点的移动、转向和炮塔操作，作为动作习惯先验。训练不从这些记录推断未记录的视线、道具效果或子弹。整场比赛划入同一个训练或验证集合，连续死亡、控制切换及采样间隔中断处切断序列。

历史 `HUMAN` 标签表示未启用托管，不包含客户端是人工操作还是自动脚本的来源证明。数据文件保留这一来源标记。

2026-10-17 的导出读取到 101 个结算回合，关联到 36 个轨迹会话，其中保留 4966 个真人标签采样点、4646 个存活采样点。其余 65 个回合没有符合时间匹配条件的轨迹。

## 模拟与模型接口

`scripts/learning/simulation-server.mjs` 在开发虚拟机监听 `0.0.0.0:40101`。每个训练连接拥有独立 Node 模拟进程，连接关闭时销毁对应进程。`environment.ts` 创建真实 `World`，注入固定时钟和按种子生成的 `Math.random`。模拟每次推进 50ms，模型每 100ms 模拟时间提交一次普通 `MsgPlayerInput`，按请求推进，无需等待真实时间。训练进程不连接账户库，不写线上库存或战绩。

`GET /health` 返回服务、协议版本、源码提交、Node 版本及活跃世界数。训练端为每个世界保持一个 HTTP 连接，向 `POST /environment` 发送一个重置或动作 JSON，收到对应结果后才发送下一个请求；同一连接不能并发提交两个动作。请求与环境内部的逐行 JSON 内容相同：

```json
{"type":"reset","seed":179,"mode":4,"mapId":7,"players":2,"controlled":1,"lesson":"navigation"}
{"type":"step","actions":[[2,1,1,0,0]]}
```

动作有五个离散头：移动 3 类、车体转向 3 类、炮塔转向 3 类、开火 2 类、道具槽位 0–8。前三类按 `0/1/2 → -1/0/1` 映射。输入资格、库存扣量、碰撞、弹道和结算继续由现有战斗实现执行。

`World.learningFrame()` 返回 schema 3 的 160 维观察和动作掩码：自身状态与上一动作、局部 NAV 探针、可见敌人与队友、可见弹丸、公开模式目标、模式身份、库存槽位和练习路点，以及武器与射程特征。最后三维为路点方向的归一化横纵分量和距离。敌人经过 2500 单位的观察距离、场景视线和隐身状态过滤；观察范围覆盖普通与远程弹药的射程边缘。奖励统计与观察分开，策略不能读取它们。

自身射程按实际弹药的 `runtime.range × shotModifiers.rangePercent / 100` 读取，包含当前技能和装备的加成。普通弹药的基础射程为 1000；2023 弹药的 FuncType23 为 200%，实际射程为 2000。额外特征包括瞬发/弹丸类型、弹速、穿障、装填、弹量、目标距离与射程的比例、射线是否可达及准星是否选中目标。可达性复用真实 `queryShotTarget`，参与查询的角色仅包含已感知角色。敌方弹药从可见敌人在可见位置发出的真实 `fire.skillId` 记录，以公开弹药定义估计射程；开火后的自动换弹或手动选弹不改变已观察弹种，不读取对方隐藏的装备修正。

移动课程按 `level` 分级：0 为朝向前方约 ±9°、60–120 单位的直行；1 为前方约 ±46°、60–160 单位的转向；2 为任意方向、60–240 单位的直达路点；3 为 200–500 单位内需绕障且存在 NAV 路径的目标。候选路径使用实际战车的 NAV 采样尺寸检查。移动课程关闭炮塔、开火和道具，直行课另关闭转向，以距离进展、对准、到达和受阻情况计奖励；到达或 15 秒结束练习，绕障限 30 秒。

`turning` 将原地转向独立训练，关闭平移、炮塔、开火和道具。0/1 级目标方位分别为约 ±23°/±46°，2/3 级为任意方位；航向误差小于 0.08 弧度并连续保持 0.5 秒才算成功，单次限时 10 秒。它为移动转向提供初始参数，后续移动仍由策略自己选择操作。

`aiming` 固定车体，0/1/2 级依次覆盖前方 ±14°、±46°和任意方位的静止靶，3 级使用往返移动靶。0 级目标为 150 HP，其余为 600 HP；单次限时 20 秒。该课程先训练瞄准，再由 `shooting` 开放车体运动与对射。

`shooting` 课程 0 级固定车体，练习瞄准与击毁 90–150 单位内的 150 HP 靶；1 级开放移动和转向，对付任意方向的满血静止靶；2 级对付往返移动靶，3 级对手同时瞄准还击。`dodge` 课程由练习对手瞄准射击，关闭学习者的炮塔、开火与道具，以存活及减少受伤计奖励。练习靶通过 `World.placeLearningActor()` 设置初始位置和 HP，检查地形及战车重叠，并清除初始出生保护；后续运动、子弹、装填和伤害均使用普通战斗入口。导航练习的成功定义为进入目标 20 单位内；射击为击毁目标；躲避为 15 秒未受伤。

`combat` 课程使用正常 60 秒对局，以实际伤害、击毁、死亡和胜负计奖励，模式 2/3/5 分别加入堡垒伤害、VIP 伤害和目标摧毁数。

`range` 课程 0 级从自身射程的 105/112.5/120% 处接近，1 级从 35/45/55% 处后撤；两级关闭转向、炮塔和开火，要求在 75–90% 的距离带内连续保持 5 秒。练习通道由地图出生点、每 5° 的方向和起始距离生成，筛选完整接近/后撤路径、战车 NAV 足迹和双方视线后缓存，按回合种子选择。2 级在射程边缘练习瞄准击毁，3 级对手还击；两级仅以击毁事件发生时双方处于该距离带的击毁作为成功和击毁奖励。射程课分别记录普通击毁、距离带内击毁 `rangeKills`、距离带停留时间、距离带内射击数和射程外射击数；奖励距离控制和有效射击，对射程外的实际开火计成本。`--ammo-id 2023` 使用普通库存与选弹入口获得远程弹药；地图需要容纳相应射程。

`train_motion.py` 使用 64 维 GRU 和三个动作头。`train_combat.py` 扩展为 160 维观察、64 维 GRU、五个动作头和价值头，继承动作先验，以 recurrent PPO 训练。先前 128/157 维课程的参数通过 `--weights` 迁移，新增输入列置零，再由后续课程学习。回合结束和死亡清理记忆；PPO 以 32 步序列优化，保存优化器、训练步数、配置和检查点。相同观察维度的续训通过 `--resume` 加载参数及优化器，模拟从新种子回合开始。

射程课程以重置时所选弹药的有效射程固定练习距离带。特殊弹药耗尽后关闭后续开火，已发出的最后一发仍可完成带内击毁；自动切回普通弹不会改变这次课程的成功判定。观察继续报告当前实际弹药，日志另存 `currentWeaponRange`。

射程带内/带外射击按每个 50ms 模拟步的实际 `fire` 事件位置统计，命中选取沿用事件的 `targetId`。带内击毁按真实 `destroy` 事件的位置统计。它们分别衡量开火选择与击毁结果。

## 运行

远程基础 Python 环境：

```bash
python3 scripts/learning/remote.py scripts/learning/setup.ps1
```

数据导出支持将压缩流直接通过 SSH 交给远程 `receive.py`，无需在本地保存新增数据。`python3 scripts/learning/sync_trainer.py` 将已提交的训练脚本及文档流式传到 `D:/ai/cdtank/data/trainer-<提交前12位>.tar.gz`，解压至 `D:/ai/cdtank/trainer`，包内 `source.json` 记录训练端源码。179 的训练不再启动 Node 世界或加载场景资源；已有 `game/` 和历史模拟归档保留。

本机模拟服务从固定提交的独立 detached worktree 运行，避免开发工作区更新后，新建世界与服务记录的源码提交不一致。当前模拟版本为 `18524d48b6bbb535f40a68de0cf0b551ec85289e`，目录为 `/workspace/worktrees/cdtank-simulation-18524d48b6bb`。该目录独立复制 `apps/server/resources`，通过 `node_modules` 链接复用本机已安装依赖。

准备并在固定目录启动服务：

```bash
git worktree add --detach /workspace/worktrees/cdtank-simulation-18524d48b6bb 18524d48b6bbb535f40a68de0cf0b551ec85289e
ln -s /workspace/cdtank/node_modules /workspace/worktrees/cdtank-simulation-18524d48b6bb/node_modules
cp -a --reflink=auto /workspace/cdtank/apps/server/resources /workspace/worktrees/cdtank-simulation-18524d48b6bb/apps/server/resources
cd /workspace/worktrees/cdtank-simulation-18524d48b6bb
node scripts/learning/simulation-server.mjs --host 0.0.0.0 --port 40101
```

准备命令只在首次创建目录时执行。当前服务以脱离终端的进程运行。更新模拟版本时准备新的固定提交目录，停止训练并保留检查点，再切换服务和恢复训练；正在运行的模拟目录保持不变。

40101 位于已映射到当前开发容器的 40100–40200 范围。外部健康地址为 `http://192.168.10.140:40101/health`。所有训练和冻结评估的 `--environment-url` 使用同一服务地址；配置分别记录训练端源码与模拟端源码、模拟 Node 版本。

远程命令示例：

```powershell
D:/ai/cdtank/venv/Scripts/python.exe D:/ai/cdtank/trainer/scripts/learning/train_motion.py --data D:/ai/cdtank/data/history-20261017.jsonl.gz --output D:/ai/cdtank/runs/motion-001
D:/ai/cdtank/venv/Scripts/python.exe D:/ai/cdtank/trainer/scripts/learning/train_combat.py --environment-url http://192.168.10.140:40101 --output D:/ai/cdtank/runs/navigation-001 --prior D:/ai/cdtank/runs/motion-20261017-001/best.pt --lesson navigation --steps 100000
```

通过 SSH 持续运行时调用 `D:/ai/cdtank/trainer/scripts/learning/start-training.ps1 -RunName <新目录名> -Lesson navigation -Level 0 -Steps 30000`，`-EnvironmentUrl` 默认使用 `http://192.168.10.140:40101`。后续课程通过 `-Weights <前一课程检查点>` 继承全部策略参数并重置优化器和步数；同一课程中断后可用 `-Resume <检查点>` 继续优化器和累计步数，`Steps` 为累计目标。迁移模拟进程时从检查点开始新回合，保留优化器和累计步数。启动信息写入 `runs/<目录名>.launch.json`，标准输出和错误分别写入同目录名的 `.stdout.log`、`.stderr.log`；进程独立于 SSH 会话存活。

`--mix-levels`（启动脚本的 `-MixLevels`）按每回合的独立种子，从 0 到指定 `level` 均匀选择课程，重放此前技能。射程接近和后撤通过 `--lesson range --level 1 --mix-levels` 在同一模型中训练；日志保留每个回合实际使用的级别。

基础操作可用 `--teacher-steps`（`-TeacherSteps`）在 PPO 前预热。`teacher.py` 仅读取策略的局部观察和动作掩码，为原地转向、直达路点、固定车体瞄准和接近/后撤提供操作示范；它不参与之后的动作执行。示范由真实 World 连续推进，按 32 步序列监督学习，单独保存 `teacher.jsonl` 和 `teacher.pt`。标签来源为 `scripted primitive control`，不计为真人数据，预热步数与 PPO 步数分开记录。启用预热的运行在后续 PPO 中以 `--imitation-weight 0.1` 保留基础操作辅助损失，日志 `losses` 的第五项为该损失；将系数设为 0 可单独评估纯奖励优化。随后仍以冻结模型的独立种子评估判定效果。

预热与辅助模仿独立控制：`--resume` 跳过预热，并从检查点配置恢复有效的 `imitationWeight`，显式传入 `--imitation-weight`（启动脚本的 `-ImitationWeight`）可覆盖该系数。配置分别记录本次实际预热步数 `teacherBootstrapSteps` 和辅助模仿系数；只有预热、没有辅助损失的旧检查点继续使用纯 PPO。

示范预热逐渐混入学习策略的贪心动作，概率从 0 增长到 `--teacher-student-fraction 0.75`。这些动作产生的真实状态继续由基础控制器标注，学习策略在自己过早停车、瞄准偏移等状态上获得纠正示范；日志记录实际混合概率。后续 PPO 执行策略自身采样的动作。

`evaluate.py` 在不同于训练的种子上冻结模型执行完整练习，默认选择概率最高动作；`--stochastic` 评估采样策略。指定 `--checkpoint`、`--output`、`--lesson` 和 `--level`。输出 `episodes.jsonl` 保存实际动作、位置、观察、受阻与距离记录，`result.json` 记录到达/击毁/无伤比例和平均奖励。该评估用于选择课程与检查点。

PPO 完成训练后关闭训练世界，自动在 `evaluation-level-<级别>` 中完成 32 个独立种子的冻结评估；混合课程逐级评估。`--evaluation-episodes` 调整每级评估局数。评估配置记录检查点所属源码、实际评估源码、观察版本和设备，结果汇入运行目录的 `result.json`。已有运行使用其启动时的训练入口，需要单独调用评估脚本。

每次运行使用新目录。`config.json` 保存数据划分、软件版本和超参数；`metrics.jsonl` 保存训练指标；`latest.pt` 用于续训，动作预训练另保存 `best.pt` 和 `result.json`。训练完成不代表满足接入条件。

## 当前结果与限制

模拟迁移后，普通弹射程、远程弹射程与导航分别在 `range-network-20261018-001`、`range-long-network-20261018-001`、`navigation-network-20261018-001` 从原检查点恢复，保留优化器和累计 PPO 步数，每项使用 4 个本机世界。首次运行记录中，三项步数分别从 22272 增至 23296、25344 增至 26368、24320 增至 25344；本机健康接口报告 12 个世界，179 的本任务 Node 模拟进程数为 0，RTX 2080 Ti 的瞬时利用率为 80%、显存使用为 1446 MiB。配置与检查点继续写入 `D:/ai/cdtank/runs`，迁移记录为 `runs/simulation-migration-20261018-001.json`。这些记录证明训练已通过网络继续推进，不代表课程通过。

首轮动作先验在 GPU 上完成 100 epoch，最佳验证交叉熵为 0.73356。验证集 549 条连续动作中，移动、转向和炮塔操作准确率分别约 69.2%、77.2%、67.4%；保持上一动作基线为 69.2%、74.5%、63.6%。这是粗采样动作预测结果，不代表交战或对人胜率。

人类风格需要在基础技能稳定后单独评估：从确认的人工输入采集观察到操作的延迟、连贯转向、瞄准修正、交火距离和道具时机，作为模仿约束；再比较学习策略与人工样本的行为分布和对局表现。目前的 500ms 历史记录不足以确定反应时与瞄准节奏。现有感知为局部距离与视线过滤，尚未复现玩家相机视野；其后的拟人化训练需要同时处理视野、反应延迟和操作误差。

## 后续训练顺序

基础阶段先分别学习转向、直行、瞄准和交火距离，再在同一个策略中重放已学课程，开放移动射击、移动目标、绕障、脱困和对射。普通弹和远程弹都要分别评估接近、后撤和五秒距离保持；交火课按实际带内击毁评估。随后随机出生、战车、弹药和地图，使用未用于优化的地图及固定对手池评估完整 1v1，确认组合技能没有退化。

道具阶段按治疗/防御、移动强化、特殊弹药、陷阱和范围攻击分组开放。观察需要加入自身效果持续时间、真实冷却、队友需求和使用资格，奖励来自节省的生命、交火收益与目标完成，并扣除实际消耗；使用次数本身不作为正奖励。先单类课程，再混合配给和普通对局。

团队阶段先 2v2，再 3v3。集中价值网络可读取训练世界的队伍状态，执行策略继续只使用各自局部观察。共享胜负与目标奖励，结合个体贡献训练集火、掩护、队友治疗、分路和目标分工。将各队成员分开控制，不能把多名脚本 CPU 对手称为多智能体学习。历史检查点与当前策略混合组成对手池，避免只适应同一种队友或对手。

模式阶段继承通用移动、瞄准、射程和道具主干，为每种真实规则保存独立策略头及检查点。模式 1 优化队伍生命和胜负；模式 2 围绕敌方堡垒攻击与己方防守；模式 3 分别训练 VIP 生存、护送和击杀敌方 VIP；模式 4 优化个人击毁与排名；模式 5 围绕突破目标与场景破坏。中间奖励服务于实际胜负条件，不用总伤害替代规则完成。

接入前在不同地图、阵容、模式和对手池中冻结评估，并复查真实轨迹中的无效开火、受阻、距离控制、道具消耗和团队目标表现。达到完整对局要求后导出推理参数，以既有 CPU 输入入口执行，再评估不同操作节奏和难度；当前基础课程检查点还未达到该条件。
