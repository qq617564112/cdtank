# AI 训练

训练主机为 `192.168.10.179`，GPU 为 RTX 2080 Ti（计算能力 7.5，驱动报告 22528 MiB 显存）。游戏模拟在当前开发虚拟机运行，通过 `http://192.168.10.140:40101` 提供服务；训练主机仅执行 CUDA 模型训练和评估。历史数据、训练依赖与缓存、训练日志和模型全部保存在 `D:/ai/cdtank`。Python 使用该目录的虚拟环境，复用主机已有的 PyTorch 2.3.1+cu118。

## 数据来源

账户数据库 `match_history` 只保存结算，没有逐帧操作。`scripts/learning/export_history.py` 以只读事务读取数据库，根据房间、回合、地图、模式、结束时间关联 `state/cpu-traces/*.ndjson*`，选择最后采样距结算不超过 3 秒的进程会话。导出仅保留结算参与者中标记为 `HUMAN` 的状态与普通输入，不导出账号、令牌、凭据或显示名。托管 `AUTOPILOT` 和脚本 `CPU` 不作为真人标签。

历史轨迹约每 500ms 在模拟推进后采样。它不能提供按键发生前的完整观察；初始模型使用当前自身状态预测下一采样点的移动、转向和炮塔操作，作为动作习惯先验。训练不从这些记录推断未记录的视线、道具效果或子弹。整场比赛划入同一个训练或验证集合，连续死亡、控制切换及采样间隔中断处切断序列。

历史 `HUMAN` 标签表示未启用托管，不包含客户端是人工操作还是自动脚本的来源证明。数据文件保留这一来源标记。

2026-10-17 的导出读取到 101 个结算回合，关联到 36 个轨迹会话，其中保留 4966 个真人标签采样点、4646 个存活采样点。其余 65 个回合没有符合时间匹配条件的轨迹。

## 模拟与模型接口

`scripts/learning/simulation-server.mjs` 在开发虚拟机监听指定端口，当前共享进程池地址为 `192.168.10.140:40109`，源码 `328d491802a8`，使用六个 worker。每个训练连接拥有独立 `World`、时钟、随机流、感知与示范控制器；worker 共享只读内容资源，串行处理其世界命令，连接关闭后删除对应世界。`environment.ts` 在命令期间切换到对应世界的随机流，结束时恢复外层 `Math.random`。模拟每次推进 50ms，模型每 100ms 模拟时间提交一次普通 `MsgPlayerInput`，按请求推进，无需等待真实时间。训练进程不连接账户库，不写线上库存或战绩。

`GET /health` 返回服务、协议版本、源码提交、Node 版本、活跃世界数及 worker 数量。训练端为每个世界保持一个 HTTP 连接，向 `POST /environment` 发送一个重置或动作 JSON，收到对应结果后才发送下一个请求；同一连接不能并发提交两个动作。请求与环境内部的逐行 JSON 内容相同：

```json
{"type":"reset","seed":179,"mode":4,"mapId":7,"players":2,"controlled":1,"lesson":"navigation"}
{"type":"step","actions":[[2,1,1,0,0]]}
```

动作有五个离散头：移动 3 类、车体转向 3 类、炮塔转向 3 类、开火 2 类、道具槽位 0–8。前三类按 `0/1/2 → -1/0/1` 映射。输入资格、库存扣量、碰撞、弹道和结算继续由现有战斗实现执行。

`World.learningFrame()` 当前源码返回 schema 6 的 305 维观察和动作掩码。前 160 维保留 schema 3 的自身状态与上一动作、局部 NAV 探针、可见敌人与队友、可见弹丸、公开模式目标、模式身份、库存槽位、练习路点，以及武器与射程特征；157–159 维为路点方向的归一化横纵分量和距离。敌人经过 2500 单位的观察距离、场景视线和隐身状态过滤；观察范围覆盖普通与远程弹药的射程边缘。奖励统计与观察分开，策略不能读取它们。固定旧提交的模拟服务继续返回其自身的观察版本，训练配置保存实际 schema。

新增 106 维为七个库存槽位的道具类别、实际可恢复生命、效果时长与自身同类效果剩余时间，以及自身 15 项增益、保护和异常状态的剩余时间。治疗动作检查缺失生命与最后一搏；常用增益检查技能栏、现有效果与移动属性资格，隐身和伪装检查互斥状态。热键分类及陷阱放置许可沿用实际请求入口的规则；后续消耗和效果仍由普通战斗入口执行。

schema 5 在这 266 维后追加 24 维：三个可见敌人的炮塔朝向与由连续可见位置计算的速度、自身实际移动/转向参数、车体采样尺寸，以及按真实 NAV 车体足迹检查的八向通行距离。敌方速度只使用 500ms 内连续可见的位置，不读取隐藏动作或对方装填状态；失去可见性后移除对应位置记录。

自身射程按实际弹药的 `runtime.range × shotModifiers.rangePercent / 100` 读取，包含当前技能和装备的加成。普通弹药的基础射程为 1000；2023 弹药的 FuncType23 为 200%，实际射程为 2000。额外特征包括瞬发/弹丸类型、弹速、穿障、装填、弹量、目标距离与射程的比例、射线是否可达及准星是否选中目标。可达性复用真实 `queryShotTarget`，参与查询的角色仅包含已感知角色。敌方弹药从可见敌人在可见位置发出的真实 `fire.skillId` 记录，以公开弹药定义估计射程；开火后的自动换弹或手动选弹不改变已观察弹种，不读取对方隐藏的装备修正。

移动课程按 `level` 分级：0 为朝向前方约 ±9°、60–120 单位的直行；1 为前方约 ±46°、60–160 单位的转向；2 为任意方向、60–240 单位的直达路点；3 为 200–500 单位内需绕障且存在 NAV 路径的目标。候选路径使用实际战车的 NAV 采样尺寸检查。移动课程关闭炮塔、开火和道具，直行课另关闭转向，以距离进展、对准、到达和受阻情况计奖励；到达或 15 秒结束练习，绕障限 30 秒。

`turning` 将原地转向独立训练，关闭平移、炮塔、开火和道具。0/1 级目标方位分别为约 ±23°/±46°，2/3 级为任意方位；航向误差小于 0.08 弧度并连续保持 0.5 秒才算成功，单次限时 10 秒。它为移动转向提供初始参数，后续移动仍由策略自己选择操作。

`aiming` 固定车体，0/1/2 级依次覆盖前方 ±14°、±46°和任意方位的静止靶，3 级使用往返移动靶。0 级目标为 150 HP，其余为 600 HP；单次限时 20 秒。该课程先训练瞄准，再由 `shooting` 开放车体运动与对射。

`shooting` 课程 0 级固定车体，练习瞄准与击毁 90–150 单位内的 150 HP 靶；1 级开放移动和转向，对付任意方向的满血静止靶；2 级对付往返移动靶，3 级对手同时瞄准还击。`dodge` 课程由练习对手瞄准射击，关闭学习者的炮塔、开火与道具，以存活及减少受伤计奖励。练习靶通过 `World.placeLearningActor()` 设置初始位置和 HP，检查地形及战车重叠，并清除初始出生保护；后续运动、子弹、装填和伤害均使用普通战斗入口。导航练习的成功定义为进入目标 20 单位内；射击为击毁目标；躲避为 15 秒未受伤。

schema 5 的躲避对手按 0/1/2/3 级每 1/0.5/0.2/0.1 秒更新瞄准目标方位，首次开火等待分别为 1.5/1/0.5/0 秒，初始距离分别为 400–600、300–500、200–350、90–360 单位。炮塔速度、射程、装填和命中仍使用真实战斗规则。基础躲避示范从局部观察选择相对敌方方位的侧向通行方向；射击示范结合炮塔瞄准和车体接近/后撤，均只在预热或辅助损失中提供标签。

`combat` 课程使用正常 60 秒对局，以实际伤害、击毁、死亡和胜负计奖励，模式 2/3/5 分别加入堡垒伤害、VIP 伤害和目标摧毁数。团队模式的过程奖励由 25% 个体贡献和 75% 全队贡献组成；每名学习者独立取得胜负奖励，实际道具消耗与无效使用计成本。个人模式 4/5 保持个人目标与胜负。

schema 6 的局部观察为 305 维，在 schema 5 后追加自身队伍、固定席位、公开队伍生命及分数、双方存活数和友伤设置。训练环境支持最多六个角色；`--players 4 --controlled 2` 和 `--players 6 --controlled 3` 分别建立一整队学习角色对现有 CPU 的 2v2、3v3。交替入房保证学习队友都在队伍 0。`--controlled` 与 `--players` 相等时，两侧都由共享学习策略独立控制。每个角色有独立 GRU 状态，死亡仅重置该角色记忆，整局结束才共同重置世界。

`--centralized-critic` 启用集中价值网络，使用单独的 140 维 `criticStates`：模式、队伍、时间、队伍生命及分数、六个角色全局位置/朝向/生命/战绩和四个目标状态。该输入只传价值网络，执行策略始终只接收本地观察与动作资格。PPO 按 `世界数 × 学习角色数` 展平采样，以 32 步序列优化；日志 `steps` 为角色决策数，`worldSteps` 为世界决策数，配置记录实际队伍名单、批量与集中状态维度。

`--opponent-pool` 读取 D 盘 JSON 检查点列表，在全员受控的团队对局中逐局选择一个冻结历史策略控制队伍 1。每个冻结角色有独立记忆，只读局部感知；只更新队伍 0 的策略与价值参数，并仅用其优势统计归一化。配置记录每个对手的实际检查点步数及训练、模拟源码。未指定历史对手且全员受控时，两侧共同学习。

冻结评估记录全部学习角色的动作、位置、回报、击毁/死亡、实际道具消耗和结算。对战成功来自真实 `MatchResult` 中首名学习者的胜负，另存各角色 `outcomes`；统计胜、负、平与未结算回合，局部策略评估不读取集中状态。基础课程仍沿用各课成功条件。

`range` 课程 0 级从自身射程的 105/112.5/120% 处接近，1 级从 35/45/55% 处后撤；两级关闭转向、炮塔和开火，要求在 75–90% 的距离带内连续保持 5 秒。练习通道由地图出生点、每 5° 的方向和起始距离生成，筛选完整接近/后撤路径、战车 NAV 足迹和双方视线后缓存，按回合种子选择。2 级在射程边缘练习瞄准击毁，3 级对手还击；两级仅以击毁事件发生时双方处于该距离带的击毁作为成功和击毁奖励。射程课分别记录普通击毁、距离带内击毁 `rangeKills`、距离带停留时间、距离带内射击数和射程外射击数；奖励距离控制和有效射击，对射程外的实际开火计成本。`--ammo-id 2023` 使用普通库存与选弹入口获得远程弹药；地图需要容纳相应射程。

`items` 按真实消耗和效果练习道具。0 级从 50–100% 生命开始，配一份 400 HP 食品，静止对手在第 3、8 秒开火；学习者关闭运动和开火，15 秒后存活，且生命达到上限 75% 与本回合可达生命上限的较小值才算成功。可达生命上限按实际受伤顺序，分别维护未用食品和已用食品两种状态的最佳存活血量；食品按自身真实恢复属性计算并限制在生命上限内，未治疗状态死亡后不再允许延后使用食品。移除道具的对照保留相同目标。1 级配一份无敌道具，对手在第 5、8 秒开火，要求 15 秒无伤。2 级在地图 1 的通道内前进 200 单位，开放一份加速饮料，比较到达时间与消耗，进入目标 20 单位内成功。3 级开放移动射击，配食品、无敌、加速与攻击饮料各一份，对付移动还击的 600 HP 靶；存活击毁为成功，限 30 秒。

道具日志记录实际 `itemUsed`、`itemRejected`、恢复生命和最终 HP；使用次数仅计成本，奖励来自实际恢复、避免伤害和目标进展。基础道具示范读取自身状态、公开课程时间与动作资格：战车 1 的治疗课在受伤后生命不超过 212 HP 时提前保命，否则在第二轮攻击结束后的第 90 个决策起按需使用食品；其它道具课程观察到敌方真实开火后按缺失生命使用食品，面向可见威胁使用无敌，朝路点移动时使用加速。标签仍为脚本示范。`--items '[]'` 可在训练或冻结评估中移除消耗品，按相同种子比较收益；课程 JSON 的 `items` 也可指定槽位、物品表 ID 和数量。

`train_motion.py` 使用 64 维 GRU 和三个动作头。`train_combat.py` 使用环境返回的观察维度、可配置容量的 GRU、五个动作头和价值头，继承动作先验，以 recurrent PPO 训练。较早课程的参数通过 `--weights` 迁移，新增输入列置零，再由后续课程学习。回合结束和死亡清理记忆；PPO 以 32 步序列优化，保存优化器、训练步数、配置和检查点。相同观察维度的续训通过 `--resume` 加载参数及优化器，模拟从新种子回合开始。

射程课程以重置时所选弹药的有效射程固定练习距离带。特殊弹药耗尽后关闭后续开火，已发出的最后一发仍可完成带内击毁；自动切回普通弹不会改变这次课程的成功判定。观察继续报告当前实际弹药，日志另存 `currentWeaponRange`。

射程带内/带外射击按每个 50ms 模拟步的实际 `fire` 事件位置统计，命中选取沿用事件的 `targetId`。带内击毁按真实 `destroy` 事件的位置统计。它们分别衡量开火选择与击毁结果。

`train_modes.py` 从同一团队检查点初始化五个独立候选模型，每个模式分别优化全部参数和保存检查点。模式 1/2/3 使用两名学习队友与两名 CPU，地图分别为 7/2/7；模式 4/5 是四人个人战，地图分别为 7/20。每名学习者配一份食品、无敌、加速和攻击饮料，各模式分别完成固定种子冻结对局后写入模型清单。`run-mode-stages.ps1` 等前一团队运行完成训练及冻结评估，再顺序启动这五项训练；等待和运行状态、依赖评估及错误写入 D 盘的 `runs/<名称>.schedule.json`。这些输出均为训练候选，`readyForGameplay` 保持 false。

`export_policy.py` 在 179 将固定检查点导出为 `cdtank-recurrent-actor-v1` JSON，只含编码器、动作资格编码、配置容量的 GRUCell 和五个动作头；价值网络不进入运行模型。旧观察输入的新增列置零，导出统一为 schema 6。`learning/policy.ts` 用原生 CPU 数组执行同一门控公式，`LearnedCpuPolicy` 按每角色 100ms 决策，独立保存记忆，死亡或新回合重置。道具只在决策时产生一次按键请求，其余输入保持到下次决策。

World 的 `learnedCpuPolicy` 注入接口为指定 CPU 或托管角色返回策略；所有动作仍经过 `advanceActors → updateInput → acceptBattleInput` 的普通资格、序列、消耗和伤害路径。`evaluate_native.py` 将导出模型交给本机模拟，通过真实托管控制运行固定种子对局，179 只编排评估并用 PyTorch CPU 计算实际决策观察上的参考动作，记录动作分歧数与最大 logit 误差。运行端没有 CUDA、PyTorch 或集中状态依赖。

房间进程通过 `CDTANK_AI_MODELS` 读取模式清单，结构为 `{"models":[{"mode":1,"model":"mode-1.json"}]}`，模型相对路径按清单目录解析。每个房间只加载一次，所列模式的 CPU 和托管角色使用对应本地模型，未配置模式继续使用现有控制器。启用前应完成该模型的原生冻结评估和对应人数、地图、战车及配给的实战评估。当前训练候选未配置到运行服务。

`--hidden-size 64/128/256` 设置共享编码器与 GRU 的容量。`--weights` 扩容时按三组 GRU 门分别嵌入旧参数，旧单元对新增单元的连接置零，动作头新增列置零；新增单元保留初始化参数以参与后续学习。训练配置记录真实重置观察上的扩容前后动作分歧与最大 logit 差异、总参数数。`--resume` 继续原容量与优化器，容量变更使用 `--weights`。对手池按各冻结检查点的容量保留独立记忆。训练、冻结评估、导出与原生执行均读取模型容量；每次 PPO 更新记录实际分配、保留和峰值显存。

单队受控的团队对局可在重置中指定 `learnerTeam: 0/1`，经等待房间的普通换队与人数限制建立完整学习队伍。训练端按独立种子随机选择两侧，避免只学习某一队伍标记与出生方向；冻结评估同样按种子固定选择，逐局记录实际 `learnedTeam`。全员学习和历史对手模式继续保留各自的双方控制配置。旧固定模拟服务按自身源码执行其原编组。

序列优化复用 PyTorch 2.3 的 packed GRU 算子，参数继续使用原有 GRUCell 布局。CUDA 上首次合批计算前将循环参数整理为 cuDNN 连续存储，后续更新复用同一存储。每个 32 步片段按角色死亡或回合重置切分，再合批计算循环状态、动作分布、价值与辅助模仿损失。示范阶段先用当前策略采样真实轨迹，再对完整片段优化；逐次日志记录单步采样与合批计算的动作分歧和最终记忆误差。每隔至少 4096 个示范步骤保存 `teacher-latest.pt`，包含实际 `teacherProgress`，可作为 `--weights` 继续阶段训练。训练开始另存 `initial.pt`。

## 专项蒸馏与技能保留

`consolidate.py` 将多个冻结学习专项模型蒸馏到同一个 305 维、256 单元的循环策略。每门课指定一个固定教师，读取真实世界连续 128 步的观察、动作资格和记忆重置位，缓存教师在完整序列上的动作分布。优化目标为 `0.25 × 控制示范损失 + 教师 KL`，硬动作取该冻结教师分布的最大概率项，配置中记作 `controlLabelSource: frozen reference argmax`。旧专项模型使用观察中对应的 266/290 维前缀，保留各自容量和动作资格。配置记录每门课的教师路径、源码、实际步骤和观察版本。

通过 SSH 持续运行时，解析同一个 `$trainer`，调用 `& "$trainer/scripts/learning/start-training.ps1" -RunName <新目录名> -Lesson navigation -Level 0 -Steps 30000`，`-EnvironmentUrl` 默认使用 `http://192.168.10.140:40109`。后续课程通过 `-Weights <前一课程检查点>` 继承全部策略参数并重置优化器和步数；同一课程中断后可用 `-Resume <检查点>` 继续优化器和累计步数，`Steps` 为累计目标。带集中价值网络的完整交战或团队检查点继续使用 `-CentralizedCritic`。迁移模拟进程时从检查点开始新回合，保留优化器和累计步数。启动信息写入 `runs/<目录名>.launch.json`，标准输出和错误分别写入同目录名的 `.stdout.log`、`.stderr.log`；进程独立于 SSH 会话存活。

`-Environments` 控制并行模拟世界数，`-MinibatchSequences` 控制每个 PPO 梯度批次包含多少条 32 步序列，分别对应 Python 的 `--environments` 和 `--minibatch-sequences`。扩大两种批量后，以相同课程的累计步数与耗时判断提速，冻结评估仍决定策略质量；较大的梯度批次会减少每个回合采集批次中的优化器更新次数。

GPU 调度使用 NVML 读取整卡利用率与显存。用户要求整卡负载不超过 90%，`--gpu-utilization-limit`（启动脚本 `-GpuUtilizationLimit`）默认设为 80，为驱动采样和已提交计算保留余量，参数最高为 90。训练、示范预热和冻结评估共享主机单调时钟的计算窗口，保留空闲时间；采样达到内部阈值前 2 个百分点时停止提交 CUDA 工作，降至内部阈值前 7 个百分点后恢复。`gpu.jsonl` 每秒记录整卡利用率、显存、冷却状态和累计暂停时间，PPO 指标同时记录 GPU 利用率。该限制通过软件调节提交时机，Windows 驱动不提供整卡利用率的硬件瞬时限幅，采样峰值仍需据实际记录调整并行度。

`--mix-levels`（启动脚本的 `-MixLevels`）按每回合的独立种子，从 0 到指定 `level` 均匀选择课程，重放此前技能。射程接近和后撤通过 `--lesson range --level 1 --mix-levels` 在同一模型中训练；日志保留每个回合实际使用的级别。

基础操作可用 `--teacher-steps`（`-TeacherSteps`）在 PPO 前预热。`teacher.py` 仅读取策略的局部观察和动作掩码，为原地转向、直达路点、固定车体瞄准和接近/后撤提供操作示范；它不参与之后的动作执行。示范由真实 World 连续推进，按 32 步序列监督学习，单独保存 `teacher.jsonl` 和 `teacher.pt`。标签来源为 `scripted primitive control`，不计为真人数据，预热步数与 PPO 步数分开记录。启用预热的运行在后续 PPO 中以 `--imitation-weight 0.1` 保留基础操作辅助损失，日志 `losses` 的第五项为该损失；将系数设为 0 可单独评估纯奖励优化。随后仍以冻结模型的独立种子评估判定效果。

预热与辅助模仿独立控制：`--resume` 跳过预热，并从检查点配置恢复有效的 `imitationWeight`，显式传入 `--imitation-weight`（启动脚本的 `-ImitationWeight`）可覆盖该系数。配置分别记录本次实际预热步数 `teacherBootstrapSteps` 和辅助模仿系数；只有预热、没有辅助损失的旧检查点继续使用纯 PPO。

策略将 20 个动作资格位经独立线性层加入观察编码，使同一方位的路点在允许转向与禁止转向时可以选择不同动作。旧检查点的该层以零初始化，保留原策略输出；续训同时保留既有优化器状态，为新增参数建立优化器组。直行示范在转向不可用时直接向前方路点行驶。

`--curriculum <JSON路径>`（启动脚本 `-Curriculum`）在同一个策略中重放不同基础技能。JSON 为课程数组，可覆盖 `lesson`、`level`、`mix_levels`、`mode`、`map_id`、`players`、`ammo_id`；未指定字段沿用命令行参数。各世界按编号循环分配课程，每门至少有一个世界；示范与辅助损失按各世界实际课程取标签。完成训练后，在 `evaluation-course-<序号>-level-<级别>` 中逐课逐级冻结评估，分别记录地图、弹药和结果。示例：

```json
[
  {"lesson":"navigation","level":2,"mix_levels":true,"map_id":7},
  {"lesson":"aiming","level":2,"mix_levels":true,"map_id":7},
  {"lesson":"range","level":1,"mix_levels":true,"map_id":1,"ammo_id":2001},
  {"lesson":"range","level":1,"mix_levels":true,"map_id":2,"ammo_id":2023}
]
```

示范预热逐渐混入学习策略的贪心动作，概率从 0 增长到 `--teacher-student-fraction 0.75`。这些动作产生的真实状态继续由基础控制器标注，学习策略在自己过早停车、瞄准偏移等状态上获得纠正示范；日志记录实际混合概率。后续 PPO 执行策略自身采样的动作。

示范损失对实际开火标签乘 5、消耗品标签乘 30，其余标签乘 1，避免一次治疗或装填后的开火被大量无操作步骤淹没。预热和 PPO 辅助损失使用相同权重，检查点配置记录 `imitationEventWeights`。冻结评估仍按模型自身动作执行，权重不改变奖励或战斗规则。

`evaluate.py` 在不同于训练的种子上冻结模型执行完整练习，默认选择概率最高动作；`--stochastic` 评估采样策略。指定 `--checkpoint`、`--output`、`--lesson` 和 `--level`。默认使用 8 个并行世界，`--environments` 可调整；第 i 个回合始终使用 `seed+i`，保留原来的独立种子集合。回合完成时立即写入 `episodes.jsonl`，保留回合编号、实际动作、位置、观察、受阻与距离；`result.json` 记录成功率、平均奖励、用时、实际道具消耗、恢复生命、受伤和最终 HP。该评估用于选择课程与检查点。

PPO 完成训练后关闭训练世界，自动在 `evaluation-level-<级别>` 中完成 32 个独立种子的冻结评估；混合课程逐级评估。`--evaluation-episodes` 调整每级评估局数，`--evaluation-environments` 调整并行世界数。评估在同一 Python 进程中执行，复用 CUDA 上下文。评估配置记录检查点所属源码、实际评估源码、观察版本和设备，结果汇入运行目录的 `result.json`。已有运行使用其启动时的训练入口，需要单独调用评估脚本。

`evaluate_curriculum.py` 从检查点配置读取全部课程，在同一 CUDA 进程中逐课逐级调用并行冻结评估；也可用 `--curriculum` 指定课程 JSON。指定 `--environment-url`、`--checkpoint`、`--output`，中间结果写入 `progress.json`，最终写入 `result.json`。`--without-items` 用相同种子移除所有课程的消耗品，供道具收益比较。

每次运行使用新目录。`config.json` 保存数据划分、软件版本和超参数；`metrics.jsonl` 保存训练指标；`latest.pt` 用于续训，动作预训练另保存 `best.pt` 和 `result.json`。训练完成不代表满足接入条件。

## 后续训练顺序

基础阶段先分别学习转向、直行、瞄准和交火距离，再在同一个策略中重放已学课程，开放移动射击、移动目标、绕障、脱困和对射。普通弹和远程弹都要分别评估接近、后撤和五秒距离保持；交火课按实际带内击毁评估。随后随机出生、战车、弹药和地图，使用未用于优化的地图及固定对手池评估完整 1v1，确认组合技能没有退化。

道具阶段按治疗/防御、移动强化、特殊弹药、陷阱和范围攻击分组开放。观察需要加入自身效果持续时间、真实冷却、队友需求和使用资格，奖励来自节省的生命、交火收益与目标完成，并扣除实际消耗；使用次数本身不作为正奖励。先单类课程，再混合配给和普通对局。

团队阶段先 2v2，再 3v3。集中价值网络可读取训练世界的队伍状态，执行策略继续只使用各自局部观察。共享胜负与目标奖励，结合个体贡献训练集火、掩护、队友治疗、分路和目标分工。将各队成员分开控制，不能把多名脚本 CPU 对手称为多智能体学习。历史检查点与当前策略混合组成对手池，避免只适应同一种队友或对手。
