## 共享优化

WebGPU uniform 上传使用 64 KiB 页面；逻辑 buffer 创建时分配固定的对齐区间，bind group 保留原绑定大小和独立身份，每次原生提交前只复制各个脏页面一次。Babylon 延迟销毁逻辑 buffer 时归还区间，相邻空闲区合并，空页销毁；设备重建时一起清理。该实现减少 GPU 复制命令，原生逻辑 buffer 的分配仍保留，不作为内存下降量。

静态阴影候选在注册时筛选；禁用根节点和不可见网格先跳过。破损模型登记到集合，接收阴影网格在移除事件中注销，减少每帧扫描全场景。阴影贴图、覆盖范围、绘制频率和着色规则保持原值。

手机与电脑的装填准星订阅原有装填状态，直接更新原 SVG 裁剪矩形的高度和位置；图案、数值和更新频率相同，连续进度不再重建 React SVG 子树。

## GPU 时间跨度

第二十五局在原生 GPU 计时关闭时，每八帧记录一次各渲染通道的开始与结束时间戳；同一命令缓冲只追加一次查询回收，不逐通道提交。50 个完整采样帧的通道内时间之和平均为 14.15 ms，从第一个通道开始到最后一个通道结束平均为 17.02 ms，中间间隔平均为 2.86 ms。

| 区间 | GPU 平均耗时 |
| --- | ---: |
| 速度缓冲通道 | 1.54 ms |
| 阴影通道 | 0.37 ms |
| 场景颜色通道 | 8.49 ms |
| 屏幕输出及界面通道 | 3.76 ms |
| 速度缓冲结束至阴影开始 | 0.03 ms |
| 阴影结束至场景颜色开始 | 0.69 ms |
| 场景颜色结束至屏幕输出开始 | 2.14 ms |

完整 GPU 时间跨度已接近或超过 60 FPS 的 16.67 ms 单帧预算。通道间隔包含通道外的 GPU 操作及等待，当前记录不能把它全部归因于 MSAA 解析；时间跨度不包含首个时间戳之前或最后一个时间戳之后的上传、合成及呈现工作。原生各通道时间之和不能代表完整 GPU 帧耗时，也不能据此认定 GPU 已达到 60 FPS。

第二十六局在独立基线之后，每八帧使用空 compute pass 的时间戳包围 uniform 复制及原生上传、渲染命令缓冲。53 个采样帧从 uniform 复制之前到最后渲染命令之后平均为 20.73 ms、P95 为 25.03 ms；uniform 复制区间平均 1.11 ms，其后上传与渲染平均 19.61 ms。该测量包含采样命令的开销，不包含 Chromium 随后的画布 alpha 处理、合成和呈现；不能把完整进程的 GPU 帧开销简化为各渲染通道内计时之和。

第三十三局在独立基线后按相同方法记录 54 个 GPU 采样帧，从 uniform 复制之前到最后渲染命令之后平均为 20.72 ms、P95 为 24.64 ms；uniform 复制区间平均 2.06 ms，其后上传与渲染平均 18.66 ms。战况和绘制量不同，不能将其与第二十六局直接比较；完整 GPU 时间跨度仍超过 16.67 ms 预算。

当前设备为 Intel Iris Xe、驱动 32.0.101.7088，Chrome 报告 `msaa_is_slow` 和最大四采样的驱动规避项。WebGPU 使用 D3D12，合成后端为 GaneshGL/ANGLE D3D11。这些记录支持继续排查 GPU 路径，不能单独作为该设备无法达到 60 FPS 的证明。

## 全屏颜色交接

运动模糊开启时，场景直接绘制到模糊后处理的输入目标，由同一目标承担原有渲染倍率与 MSAA；模糊关闭时使用原生 PassPostProcess 输出。模糊着色器、速度通道、玩家遮罩和界面绘制顺序保持原值。

该路径减少一次原样全屏颜色复制和一张中间 RGBA8 目标。3840×1969 时，中间颜色数据为 30,243,840 字节，约 28.84 MiB；这是目标像素容量，不是实测进程内存下降量。

第八局对同一份场景颜色输入分别执行“直接模糊”和“原样复制后模糊”。排除独立绘制的准星及持续变化的界面后，场景区域像素一致；恢复正常渲染后引擎继续出帧。该修改减少了资源和通道，当前采样未证明帧率显著上升。

## 连续屏幕通道

世界后处理、头顶标识、小地图及 HUD 的绘制顺序保持原值。恢复默认帧缓冲时，如果当前已经位于默认帧缓冲，保留正在进行的屏幕通道，仅恢复视口和清理绑定状态；实际离屏目标继续交由 Babylon 原生解绑。帧末仍由原生 `endFrame` 结束通道、解析 MSAA 并提交。

第十局进行了三轮交替短时对照，原路径每帧 4 个屏幕通道，分别为 33.30、33.24、32.32 FPS；合并后每帧 2 个屏幕通道，分别为 35.64、36.57、36.99 FPS。该窗口包含临时 GPU 计时，且战斗持续变化，只作为同局方向性证据；第十一局的独立基线用于复测。

在同一份世界颜色、速度纹理及屏幕网格数据上，分别绘制原路径、合并路径及再次原路径。临时隐藏独立的 DOM 结算遮罩后，3840×1970 截图逐像素差异为零，包含战车、阴影、名牌、小地图和屏幕图片；画布实际尺寸为 3840×1969。对照结束后恢复 DOM 可见性和正常渲染。分辨率、世界与屏幕的 MSAA、纹理采样及混合状态保持原值。

## 屏幕清理时序

世界颜色在后处理的离屏输入目标清理。后处理全屏输出已覆盖默认帧缓冲的颜色，屏幕深度与模板在输出之前清理，随后继续绘制名牌、小地图和 HUD；避免在世界渲染之前单独启动、结束一次屏幕清屏通道。

每帧按后处理就绪状态选择清理位置。效果尚未就绪或后处理关闭时，保留 Babylon 的场景背景清屏；后处理输入目标的颜色与深度仍由原生 `PostProcess.activate` 清理。该路径覆盖手机和电脑。

第十四局在已合并连续屏幕通道的实现上进行交替对照：每帧屏幕通道由 2 次降为 1 次。12 个交替的两秒窗口中，原清屏时序合计 36.81 FPS，延后清屏合计 40.22 FPS。实战负载持续变化，该结果作为同局方向性证据。记录中的原生绘制计数是累计计数，不能作为每帧绘制数。

固定同一份世界颜色、速度、玩家遮罩及屏幕网格数据，绘制原时序、延后时序和再次原时序，三张 3840×1970 截图逐像素差异为零。对照后恢复正常渲染及 DOM。该核对覆盖当时的动态模糊、4× MSAA、名牌、小地图和 HUD，不能替代后续整局稳定性采样。

## 场景实例与颜色载入测量

地图 8 的 56 个不透明完整破损物件共用三个模型与材质源；完整模型绘制包含原生描边颜色、主体及描边深度三个步骤。透明排序、独立隐藏与破损状态仍需保留。同一输入的两处视角对照中，一处像素一致，另一处存在像素差异。八个交替实战窗口的克隆与原生实例路径分别为 40.40、38.83 FPS；固定场景窗口分别为 50.34、49.43 FPS，没有稳定的帧率收益。当前完整模型继续使用独立网格。

屏幕输出通道载入颜色与原生清理颜色的八个交替实战窗口分别为 41.27、39.54 FPS；不同窗口的绘制量不同，不能直接作为收益比较。结算状态稳定后的同输入截图像素一致。为各离屏目标分配独立计数器后，屏幕通道 GPU 时长中位数分别约为 1.84、1.77 ms，尚未证明稳定的实战帧率收益；当前输出清理时序保持原值。跨过结算界面切换的截图不用于画面等价结论。

结算场景还核对了 MSAA 解析后颜色数据的存储。758 个记录帧均只有一个屏幕通道和一个世界颜色通道；原生存储与丢弃 MSAA 颜色的交替窗口分别为 44.77、45.07 FPS，世界颜色 GPU 时长中位数均约为 5.18 ms，屏幕通道均约为 1.77 ms。该测量不支持稳定收益，保留原生存储规则。

## 通道内绑定缓存

同一原生 WebGPU 渲染通道只在管线对象或顶点缓冲的槽位、对象、偏移、范围变化时重新绑定。每个通道各自保存状态；执行原生 render bundle 时清空记录。缓冲内容更新仍使用原流程，着色器、绘制顺序、材质状态、深度、MSAA 和呈现流程保持原值。此实现覆盖手机和电脑。

第十八局结算场景的八个交替窗口中，未装计数探针的原生路径与缓存路径分别为 42.22、42.96 FPS，每帧绘制均为 817 次。固定输入的原路径、缓存路径及再次原路径截图逐像素一致。结算场景的短时收益不能代替实战测量；第十九局独立采样验证实际效果。

第十九局十二个交替实战窗口的原生路径与缓存路径分别为 38.56、39.84 FPS，平均每帧绘制分别为 611、538 次，不能将全部涨幅归因于缓存。场景基本固定后的窗口约为 53.85、53.86 FPS，渲染 CPU 均值为 11.31、11.19 ms；当前证据支持减少冗余提交，尚未证明稳定的实战帧率收益。结算稳定后的原路径、缓存路径及再次原路径截图逐像素一致；进行中的异步资源切换窗口不用于像素等价判定。

## Uniform 上传合批

Babylon 仍负责 uniform 数值、四字节对齐和每个绘制上下文的独立缓冲。上传入口立即保存当前字节快照，在原生队列提交之前通过一张映射暂存缓冲按原顺序复制到原目标；每次纹理或 readback 提交同样先处理待上传快照。暂存缓冲在提交后销毁，目标缓冲继续按原生帧末顺序释放。设备重建前解除旧设备包装，初始化完成后安装到新设备；引擎销毁时丢弃旧设备待上传数据。手机和电脑的 WebGPU 路径共用。

第十九局结算场景每帧绘制均为 458 次，八个交替窗口原路径约 45.60 FPS、合批约 50.62 FPS，渲染 CPU 均值分别为 19.81、17.61 ms。固定输入下的原路径、合批路径及再次原路径截图像素一致；固定场景短时结果不能代替实战性能。

第二十局的交替实战窗口分别约为 38.88、42.28 FPS，但每帧绘制分别为 814、565 次，不能将全部差值归因于合批。固定场景窗口约为 51.66、51.48 FPS，当前证据尚未证明稳定的实战帧率收益。同一输入的三张截图像素一致，诊断未记录 GPU 错误或设备丢失。

第二十局还核对了语义相同的资源绑定共享与运动模糊整数像素读取，两项短时诊断均未证明稳定收益，当前绘制及着色器保持原值。相关临时钩子已移除。

## Uniform 页面上传诊断

第三十四局结算后，将已经保存完整 CPU 数据的独立 uniform 临时映射到对齐的页面范围，每次提交只复制有变化的页面。各绘制的布局、绑定范围、数值与提交顺序保持原值。相同 1016 次绘制并施加同公式的细小相机移动时，原路径约 43.53 FPS，候选约 51.72 FPS；原路径、候选及重复截图逐像素一致，未捕获 GPU 错误。

额外四个窗口记录完整 GPU 时间跨度，原路径的 uniform 复制区间平均为 2.03 ms，候选为 0.073 ms；从复制前到最后渲染命令后的平均时间由 20.15 降为 18.06 ms，后续上传与渲染约为 18.12、17.98 ms。该组来自结算场景，不能代替实战；该组对照结束后恢复原缓冲和绑定；正式实现的独立实战结果见第三十六局。

第三十五局在临时页面探针下的独立窗口约为 44.85 FPS，平均每帧 659 次绘制，不能作为运行源码的独立基线。八个实战交替窗口原路径约为 43.85 FPS、候选约 44.51 FPS，平均绘制分别为 648、535 次；差值不作为严格收益。候选平均每帧约 18.2 次页面复制，约 444 次 uniform 写入。临时实现累计分配页面且在新映射时重新生成绑定，CPU Profile 中仍有绑定创建开销；源码已在缓冲创建时固定映射，并随原生释放复用空闲范围。

第三十六局在独立基线之后核对源码上传：333 帧内有 68,666 次 uniform 写入和 4,079 次页面复制，平均每帧约 206.2 次写入合为 12.25 次复制。诊断观察到 15 张页面，容量合计 960 KiB；这是采样触及页面的容量，不是总进程内存。另一个 53 帧 GPU 窗口中，复制均值 0.116 ms，后续渲染跨度 20.415 ms，合计 20.531 ms。临时页面探针不存在，未捕获 GPU 错误或设备丢失。

## 底层 uniform 存储诊断

第二十一局临时将原 uniform 的字节范围放进同设备的 64 KiB 页面，保留独立绑定范围、原布局和上传顺序。整局累计分配 16,467 个逻辑 uniform 缓冲，对应 67 页、约 4.19 MiB 页面容量；该累计数包含已经释放的逻辑缓冲，不是同时常驻的缓冲数。页面容量不是实测进程内存下降量。

八个交替实战窗口的原存储路径与共享路径分别约为 36.34、39.68 FPS，每帧绘制分别为 811、563 次，不能直接归因于共享。固定场景均为 783 次绘制，分别约为 51.68、52.37 FPS，渲染 CPU 均值分别为 10.99、11.02 ms；同输入的原路径、共享路径及再次原路径截图像素一致。当前小幅差值不足以支持增加页面分配与回收实现，源码保持独立缓冲。

结算场景的顶点上传核对记录每帧约四次、每次 48 字节上传，交替窗口没有发现逐字节相同的重复上传，未添加内容比较缓存。

## 静态物件平面法线

完整静态 Breach/General 材质使用 POL 模型。34 类模型在三套画质中的完整模型及序列屏幕共 105 个 GLB、6726 个三角形，已有法线均与几何面平行、三角形内方向一致且不为零。与此不同，物件目录中包含的 C9 等动画模型使用平滑法线；161 个 GLB 的广泛统计不能用于认定完整静态 POL 材质的法线性质。模型目录的广泛统计与实际材质范围的统计分别见第三十七局 `prop-flat-assets.json`、`static-material-flat-assets.json`。

完整静态 POL 材质在顶点阶段通过世界矩阵余因子计算几何法线，处理非均匀和镜像缩放，并按原 shading normal 定向；阴影入射角、法线偏移、方向光正交投影及投影平面坡度随之移到顶点。片元保留原 PCF、光照、纹理、alpha discard、雾和绘制顺序，战车与 CVD 动画继续使用各自原路径。手机关闭阴影时宏排除此计算。

第三十七局结算后的相同 627 次绘制下，八个交替窗口排除首个预热窗口，原路径约 47.72 FPS、顶点路径约 49.83 FPS；世界颜色 GPU 均值约 6.99、6.40 ms，中位数约 6.09、5.57 ms，其它通道中位数保持一致。正、左、右视角的同输入截图分别有 85、62、49 个像素差异，最大通道差为 3、3、2，原路径重复截图逐像素一致。未见模型或阴影形状异常，未捕获 GPU 错误。此结果是固定场景对照，不能当作实战 60 FPS。

## 屏幕通道深度附件

世界场景的深度测试和 MSAA 保持原值。世界后处理就绪时，最终屏幕通道仅绘制全屏输出、玩家标签、小地图和 UI 图块；实战 211 帧审计中，后处理关闭深度测试，屏幕图块使用 ALWAYS 且不写深度，均未启用 stencil。此时原生 MainRenderPass 省略深度附件，管线同步省略深度格式。后处理未就绪或被关闭时恢复屏幕深度路径；离屏目标一直使用各自深度附件。引擎初始化及设备恢复重置屏幕状态。

第三十七局结算后的相同 627 次绘制下，八个交替窗口排除首个预热窗口，原路径约 48.67 FPS、屏幕无深度附件约 51.28 FPS；输出通道 GPU 均值约 2.23、1.92 ms，中位数约 1.84、1.64 ms。三处视角候选与原路径及重复截图均逐像素一致，未捕获 GPU 错误。此结果是独立于静态物件候选的局部对照，不能将两组 FPS 差值相加。

## 阴影材质计算诊断

第二十二局针对 13 个不接收阴影的地形材质，临时使用不包含阴影计算的原生 ShaderMaterial 变体。固定场景保持每帧 607 次绘制，排除首个编译停顿窗口后，原路径约 48.82 FPS、变体约 50.60 FPS；同输入的三张截图像素一致。实战交替窗口的战况不同，未证明稳定收益。

保留原生材质与回调，仅在片元计算入口增加材质级 receiver/settings 判断时，预热后的八个固定窗口分别约为 48.78、48.24 FPS，同输入截图像素一致。该判断没有显示出性能收益，运行源码保持原值；全部临时材质及着色器钩子已恢复。

## 特效网格重建

第二十九局独立基线结束后的 12 秒记录包含 32,691 次特效 draw 调用、7 次控制器切换和 7 次网格重建，均为渲染状态相同的控制器切换，没有渲染状态变化触发的重建。该频率不足以将重建认定为持续低帧的主要来源，运行源码保持原值。

## 特效挂点按需更新

第二十三局临时记录实际挂点读取：12 台车各自通常请求 1–3 个挂点，原路径每次更新均处理全部 7 个。保留已返回数组持续更新、首次读取立即计算当前姿态后，八个交替窗口中，原路径 12,077 次更新处理 84,539 个挂点，按需路径 12,675 次更新处理 21,797 个挂点，平均每次由 7 个降为 1.72 个。

挂点更新计时每次约由 0.00613 ms 降为 0.00450 ms，下降约 27%；100 次已请求矩阵的逐元素对照无差异。两组帧率约 40.61、42.25 FPS，每帧绘制约 287、271 次，战况不同，不能直接作为帧率收益。该局属于临时探针诊断。源码在结算后改为只更新已请求的挂点：首次读取按当前姿态初始化，已返回的数组继续在原更新时机改写，保留 M/U 回退和炮塔攻击挂点规则。手机和电脑共用。

第二十四局独立采样使用源码实现，临时挂点探针不存在；12 台车在实战读取时各保留 2–3 个挂点，合计 33 个，原实现会建立 84 个。45 秒实际提交 1803 帧、约 40.06 FPS，每帧平均绘制 611 次。当前测量未证明整局帧率提升，60 FPS 目标仍未达到。

独立采样结束后，在相同战车姿态与时钟输入下，对原更新函数和源码实现各执行 6,023 次。原路径处理 42,161 个挂点、计时合计约 30.8 ms，源码处理 17,536 个、计时合计约 23.0 ms，局部耗时下降约 25%。100 次已请求矩阵逐元素对照无差异；计时包装结束后已恢复源码方法。此数值是挂点更新的局部收益。

该局 CPU Profile 出现 UI 图片裁剪编码，后续 15 秒诊断没有记录新的 PNG 编码调用；当前证据不支持将它判定为持续编码循环。

## 道具栏连续反馈

道具栏父组件订阅稳定的绑定投影；装填遮罩和剩余秒数单独读取最新战斗状态，更新原来的两个 DOM 元素。原装填与效果到期公式共用，物品、库存、弹药选择和操作许可变化仍由 React 更新。手机和电脑共用。

第五局 45 秒平均 30.62 FPS、P95 50.1 ms、主线程忙碌 54.64%。单独的 CPU 采样中，React 路径占窗口约 2.01%，第四局约 8.85%；不同战况下的采样不能等同于严格 A/B。帧率仍未达到目标。

## 木牌图片首次解码

第三十三局独立 CPU Profile 的 `BattleWoodPanel → imageResourceUrl → toDataURL` 路径有 49 个采样点，约占 8 秒窗口的 1.05%，对应约 80 ms。后续 15 秒诊断没有记录新的 PNG 编码，当前证据表明是首次生成完整图片的停顿，不能认定为持续编码循环。

电脑战斗 UI 在 atlas 和原控件准备完成后，提前调用现有的 `decodeImage`，准备观战、比分和计时三个木牌图片，再报告界面就绪。组件读取同一组路径，裁剪缓存、PNG 编码、图片元素及样式沿用原实现。该修改把首次编码和解码移到加载阶段，不作为持续 FPS 提升；手机 UI 不额外准备电脑木牌。

第三十四局进入战斗后再次读取三个木牌，0.3 ms 完成，PNG 编码次数为零。30 秒独立窗口提交 1343 帧、约 44.74 FPS，每帧平均绘制 385 次，低于第三十三局的 467 次；未记录长任务或错误，不能据此把跨局差值归因于预解码。

## 后台资源加载

Chrome 后台页面的 `HTMLImageElement.decode()` 会等待页面回到前台。加载器的 30 秒限制只累计前台可见时间，隐藏时暂停，恢复时继续使用剩余时长；完成、失败和超时均移除计时器及可见性监听。图片、字体、音频与纹理共用此规则。

同一图集的 IndexedDB Blob 与 HTTP 200 响应逐字节相同，均为 2,650,024 字节，前台 HTMLImageElement 与 ImageBitmap 均能解码成 2048×2044。后台停留 35 秒的实际页面对照中，墙钟计时显示“图片解码失败”，只累计前台时间的实现保持加载，切回前台后正常完成。该修复解决加载故障，不计作战斗帧率收益。证据为第二十七局的 `atlas-background-timeout-before.json`、`atlas-background-timeout-after.json` 和 `atlas-background-timeout-restored.json`。

## 矩阵比较与界面合成

原生矩阵严格比较在第二十九局结算场景将每帧 uniform 写入由 5 次降为 1 次，但相同 403 次绘制下帧率分别约为 53.60、51.28 FPS，渲染 CPU 均值为 7.60、7.99 ms，同输入截图像素一致。第三十局交替实战窗口绘制量和战况不同，未证明收益；当前使用原生默认配置。

第三十局独立采样后的界面合成隔离保持画布尺寸和渲染设置，暂时固定场景并切换 DOM 界面的可见性。排除首个窗口后，显示与隐藏约为 47.54、49.35 FPS；此结果只用于定位界面合成成本，隐藏界面的数值不作为目标帧率。诊断结束后恢复原渲染循环、界面与显示设置。

## 方向光投影计算

第三十局结算场景的方向光矩阵末行为 `[0, 0, 0, 1]`。保留逐像素投影、仅省掉恒为一的除法后，同输入截图逐像素一致；相同 624 次绘制下约为 49.18、49.54 FPS，不足以认定收益。临时将正交投影移到顶点、片元只计算法线偏移投影时约为 48.49、50.22 FPS；466 个像素存在至多 2 级通道差异，原路径重复截图无差异。第三十一局实战交替窗口约为 39.76、39.94 FPS，每帧平均绘制约 537、541 次，未证明稳定收益；该候选未写入源码。

地形专用实现将平面入射角、法线偏移及方向光正交投影一起移到顶点阶段。片元仍在分支和 alpha discard 前计算投影导数，原 PCF 采样、光照、透明测试、纹理与绘制顺序保持一致。93 个现有地图 GLB 的 656,340 个三角形均未发现零法线或与几何面不平行的法线；此实现覆盖手机和电脑，战车与 CVD 继续使用原片元计算。

第三十一局结算后相同 559 次绘制的交替窗口约为 50.40、53.00 FPS；世界颜色通道 GPU 均值由 7.41 降为 6.33 ms，中位数由 6.68 降为 5.70 ms，其它通道中位数保持一致。三处视角同输入截图分别有 2079、1604、413 个像素差异，最大通道差为 5、8、4，原路径重复截图逐像素一致。图像未见阴影或模型形状异常；数值计算顺序变化产生少量像素差异。该实现已写入源码并完成集中走查。第三十二局新页面实际载入顶点投影源码，30 秒提交 1270 帧、约 42.31 FPS，每帧平均绘制 613 次；第三十一局为 788 次，跨局帧率差值不作为收益对比。采样窗口未捕获错误或设备丢失，60 FPS 目标尚未达到。

第三十二局独立采样后进一步临时将地形的非阴影光照颜色移到顶点。固定场景世界颜色通道 GPU 均值约为 6.36、6.10 ms，中位数 5.77、5.51 ms；帧率约为 52.85、53.63 FPS，绘制数略有变化。第一张原路径图跨过异步资源变化，不能作为画面等价比较；候选与最后一张原路径图逐像素一致。结算后的相同 625 次绘制下，原路径约 55.27 FPS、候选约 54.80 FPS，世界颜色通道 GPU 中位数均约 5.18 ms；三处视角候选与原路径及重复截图均逐像素一致。当前证据未显示稳定收益，源码保持原值；临时材质及 GPU 计时已恢复。

## 地形阴影坡度

平面地形的投影深度梯度在三角形内恒定。顶点阶段用光投影矩阵的余因子矩阵变换平面法线，计算 `dz/du` 与 `dz/dv`，片元读取插值后的坡度；原 PCF、坡度偏移、背光判断和照明公式保持一致。背光面不采样阴影，坡度设为零。手机关闭场景阴影时不执行此路径，电脑使用同一地形材质。

第三十二局结算后相同 625 次绘制下，两个固定场景对照的世界颜色通道 GPU 均值分别由 5.71 降为 5.50 ms、由 5.67 降为 5.53 ms，中位数分别由 5.24 降为 5.05 ms、由 5.21 降为 5.05 ms。其它通道中位数保持一致。最终背光判断版本的交替窗口约为 54.56、54.85 FPS，局部 GPU 收益不能当作实战达到 60 FPS。

最终版本三视角的同输入截图分别有 25、226、6 个像素差异，最大通道差为 2、3、1，原路径重复截图逐像素一致。地形、战车和阴影形状未见异常；计算顺序变化产生少量数值差异。源码在该局结算后更新，第三十三局新页面实际加载顶点坡度源码，221 个地形材质均使用新路径；30 秒提交 1323 帧、约 44.06 FPS，平均绘制 467 次，低于第三十二局的 613 次。跨局差值不作为严格收益比较，已监测至自然结算，战斗记录未捕获异常、冻结或设备丢失。该批源码已完成集中走查。

第三十七局 30 秒独立基线实际提交 1299 帧，平均每帧绘制约 418 次。312 条监测记录保持同一页面时间原点，297 条战斗记录未发现异常、冻结或设备丢失，至 tick 6036 自然结算。服务器记录 5978 步，平均 13.95 ms、最大 95.73 ms，7 步超过 50 ms，无采样缺口或丢弃。基线后包含临时静态物件候选与屏幕深度审计；固定输入对照及源码集成在结算后完成，源码已通过本批集中走查。60 FPS 目标尚未达到。

## 协作顺序

战绩钩子将 CPU 优化进度保存在 `state/cpu-optimization/status.json`；当前完成 3 次，第 4 次仍 pending，不能据此认定已经分析、应用并重启。当前协作规则禁止联系其它 session，浏览器侧继续使用可用服务，并在每局目录单独归档和分析 CPU 轨迹。

训练模块共用 AI 源码，开发服会将 AI 修改传播为浏览器热更新。采样记录页面导航和引擎帧号，热更新打断的窗口单独标记。
