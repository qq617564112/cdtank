# 手机战斗界面

手机和平板使用 `platform/device.ts` 的设备识别切换为 `MobileBattleHud`，电脑继续使用原战斗 HUD。页面按完整视口缩放和贴边定位，雷达根据手机 HUD 的实际位置绘制原有实时小地图。

## 操作与数据

- 左摇杆默认隐藏，在左半屏空白战斗区域按下时以触点为中心出现，松手后隐藏。所有方向按相机方向连续控制。首次离开中心20%死区时，选择更接近推动方向的车头或车尾：车头夹角不超过90°时前进，超过90°时倒车。拖动期间持续比较目标方向与当前行驶朝向，前进以车头朝向为准，倒车以车尾朝向为准；夹角超过130°时重新选择另一端，不超过130°时保持当前前进或倒车选择。回到中心只停车，松手或取消后清除选择。选定一端与目标相差超过120°时先原地转向，夹角不超过120°时边调整边行驶，对齐后沿推动方向继续行驶。行程决定行驶速度。
- 右摇杆没有转向输入时，手机相机及可转炮塔保持世界朝向，通过相对角度补偿车身转动。有右摇杆转向输入时，相机和炮塔的世界转角为本帧车身实际转角与右摇杆转角之和，同向相加、反向抵消；车身实际转角取导航及碰撞接受后的姿态。持续推住左摇杆时，目标方向随当前相机方向更新。电脑键盘保留车身带动炮塔的联动规则。固定炮塔车型保持沿车身瞄准。
- 右摇杆默认隐藏，在右半屏空白战斗区域按下时以触点为中心出现，松手后隐藏。左右推动调整炮塔和相机的世界朝向，以按下位置为起点，水平距离按 HUD 缩放换算：中心至最大水平行程的5%为死区，当前为2.16个逻辑像素；剩余95%行程归一化后使用二次曲线无级调速，归一化有效行程的平方为转速比例。有效行程25%、50%、75%分别对应当前炮塔转速的6.25%、25%、56.25%。达到摇杆帽的最大行程43.2个逻辑像素时才为当前炮塔转速的100%，继续向外推动保持满速。向左推为左转，向右推为右转；回中或松手立即停止炮塔输入，纵向移动不转炮塔。摇杆帽限制在自身行程内。开火按钮和道具槽各自捕获触摸，两根摇杆和开火可同时操作。
- 触控与键盘共用 `BattleInput`、本地运动预测和 `PlayerInput` 协议。摇杆在页面捕获阶段处理所属指针的松手与取消，全部手指离屏时清除各自输入及按住状态，并收起摇杆。失去捕获的旧指针会在下一次屏幕触摸时释放，新触摸可重新接管摇杆；其他仍在操作中的指针保持独立。失去焦点、进入后台、旋转或调整窗口、死亡及回合切换会清除对应输入。聊天、计分板和对话框打开时禁用触控。
- 手机相机使用独立水平朝向，并跟随实际渲染炮塔转轴的位置；仅操作车身时保持相机朝向，同时操作右摇杆时合成两者转角。电脑相机沿实际炮塔完整世界变换跟随，包含坡面姿态。移动、开火和受击动作各自的炮塔节点沿用当前相对角度。
- 左上生命条用 CSS 绘制，宠物头像、生命值和下方弹匣读取现有 HUD 状态。比分、倒计时、装填准星和复活倒计时沿用服务器投影。
- 顶部木牌按我方比分、倒计时、敌方比分排成一行，蓝红坦克图标区分两队，倒计时低于警戒值时沿用红色提示。城堡伤害和王生命等较长数值按字符数调整字号。混战与破坏模式使用两列布局：左侧倒计时，右侧分别合并显示“本机击毁 × 数量”和“完好目标 × 数量”。
- 手机小地图使用蓝色箭头表示本机及队友，红色箭头表示敌人；混战中其他玩家均为红色。箭头按车身朝向与相机方向旋转，本机保持地图中心。死亡、光学隐身、伪装、雷达干扰、探测及 VIP 标记沿用已有规则。
- 底部居中单排道具栏按1–8顺序显示全部槽位，沿用 `hudItemSlots` 和 `Battle.useHudSlot` 的库存、冷却及使用逻辑。
- 左右摇杆仅在按住时显示。开火按钮和单排道具栏默认50%不透明度，按住对应控件时为100%，松手后恢复。道具选中状态只影响槽位的金色底色及边框。槽位各自捕获触摸，手指在槽位内松开时使用，移动中也能点道具；滑出后松开或取消触摸不使用。
- 圆形计分板按钮打开原 Tab 计分板。返回及退出操作保留至少 44 CSS 像素高度；退出沿用服务器处罚报价及确认。
- 道具栏上方显示一条居中的无框信息，逐条淡入淡出，每条3秒。连杀、获分、击毁及聊天进入同一队列；房间聊天仅提示一次。密语、好友、家族及 GM 信息同时保留在聊天历史中。

## 视觉布局

界面参照 `output/imagegen/mobile-battle-ui/mobile-battle-round-icons-flat-top.png` 的比例。头像为 76×76、生命条为 164×32、雷达为 144×144；单行比分与计时木牌为 336×60，中间计时占 104，比分字号为 30，计时字号为 26，生命与弹匣数字为 18。尺寸为缩放前的 CSS 像素。HUD 覆盖完整视口，头像左上边距为 16、12，雷达右上边距为 14、10，控件保留自身边距。

横屏以 960×440、竖屏以 440×780 为缩放基准，取视口宽高与基准尺寸比值中的较小值，允许大视口放大。CSS 尺寸使用逻辑像素；浏览器按设备像素密度栅格化界面，雷达将 DOM 坐标按实际 canvas 边界和渲染缓冲尺寸换算，避免重复乘以 DPR。

头像内容区与相框内圈对齐，四周留出相框直径的 8%。`MobileBattlePortrait` 为每只宠物固定同一套源像素缩放比例，五种表情共用正常头像的方形视口尺寸；各表情的定位偏移独立，攻击、受伤等装饰超出开口时由头像框裁切。覆盖 10 个宠物的全部五种表情及死亡图，头像继续使用现有发布图集。

圆形开火按钮位于右下角，直径为缩放前115.2 CSS像素，默认半透明，按下完全显示。单排道具栏宽度最多442、高64，按可用宽度缩小，位于屏幕底部中间；槽位使用绿色边框、金色选中底色，空槽保留深绿透明底色。信息位于道具栏上方。左右浮动摇杆直径为144，以实际触点为中心，贴近屏幕边缘时由HUD边界裁切。

竖屏比分移到雷达下方，复活提示位于计时牌下方，道具保持单排，开火按钮上移以避开道具及信息。生命条和道具栏边框由CSS绘制，摇杆、开火等沿用现有发布素材。

### 限制

全方向车头或车尾选择、拖动期间超过130°重新选择、超过120°原地转向门槛、车身与手动炮塔转角合成，以及右摇杆无级调速尚未浏览器实测。

连续摇杆记录使用生成的导航平地和 Chromium WebGL，覆盖真实组件、模型、相机及姿态计算，未连接完整服务器对局，未覆盖坡面炮管投影或原生手机 WebGPU。

容器的软件 WebGPU 无法完成游戏渲染，本次浏览器验收通过临时网络拦截使用 WebGL，战斗贴图临时映射 HD。这些替换仅存在于验收浏览器中，运行代码使用 WebGPU；当前移动端战斗可选怀旧／HD，HD 使用怀旧尺寸的独立成品。本次结果不覆盖原生手机 WebGPU 或性能。

地图 7 的上述验收加载报告“原地形材质缺少模型或纹理：ground01/0”，完整对局尚未完成原生手机验收。

验收账户没有消耗道具库存，未实测槽位 5–8 的消耗和冷却；这些槽位复用现有道具使用路径。
